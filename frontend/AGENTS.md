# frontend/ — Next.js 작업 화면과 Mol* 뷰어

## 담당 범위
- 최상위 탭 `src/components/WorkspaceTabs.tsx`(정의는 `src/lib/workspace-tabs.ts`): `구조 분석` / `단백질 공학` / `리간드 설계·탐색` / `지식·보고서`와 전역 줄(현재 run `.mw-app-run`, M24 과학 전송 동의 표시 `.mw-app-science`, 예산 `.mw-app-budget`). `app/page.tsx`가 이 탭 안에 기존 화면을 넣는다.
- `src/components/ReportLibraryPanel.tsx`: 지식·보고서 탭의 run 전체 보고서·그림·완료된 흐름 요약 목록. 순수 판단은 `src/lib/report-library.ts`.
- `src/components/NumberingPanel.tsx`: M15 지식·보고서 탭의 잔기 번호 대응 화면(보고서 목록 위). 순수 판단은 `src/lib/numbering.ts`. 페이지가 run마다 `key`로 새로 만들고, 보고서를 만들면 `onReportCreated` → `ReportLibraryPanel`의 `reloadToken`으로 보고서 목록을 다시 읽게 한다.
- `src/components/ReactionKnowledgePanel.tsx`: M26 지식·보고서 탭의 "효소 반응 지식" 영역(번호 대응 화면 아래·JEV 판정 영역 위, `WorkspaceTabs`의 `reaction` 자리 `.mw-app-reaction`, `data-testid`는 모두 `reaction-` 접두사, 패널 `data-reaction-state`, 영역 `[data-reaction-area=snapshot|request|results|detail|report]`. 반응 참조 스냅샷 블록, 연결 요청(구조·PDB ID 확인·체인 행과 accession·M-CSA 제안 "이 accession 쓰기"·같은 구조 번호 대응), 저장된 결과 목록, 결과 상세(체인별 M-CSA 행 표·UniProt 부위 표·반응 절, 쪽 나눔), 보고서 만들기·내려받기). 순수 판단과 화면 문구는 모두 `src/lib/reaction-knowledge.ts`. 페이지가 run마다 `key`로 새로 만들고 capability는 `methods.reaction_knowledge`, 보고서를 만들면 `onReportCreated`로 보고서 목록 `reloadToken`을 올린다.
- `src/components/JevPanel.tsx`: M24 지식·보고서 탭의 "JEV 판정(외부 모델)" 영역(번호 대응 화면 아래·보고서 목록 위, `WorkspaceTabs`의 `jev` 자리 `.mw-app-jev`, `data-testid`는 모두 `jev-` 접두사, 영역은 `[data-jev-area]`, 패널 `data-jev-state`. 상태·동의, 후보 집합 종류·집합, 후보 고르기(리간드는 `LigandPanel`이 export한 `FilterForm`, 변이는 후보 표), 보낼 내용 만들기·미리보기, 승인·전송, 결과 카드, 전송 기록, 보고서 만들기). 순수 판단과 화면 문구는 모두 `src/lib/jev.ts`. 페이지가 run마다 `key`로 새로 만들고 capability는 `methods.jev_choice`, 보고서를 만들면 `onReportCreated`로 보고서 목록 `reloadToken`을, 읽거나 바꾼 동의 상태는 `onStatus`로 페이지의 전역 표시에 넘긴다. M25부터 페이지가 `sendHistoryMark`(`lib/jev-loop.ts` `loopSendHistoryMark`)를 넘겨 전송 기록의 루프 전송을 "JEV 루프" 표시와 루프 영역 안내가 붙은 읽기 전용 행(열기·보고서 단추 없음, `data-jev-loop`)으로 보인다. M24 전송 행은 그대로다.
- `src/components/JevLoopPanel.tsx`: M25 "JEV 루프" 영역. 리간드 설계·탐색 탭의 `LigandGaPanel`(M22) 다음(`branch="ligand"`)과 단백질 공학 탭의 `SequenceGaPanel`(M23) 다음(`branch="protein"`)에 같은 구성 요소를 마운트한다(`data-testid="jev-loop-panel"`·`data-branch`, 그 밖의 `data-testid`는 모두 `jev-loop-` 접두사, 영역은 `[data-jev-loop-area]`). 동의 상태(같은 `POST /jev/consent`)·UL1·UL3(+ 단백질 U3), 루프 목록, 만들기(후보 집합·풀 체크박스 ≤ 20·목표·루프 seed·반복 상한·계산 조건: 리간드는 M17 `FilterForm`과 M18 입력, 단백질은 M21 `PairInputs`·두 리터럴·cutoff), 진행(보낼 내용 만들기·미리보기·확인 체크·전송, JEV 판정 카드, 이 선택으로 계산 시작·직접 지정, 첫 계산 승인·작업 시작·취소, 도킹 시작·포기), 후보 표·바퀴 표, M18 결과 상세, 끝내기·요약·보고서. 순수 판단과 화면 문구는 모두 `src/lib/jev-loop.ts`(M24 `lib/jev.ts`·M18 `lib/docking.ts`·M21 `lib/mutation-model.ts` 함수를 가져다 씀). 페이지가 갈래·run마다 `key`로 새로 만들고 capability는 `methods.jev_loop`(영역이 자기 갈래 항목을 읽음), 보고서를 만들면 `onReportCreated`로 보고서 목록 `reloadToken`을, 동의 상태는 `onStatus`로 전역 표시에 넘긴다.

## 담당하지 않는 것
- 과학 계산, 단위 변환, 요약 수치 재계산: 백엔드 handle을 표시만 한다.
- 외부 네트워크: 모든 요청은 `/api/*`(→ `127.0.0.1:8000`)로만 간다. 원격 글꼴·CDN·예시 구조를 쓰지 않는다. 글꼴은 `@fontsource` 로컬 패키지다.
- 자격 증명: 브라우저에는 API 키 입력란, 설정, localStorage 저장이 없다.
- `app/gallery/`는 디자인 fixture 전시용이다. 메인 화면(`app/page.tsx`)이 gallery의 가짜 수치를 import하면 안 된다.
- 건드리지 말 것: `.next/`, `node_modules/`, `tsconfig.tsbuildinfo`(생성물), `tests/offscreen/artifacts/`의 과거 실패 증거.
- 스타일 원본은 `design/components.css`다. `src/design/components.css`를 직접 고치면 다음 `npm run tokens` 실행 때 사라진다. 원본을 고친 뒤 `npm --prefix frontend run tokens`로 복사한다.

## 불변 조건
- 구조 분석 탭(메인 화면과 화학 작업 화면)은 다른 탭이 보일 때도 언마운트하지 않는다. `visibility:hidden`·`pointer-events:none`·`inert`로 숨기고 `display:none`이나 조건부 렌더링·key 변경을 쓰지 않는다(Mol* 캔버스 크기와 뷰어·선택·진행 중 폴링을 유지하기 위해). 탭 전환은 뷰어 브리지의 사용자 동작 콜백이나 복원 취소를 부르지 않는다. 다른 탭 패널은 선택된 동안에만 렌더링한다(기존 검사의 텍스트 locator와 겹치지 않게).
- 최상위 탭 이름은 레일 탭 이름(`run`, `models`)으로 시작하지 않는다. 전역 예산 요소에 `.mw-top-budget`을 쓰지 않는다(기존 검사가 이 클래스로 값을 읽는다). 전역 예산은 새 주기적 폴링 없이 탭 전환과 화학 화면 `onObjectsChanged` 때 `/budget`을 한 번 읽는다.
- run 선택·전환은 구조 분석 탭(메인 레일, 화학 화면)에만 있다. M20부터 기능 없는 탭은 없다(`UNAVAILABLE_NOTICES`는 빈 표이며 타입과 "사용할 수 없음" 문구는 나중 탭을 위해 남김). 기능 없는 탭이 다시 생기면 사용할 수 없음·이유·여는 단계만 보여 주고 숫자·컨트롤·요청이 없어야 한다. 지식·보고서 탭은 M15부터 안내 대신 번호 대응 화면과 보고서 목록을, M24부터 그 사이에 JEV 판정 영역을, M26부터 번호 대응 화면과 JEV 판정 영역 사이에 효소 반응 지식 영역을, 리간드 설계·탐색 탭은 M17부터 리간드 후보 화면을, M18부터 그 아래 도킹 영역을, M19부터 그 아래 일괄 도킹 영역을, M22부터 그 아래 GA 설계 영역을, M25부터 그 아래 JEV 루프 영역을, 단백질 공학 탭은 M20부터 변이 후보 화면을, M21부터 그 아래 변이 구조 모델링 영역을, M23부터 그 아래 서열 GA 설계 영역을, M25부터 그 아래 JEV 루프 영역을 보여 준다(선택된 동안에만 렌더링, 들어갈 때 GET 읽기만).
- 보고서 목록은 저장된 바이트만 보여 준다(Markdown은 `<pre>` 원문, 렌더링하지 않음). 흐름은 `complete`이고 `summary_handle`이 있으며 `error`가 없는 실행만 넣는다. 목록 세 개는 오류가 서로 독립이고, run·요청 순번이 맞지 않는 응답은 버린다. 다운로드는 사용자가 누른 링크로만 일어난다. 보고서 목록(`ReportLibraryPanel`)에는 구조 분석으로 건너가 여는 버튼과 보고서 생성 버튼을 두지 않는다(번호 대응 보고서는 번호 대응 화면의 "보고서 만들기"로 만들고, 목록은 `reloadToken`으로 다시 읽는다).
- 번호 대응 화면: PDB ID는 `pdb_id_hint` 제안을 보여 주기만 하고, 사용자가 확인 체크(또는 수정)해야 보낸다(확인하지 않으면 `pdb_id: null`). 구조·체인·accession을 자동으로 확정하지 않는다. SIFTS accession이 하나인 체인만 미리 채우고(수정 가능), 여러 개(융합)인 체인은 accession을 보내지 않는다. UniProt은 스냅샷 검색 결과에서만 고른다. 행 표는 7필드를 그대로, 상태 필터와 전체 개수를 함께 보여 준다(대응됨이 아닌 행을 숨긴 채 전체처럼 보이게 하지 않음). 충돌은 양쪽 답, 대응 없음은 이유, 교차 확인 없음·잔기 불일치·`gapped_unique`를 표시한다. 이유 코드는 "한국어 (code)"로 코드를 함께 보여 주고(`reasonText`, 모르는 코드는 그대로), 한국어 이름을 추가·변경하면 `tests/numbering.test.cjs`와 `backend/tests/test_residue_numbering.py`의 `REASON_CODES`를 같이 고친다. 스냅샷 표시는 `snapshotBadge`로 정한다: 사용 중 세트가 있고 대응의 세트와 다를 때만 "이전 스냅샷 기준"(`data-stale`), 사용 중 세트가 없으면 "사용 중 스냅샷 없음"(`data-no-active-set`). 백엔드는 세트가 없을 때도 `stale_snapshot: true`를 주므로 이 값만으로 "이전 스냅샷 기준"을 그리지 않는다. 스냅샷 영역에는 숫자 없는 범위 문장(`SNAPSHOT_SCOPE`, 보고서 `limitations`와 같은 문장, `backend/mw/numbering_reports.py`와 함께 고친다)을 항상 보여 준다. 위치·KLIFS 번호는 참조 값으로 표시하고, 일치율·정렬 범위는 백엔드 값을 소수 한 자리 `ROUND_HALF_UP`(10진 문자열 기준)으로만 표시한다. 스냅샷을 사용할 수 없으면 숫자 없이 이유와 가져오기 명령(`IMPORT_COMMAND`, `docs/operations.md`와 같은 줄) 안내만. 체인 목록은 `structure_residues`의 `category` polymer 기준이라 도구의 사슬 잔기 규칙과 다를 수 있다(서버가 판단, `docs/tracking/findings.md`). run이 바뀌면 늦은 응답은 버린다. 지식 탭 번호 대응 화면에는 Mol* 강조가 없다(M16 참조 주석은 구조 분석 탭 패널에만 있다).
- 지식·보고서 탭 JEV 판정 영역(M24): run이 없으면 이유만(`jev-no-run`), capability(`methods.jev_choice`)를 쓸 수 없으면 숫자·컨트롤 없이 이유만(`jev-unavailable`). 마운트는 읽기만(상태·집합 목록·전송 기록)이고 외부로 보내는 요청은 사람이 승인 단추를 누를 때의 `api.jevSend` 하나뿐이다. 동의 스위치는 서버 상태 그대로이고 dry-run run에서는 켤 수 없다(`consentSwitchDisabledReason`, 끄기는 항상). 고정 안내(`CONSENT_NOTICE`, 스위치 옆 U2·U3, 기록 옆 U1)와 J1–J7은 `lib/jev.ts` 상수이며 `backend/mw/jev_constants.py`와 같아야 한다(`tests/jev.test.cjs`가 파이썬 상수 파일을 읽어 대조). 후보 집합·후보는 자동으로 고르지 않는다. 체크는 한 집합 안에서만, 리간드는 적용한 필터를 통과한 후보만, 20개를 넘는 체크는 막고 이유를 보이며(`toggleJevCandidate`), 보내는 순서는 클릭 순서가 아니라 저장 순서다. 미리보기 본문은 서버 문자열 그대로(파싱·재직렬화 없음) 접은 `pre`에, 별칭 ↔ 로컬 후보 표는 "전송하지 않음"으로 보인다. 승인 단추는 서버 차단 이유가 없고, 확인 체크가 지금 미리보기의 본문 해시에 묶여 있고(`jevConfirmed`), 전송 중이 아닐 때만 열린다. `send_id`는 처음 누를 때 만들고 기록이 오거나 `send_id_conflict`가 날 때까지 같은 값을 다시 쓴다(`jevSendAttempt`·`jevAttemptAfter`). 미리보기 뒤 상태 읽기가 진행 중 전송이 끝났다고 하면 `send_in_progress` 차단은 "다시 읽기 필요"로 보이고 미리보기를 저절로 다시 읽지 않는다. 결과 카드의 확신도·확률은 `decimalHalfUp` 소수 셋째 자리 표시만 하고 확률은 접힌 상세에 보낸 순서로, 실패·거절은 이유 "한국어 (code)"만 보인다(목록 밖 코드는 되풀이하지 않고 고정 문구). 정렬·막대·색 비교·"최고"·"추천"·응답끼리 비교·합치기가 없고, 금지어는 `jevForbiddenWords`(`JEV_FORBIDDEN`, 고정 문장 줄 예외, 수락 실행기·하네스와 같은 규칙). JEV 선택을 다른 탭 요청 칸으로 넘기는 동작은 없다. 늦은 응답은 run + 투영·전송 handle + 영역별 요청 번호(`jevResponseCurrent`, `JEV_AREAS`)가 모두 같을 때만 반영한다. 진행 중 전송이 기록에 있으면 2초마다(`JEV_POLL_MS`) 기록·상태를 다시 읽는다(읽기만). 전역 "과학 전송 허용" 표시는 `.mw-app-run` 밖 `.mw-app-science`이고(그 요소 글자는 run id와 같아야 함) 현재 run의 동의가 켜졌을 때만 보이며(`globalScienceBadge`), 페이지는 run이 바뀔 때 상태를 한 번 읽고 그 뒤로는 영역의 `onStatus`를 받아 요청 순서(`scienceMarkGate`)로 늦은 답을 버린다(새 폴링 없음).
- 리간드·단백질 공학 탭 JEV 루프 영역(M25): run이 없으면 이유만, capability(`methods.jev_loop`의 그 갈래)를 쓸 수 없으면 숫자·컨트롤 없이 이유만. 마운트는 읽기만(동의 상태·루프 목록·집합 목록)이고 쓰기는 사람이 누르는 것뿐이다: 루프 만들기, 보낼 내용 만들기(`POST /commands` `build_jev_loop_projection`), 확인한 본문의 전송(`api.jevSend` 하나), 계산 시작(`/compute`), 첫 비싼 계산 승인·작업 취소(기존 작업 라우트), 도킹 포기, 끝내기, 보고서, 동의 스위치(지식 탭과 같은 run 수준 `POST /jev/consent`, 루프별 동의 없음, dry-run이면 켤 수 없음). 자동 선택·자동 전송·자동 계산 시작·자동 다음 바퀴가 없다. 후보 집합·후보·목표·seed는 자동으로 고르지 않는다(seed 비어 있음, 반복 상한 기본 5). 풀 체크는 2–20개이고 21번째는 막고 이유를 보이며(M24 `toggleJevCandidate` 재사용) 리간드는 적용한 필터를 통과한 후보만이다. 자유 도킹 고정과 그 사실(`FREE_DOCKING_NOTE`), 단백질은 확인 두 리터럴·cutoff를 보인다. 만들기 입장 거절은 칸별로(`loopCreateRefusal`, `setup_invalid`는 계산 조건 칸에 `setup_reason`과 함께) 보인다. 미리보기 본문은 서버 문자열 그대로 접은 `pre`에, 바이트·SHA-256·질문 고정 문구·별칭 ↔ 로컬 후보 대응표("전송하지 않음")·섞기 순서·seed·예약값·차단 이유(`blocked_by` + `loop_blocks`)를 보이고, 전송 단추는 차단 이유가 없고 확인 체크가 지금 본문 해시에 묶여 있고 전송 중이 아닐 때만 열린다(`send_id`는 처음 누를 때 만들고 기록이 올 때까지 같은 값). "JEV 판정(모델 선택)" 카드는 루프 기록이 그 전송의 완료를 보일 때까지 확인 중 줄만 보이고(`loopChoiceView`의 `confirming`), 고른 별칭의 로컬 표기·목록 위치 "n/m"·확신도·응답 모델·사용량·늦으면 J7을, 접힌 상세에 확률 값만 보낸 순서대로 보인다. 계산 시작 단추는 단위·시간 확인 체크 뒤에만 열리고, 승인 대기 작업을 취소하면 그 후보가 이 run에서 다시 계산할 수 없게 된다는 안내(`CANCEL_BEFORE_START_NOTE`)를 보인다. 진행 중에는 2초마다(`LOOP_POLL_MS`) 기록을 다시 읽기만 하고, 한 번에 한 읽기만 돌리며(`loopReadRequest`·`loopReadSettled`, 연 루프만) 늦은 응답은 run + 연 루프 + 바퀴 + 영역별 요청 번호(`loopResponseCurrent`, `LOOP_AREAS`)가 모두 같을 때만 반영한다. 한 번에 한 루프만 열며 진행 중 요청이 있으면 다른 루프 열기를 이유와 함께 막는다. 후보 표의 점수는 서버 값(`decimalHalfUp` 소수 첫째 자리), 점수 없음은 "—"와 이유이며 풀 순서·후보·점수·바퀴 열 정렬(`sortLoopCandidates`)에서 점수 없는 행은 어떤 방향에서도 끝(풀 순서)이고 `aria-sort`를 둔다. 순위 열·최고 표시·강조·차이 열·막대·색 비교·그래프가 없다. 화면은 점수·집계·부족분·섞기·계산 여부를 계산하지 않는다. 고정 문장 LJ1–LJ8은 서버가 준 저장 문장 그대로, UL1–UL3·U3는 `lib/jev-loop.ts` 상수이며 `backend/mw/jev_loop_constants.py`와 같아야 한다(테스트가 파이썬 상수 파일을 읽어 대조). 금지어는 `jevLoopForbiddenWords`(고정 문장 줄 예외, 수락 실행기·하네스와 같은 규칙). 다섯 상태(`loopPanelState`)를 구분한다. M21 짝 표는 서버 `loop` 키가 있는 짝만 "루프 도킹(야생형 없음) · 바퀴 n"(`pairLoopText`)으로 보이고 다른 짝 행은 그대로다. 다른 탭 내용은 바뀌지 않으며 이 영역의 `data-testid`는 `jev-loop-` 접두사라 M24 하네스의 `jev-` 선택자가 이 영역을 빼고 센다.
- 화면의 과학 수치는 모두 백엔드 객체에서 온다. 미리보기 5행을 전체 결과처럼 표시하지 않는다.
- Mol* 조작은 모두 MolstarViewer 브리지의 직렬 큐를 거친다. 매 await 전후에 session, client, generation, source handle, catalog hash, action revision을 확인한다. 하나라도 바뀌었으면 그 작업은 적용하지 않는다.
- "적용됨"은 native 작업을 커밋하고 다시 읽어 확인한 뒤에만 보고한다. React state만 바꾸고 성공으로 표시하지 않는다. 부분 적용은 적용된 명령과 거부된 명령을 나눠 보여 주고, 롤백했다고 주장하지 않는다.
- 브라우저 선택 → 잔기·원자 식별자 변환은 제공된 바이트의 SHA-256에 묶인 `atomSourceIndex` 일대일 대응만 쓴다. Mol*가 합성한 label, PDB serial, 좌표 최근접을 쓰지 않는다. 대응이 준비되기 전에는 선택·초점·저장 컨트롤이 기다리거나, 재시도 가능한 오류를 보여 준다.
- 바인딩 6필드가 모두 같은 재발행은 새 사용자 동작이 아니다. 카탈로그 준비나 검증 같은 관찰은 `onSelect`를 호출하거나 복원을 취소하면 안 된다. 실제 클릭, 빈 곳 클릭, 회전은 대기 작업을 취소한다.

- 단백질 공학 탭 변이 구조 모델링(M21): 영역은 `MutationPanel` 밖 형제 요소로 둔다(M20 패널 안 문구·요청 검사 범위와 `data-testid="mutation-panel"` 선택자를 바꾸지 않기 위해). `data-testid`는 모두 `mutation-model-` 접두사. run이 없으면 이유만, capability(`methods.mutation_model`)가 없거나 사용할 수 없으면 숫자·컨트롤 없이 이유만, 같은 조건 도킹은 `methods.ligand_docking`을 쓸 수 없으면 그 영역만 이유와 함께 막힌다. 후보·모델·리간드·결과를 자동으로 고르거나 열지 않고, 후보 전달은 요청 칸만 채운다(seed 비움, 확인 체크 안 됨, cutoff 4.0·시간 120 기본). 요청은 `modelRequest`가 서버와 같은 모양(인자 여섯 + 최상위 `timeout_s`)으로 만들고 막히는 이유를 모두 보인다. 비싼 계산 1단위 안내와 명시적 "비싼 계산 승인"(첫 계산)은 M7 방식이다. 모든 숫자는 서버 저장값이며 화면은 전위·SASA·접촉·점수를 계산하지 않는다. 전위·SASA·거리는 `decimalHalfUp` 소수 둘째 자리, null은 "—"와 이유(`nullText`). 두 구조의 차이·증감·개선 표시, 화살표, 구조 간 막대·색 비교, 순위 열이 없고 두 구조 칸은 같은 스타일이다. 금지어는 `modelForbiddenWords`(고정 한계 문장 `MODEL_LIMITATIONS` 줄은 예외, 그 밖의 줄은 M18 점수 이름만 지운 뒤 검사). 한계 문장은 저장된 `limitations` 그대로. 접촉 0개는 "0개, 계산한 결과"이지 null이 아니다. 다섯 상태(`modelAreaState`·`pairAreaState`)를 구분한다. 늦은 응답은 run + 모델 handle + 영역별 요청 번호(`modelResponseCurrent`, 영역 `list`·`detail`·`contacts`·`pairs`·`report`·`model_job`·`pair_jobs`)가 모두 같을 때만 반영하고, 보고서 생성이 늦게 끝나도 run이 같으면 목록을 다시 읽는다(`modelReportSavedForRun`). 같은 조건 도킹은 SDF 리간드만(후보 출처는 `PAIR_SDF_ONLY_REASON`과 함께 막힘), 자유 도킹만, 인스턴스 범위 상자 막힘, 2단위 확인 체크 뒤 한 번의 동작으로 `pairDockingRequests`가 만든 두 요청(`receptor_source.side`만 다름)을 야생형 기준 → 변이형 순서로 제출하고 하나씩 시작한다. 한쪽 거절·실패가 다른 쪽을 숨기지 않는다. 시간 상한은 M18 `DOCKING_TIMEOUT_S` 600. 짝 동작이 진행 중(`pairBusy`)이면 다른 모델을 열 수 없고 이유(`MODEL_SWITCH_PAIR_BUSY_REASON`)를 보인다. 짝 표는 서버 `docking_pairs` 그대로(점수는 `both_published`일 때만, 아니면 쪽마다 작업 상태와 "없음(이유)"), 점수 이름은 서버 `score_label`. Mol* 표시·저장된 보기·브리지는 건드리지 않는다. M18 `DockingPanel`은 바꾸지 않았다(M18 순수 함수 `dockingConditionArgs`를 추출해 함께 씀).
- 지식·보고서 탭 효소 반응 지식 영역(M26): run이 없으면 이유만(`reaction-no-run`), capability(`methods.reaction_knowledge`)가 없으면 이유만(`reaction-unavailable`). 스냅샷이 없거나 손상이면(`not_installed`·`snapshot_invalid`) 숫자·컨트롤 없이 이유와 가져오기 명령(`REACTION_IMPORT_COMMAND`)만 보이고 요청 블록은 닫는다. 탭에 들어올 때마다 스냅샷 상태·구조·번호 대응·결과 목록을 GET으로만 다시 읽고, 쓰기는 사람이 누르는 "연결하기"(`POST /commands` `link_reaction_knowledge`)와 보고서 만들기뿐이다(승인·예산 없음). 구조·체인·번호 대응은 자동으로 고르지 않는다: 구조 파일의 PDB ID와 같은 구조의 가장 최근 번호 대응의 PDB ID·체인 accession은 빈 칸에만 제안으로 채우고(`applySuggestions`), PDB ID는 사람이 확인해야 보내며(확인하지 않으면 `pdb_id: null`, M-CSA 검사하지 않음), M-CSA가 적은 accession은 "이 accession 쓰기" 단추로만 칸에 들어간다. 요청 가드(`checkReactionForm`: 구조, PDB ID·accession 형식, 체인 행, 같은 구조의 번호 대응)를 통과해야 단추가 열리고, 서버 입장 거절은 칸 옆에 "한국어 (code)"로 보인다. 결과는 서버 저장값만 보이고 화면은 대응·개수를 계산하지 않는다. 검사하지 않음·사용할 수 없음·계산하지 않음은 숫자 없이 "—"와 이유이며 0으로 보이지 않고, M-CSA가 다루지 않은 체인 이름표 옆에 UK4를 둔다. M-CSA 역할 문구는 영어 원문 그대로 "M-CSA 원문, 계산 아님" 열에만(빈 문자열은 빈 그대로), 잔기는 7필드 식별(null 그대로)로 보인다. 정렬·순위·막대·색 우열·"중요"·"핵심"·"활성"·효과 표현이 없다(`reactionForbiddenWords`: RK1–RK6·UK1–UK4 줄은 예외, UniProt 부위 종류 이름은 빼고 검사, 결과의 참조 원문은 서버 값이라 이 검사 대상이 아님). 고정 문장 RK1–RK6·UK1–UK4는 `lib/reaction-knowledge.ts` 상수이며 `backend/mw/reaction_knowledge_constants.py`와 같아야 한다(테스트가 파이썬 상수 파일을 읽어 대조). 결과의 세트가 사용 중 세트와 다르면 "이전 스냅샷 기준", 사용 중 세트가 없으면 "사용 중 스냅샷 없음"이고 다시 계산하지 않는다. 늦은 응답은 run + 연 결과 handle + 영역별 요청 번호(`reactionResponseCurrent`, `REACTION_AREAS`)가 모두 같을 때만 반영하고, 보고서 생성이 늦게 끝나도 run이 같으면 보고서 목록을 다시 읽는다(`reactionReportSavedForRun`). 다섯 상태(`reactionPanelState`)를 구분한다. Mol* 강조·저장된 보기·브리지는 건드리지 않는다. 수락 증거는 보고서 내려받기·실패 단계 패널 HTML을 해시만 남긴다(제3자 참조 원문을 커밋하지 않음).
- M20 영역의 촉매 칸과 후보 집합 표시(M26): 요청 영역의 촉매 주석 칸은 같은 구조(전처리 구조)의 효소 반응 지식 결과만 나열하고 가장 최근 것을 미리 고르되 자동 제출하지 않는다. 고르지 않았거나 결과가 없으면 "M-CSA 촉매 잔기 보호를 검사하지 않음"과 UK2를 눈에 띄게 보이고, 고른 결과로 미리 아는 체인별 `covered`/검사되지 않는 체인(`predictCatalyticCoverage`)과 연결된 UniProt 부위가 있을 때의 UK3 한 줄을 요청 전에 보인다. 결과 목록·상세 읽기가 실패해도 M20 요청은 쓸 수 있고 실패 이유를 칸 옆에 보인다. 결과 영역은 보호 검사 칸의 `catalytic_residue_database` 상태·이유·체인별 덮임·행 수, 위치 행의 `catalytic_residue`와 M-CSA 항목 ID(해제되면 "해제됨"), 충돌·대응 없음 목록(M-CSA가 적은 위치 포함)을 보이고, 덮인 체인이 없으면 저장된 0 대신 "—"와 이유를 보인다(`catalyticRowCountText`, `exclusionReasonCountText`). 한계 문장 셋째는 저장된 문장 그대로(상태별 변형). 후보 집합을 고르는 다섯 곳(M20 목록·M21 요청·M23 선택·M24 변이 소스·M25 단백질 루프 풀)은 `catalytic_status`가 `checked`가 아닌 집합에 같은 "촉매 잔기 검사 안 함"(UK2) 표시와 상태별 상세(`catalyticBadge`: `not_available`은 v1, `not_checked`는 이유)를 단다. 표시는 세대가 아니라 상태 기준이다. 계산·전송·루프 규칙과 화면 흐름은 그대로다.
- 체인을 모두 해제한 상태로 포켓 검출을 실행하지 못한다(빈 목록은 서버에서 전체 체인을 뜻하므로).
- 분석 흐름 패널은 서버가 컴파일한 계획만 보여 주고 단계를 보내지 않는다. 입력은 목표를 고르거나 "화면 선택 다시 가져오기"를 누를 때만 화면에서 가져오며, 만든 계획은 이후 화면 선택으로 바뀌지 않는다. 원자 두 개·CA 대응표·화학 준비 요청은 읽기 전용이고 없으면 "기존 화면에서 먼저 만드세요" 선행 조건이다. 리간드·체인을 자동으로 고르지 않는다.
- 계획 미리보기는 "로컬 규칙으로 만든 계획이며 모델 판단이 아닙니다"와 계획은 측정 결과가 아니라는 안내를 보여 준다. 계획 승인과 계산 승인은 따로 각각의 상태로 보여 준다("이 run에서 이미 계산 승인됨" 포함). 자연어 계획은 누를 수 없는 항목으로 이유와 함께 보여 준다. dry-run run에서는 미리보기 전용 안내를 보여 준다.
- "다음 단계 실행"은 한 번에 한 단계다. 여러 단계를 이어 누르는 자동 진행을 만들지 않는다. 모든 거절(409·412) 뒤에는 실행 기록을 다시 읽는다. 자동으로 다시 보내는 것은 `stale_revision`을 받은 중지 한 번뿐이다(`stopResend`). 폴링은 단계·작업이 진행 중이거나 이 패널의 요청이 도는 동안의 읽기만 하며 이벤트를 쓰지 않는다.
- 화학 구조 결과는 화학 작업 화면에서만 연다. 메인 패널은 "화학 작업 화면에서 열기"로 안내한다. run·실행이 바뀌면 늦은 응답은 패널과 페이지 두 곳에서 버린다.
- 사용할 수 없는 기능은 숫자 없이 이유를 보여 주고, 구현하지 않은 컨트롤은 누를 수 없게 한다.
- 요청 중에 run이나 선택이 바뀌면, 늦게 도착한 응답이 새 화면을 덮거나 다운로드를 시작하면 안 된다. 대기·결과·오류 상태는 run과 handle 기준으로 관리한다.

## 구현 패턴
- API 호출은 `src/lib/api.ts`에 모으고, 응답 타입은 `src/lib/contracts.ts`에 정의한다.
- 상태 판단 로직은 `src/lib/*.ts`의 순수 함수로 분리해 `tests/*.test.cjs`에서 테스트한다(예: `report-selection`, `saved-scene`, `event-model`).
- 한국어 문구를 쓰되 도구 식별자는 번역하지 않는다. 식별자와 사용자 입력 문자열은 이스케이프해서 렌더링한다.
- 오프스크린 QA 조작은 Playwright locator의 실제 마우스·키보드·파일 선택 입력으로만 한다. DOM `.click()`이나 애플리케이션 핸들러를 직접 호출하지 않는다. 읽기 전용 관찰은 뷰어의 data 속성이나 제한된 관찰 브리지로 하고, 이 브리지로 성공을 만들어 내면 안 된다.
