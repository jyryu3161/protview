# frontend/ — Next.js 작업 화면과 Mol* 뷰어

## 담당 범위
- 최상위 탭 `src/components/WorkspaceTabs.tsx`(정의는 `src/lib/workspace-tabs.ts`): `구조 분석` / `단백질 공학` / `리간드 설계·탐색` / `지식·보고서`와 전역 줄(현재 run `.mw-app-run`, 예산 `.mw-app-budget`). `app/page.tsx`가 이 탭 안에 기존 화면을 넣는다.

- `src/components/NumberingPanel.tsx`: M15 지식·보고서 탭의 잔기 번호 대응 화면(보고서 목록 위). 순수 판단은 `src/lib/numbering.ts`. 페이지가 run마다 `key`로 새로 만들고, 보고서를 만들면 `onReportCreated` → `ReportLibraryPanel`의 `reloadToken`으로 보고서 목록을 다시 읽게 한다.
- 메인 화면 `app/page.tsx`: run·업로드·모델·전처리·리간드·cutoff 선택, 접촉표, 기록, Inspector 보고서, SASA·OpenMM 작업 패널, 저장된 보기·그림, M10 측정·비교, M11 화학 작업 공간, M12 포켓 패널, M13 분석 흐름 패널, M16 참조 주석 패널.

- `src/components/DockingPanel.tsx`: M18 리간드 설계·탐색 탭의 도킹 영역(`LigandPanel` 다음에 같은 탭에 마운트. 수용체·결합 사이드카·SDF 가져오기, 수용체 인스턴스 목록과 선택, 리간드 출처(SDF | M17 후보 + 부모 SDF)·방식·상자 출처·값·확인 세 항목, 작업 제출·승인·시작·폴링·취소, 요약·모드 표·접촉 표 페이지·포즈 SDF 내려받기·수용체 거부 목록·한계 문장, 보고서 만들기). 순수 판단은 `src/lib/docking.ts`. 페이지가 run마다 `key`로 새로 만들고, 보고서를 만들면 보고서 목록 `reloadToken`을 올린다. M19부터 `openRequest`(`{runId, handle, seq}`) prop을 받아 일괄 행의 "상세 열기"를 기존 결과 상세로 연다(`RefusalList`도 export해 일괄 영역이 쓴다).

## 담당하지 않는 것
- 과학 계산, 단위 변환, 요약 수치 재계산: 백엔드 handle을 표시만 한다.
- 외부 네트워크: 모든 요청은 `/api/*`(→ `127.0.0.1:8000`)로만 간다. 원격 글꼴·CDN·예시 구조를 쓰지 않는다. 글꼴은 `@fontsource` 로컬 패키지다.
- 자격 증명: 브라우저에는 API 키 입력란, 설정, localStorage 저장이 없다.
- `app/gallery/`는 디자인 fixture 전시용이다. 메인 화면(`app/page.tsx`)이 gallery의 가짜 수치를 import하면 안 된다.
- 건드리지 말 것: `.next/`, `node_modules/`, `tsconfig.tsbuildinfo`(생성물), `tests/offscreen/artifacts/`의 과거 실패 증거.
- 스타일 원본은 `design/components.css`다. `src/design/components.css`를 직접 고치면 다음 `npm run tokens` 실행 때 사라진다. 원본을 고친 뒤 `npm --prefix frontend run tokens`로 복사한다.

## 불변 조건
- 구조 분석 탭(메인 화면과 화학 작업 화면)은 다른 탭이 보일 때도 언마운트하지 않는다. `visibility:hidden`·`pointer-events:none`·`inert`로 숨기고 `display:none`이나 조건부 렌더링·key 변경을 쓰지 않는다(Mol* 캔버스 크기와 뷰어·선택·진행 중 폴링을 유지하기 위해). 탭 전환은 뷰어 브리지의 사용자 동작 콜백이나 복원 취소를 부르지 않는다. 다른 탭 패널은 선택된 동안에만 렌더링한다(기존 검사의 텍스트 locator와 겹치지 않게).
- 최상위 탭 이름은 레일 탭 이름(`run`, `models`)으로 시작하지 않는다. 전역 예산 요소에 `.mw-top-budget`을 쓰지 않는다(기존 검사가 이 클래스로 값을 읽는다). 전역 예산은 새 주기적 폴링 없이 탭 전환과 화학 화면 `onObjectsChanged` 때 `/budget`을 한 번 읽는다.
- run 선택·전환은 구조 분석 탭(메인 레일, 화학 화면)에만 있다. M20부터 기능 없는 탭은 없다(`UNAVAILABLE_NOTICES`는 빈 표이며 타입과 "사용할 수 없음" 문구는 나중 탭을 위해 남김). 기능 없는 탭이 다시 생기면 사용할 수 없음·이유·여는 단계만 보여 주고 숫자·컨트롤·요청이 없어야 한다. 지식·보고서 탭은 M15부터 안내 대신 번호 대응 화면과 보고서 목록을, 리간드 설계·탐색 탭은 M17부터 리간드 후보 화면을, M18부터 그 아래 도킹 영역을, M19부터 그 아래 일괄 도킹 영역을, 단백질 공학 탭은 M20부터 변이 후보 화면을, M21부터 그 아래 변이 구조 모델링 영역을 보여 준다(선택된 동안에만 렌더링, 들어갈 때 GET 읽기만).
- 보고서 목록은 저장된 바이트만 보여 준다(Markdown은 `<pre>` 원문, 렌더링하지 않음). 흐름은 `complete`이고 `summary_handle`이 있으며 `error`가 없는 실행만 넣는다. 목록 세 개는 오류가 서로 독립이고, run·요청 순번이 맞지 않는 응답은 버린다. 다운로드는 사용자가 누른 링크로만 일어난다. 보고서 목록(`ReportLibraryPanel`)에는 구조 분석으로 건너가 여는 버튼과 보고서 생성 버튼을 두지 않는다(번호 대응 보고서는 번호 대응 화면의 "보고서 만들기"로 만들고, 목록은 `reloadToken`으로 다시 읽는다).
- 번호 대응 화면: PDB ID는 `pdb_id_hint` 제안을 보여 주기만 하고, 사용자가 확인 체크(또는 수정)해야 보낸다(확인하지 않으면 `pdb_id: null`). 구조·체인·accession을 자동으로 확정하지 않는다. SIFTS accession이 하나인 체인만 미리 채우고(수정 가능), 여러 개(융합)인 체인은 accession을 보내지 않는다. UniProt은 스냅샷 검색 결과에서만 고른다. 행 표는 7필드를 그대로, 상태 필터와 전체 개수를 함께 보여 준다(대응됨이 아닌 행을 숨긴 채 전체처럼 보이게 하지 않음). 충돌은 양쪽 답, 대응 없음은 이유, 교차 확인 없음·잔기 불일치·`gapped_unique`를 표시한다. 이유 코드는 "한국어 (code)"로 코드를 함께 보여 주고(`reasonText`, 모르는 코드는 그대로), 한국어 이름을 추가·변경하면 `tests/numbering.test.cjs`와 `backend/tests/test_residue_numbering.py`의 `REASON_CODES`를 같이 고친다. 스냅샷 표시는 `snapshotBadge`로 정한다: 사용 중 세트가 있고 대응의 세트와 다를 때만 "이전 스냅샷 기준"(`data-stale`), 사용 중 세트가 없으면 "사용 중 스냅샷 없음"(`data-no-active-set`). 백엔드는 세트가 없을 때도 `stale_snapshot: true`를 주므로 이 값만으로 "이전 스냅샷 기준"을 그리지 않는다. 스냅샷 영역에는 숫자 없는 범위 문장(`SNAPSHOT_SCOPE`, 보고서 `limitations`와 같은 문장, `backend/mw/numbering_reports.py`와 함께 고친다)을 항상 보여 준다. 위치·KLIFS 번호는 참조 값으로 표시하고, 일치율·정렬 범위는 백엔드 값을 소수 한 자리 `ROUND_HALF_UP`(10진 문자열 기준)으로만 표시한다. 스냅샷을 사용할 수 없으면 숫자 없이 이유와 가져오기 명령(`IMPORT_COMMAND`, `docs/operations.md`와 같은 줄) 안내만. 체인 목록은 `structure_residues`의 `category` polymer 기준이라 도구의 사슬 잔기 규칙과 다를 수 있다(서버가 판단, `docs/tracking/findings.md`). run이 바뀌면 늦은 응답은 버린다. 지식 탭 번호 대응 화면에는 Mol* 강조가 없다(M16 참조 주석은 구조 분석 탭 패널에만 있다).
- 화면의 과학 수치는 모두 백엔드 객체에서 온다. 미리보기 5행을 전체 결과처럼 표시하지 않는다.
- Mol* 조작은 모두 MolstarViewer 브리지의 직렬 큐를 거친다. 매 await 전후에 session, client, generation, source handle, catalog hash, action revision을 확인한다. 하나라도 바뀌었으면 그 작업은 적용하지 않는다.
- "적용됨"은 native 작업을 커밋하고 다시 읽어 확인한 뒤에만 보고한다. React state만 바꾸고 성공으로 표시하지 않는다. 부분 적용은 적용된 명령과 거부된 명령을 나눠 보여 주고, 롤백했다고 주장하지 않는다.
- 브라우저 선택 → 잔기·원자 식별자 변환은 제공된 바이트의 SHA-256에 묶인 `atomSourceIndex` 일대일 대응만 쓴다. Mol*가 합성한 label, PDB serial, 좌표 최근접을 쓰지 않는다. 대응이 준비되기 전에는 선택·초점·저장 컨트롤이 기다리거나, 재시도 가능한 오류를 보여 준다.
- 바인딩 6필드가 모두 같은 재발행은 새 사용자 동작이 아니다. 카탈로그 준비나 검증 같은 관찰은 `onSelect`를 호출하거나 복원을 취소하면 안 된다. 실제 클릭, 빈 곳 클릭, 회전은 대기 작업을 취소한다.
- 최소화된 단백질을 표시할 때는 원래 복합체의 접촉 행을 숨기거나 비활성화하고, 범례에 OpenMM 최소화 구조임을 명시한다. 비교(오버레이) 중에는 단일 소스 저장 보기·PNG·M8 프롬프트를 비활성화하고 이유를 보여 준다.
- 화학 구조 보기는 M8·M9·M10의 입력으로 쓸 수 없다.
- 포켓 오버레이는 저장된 알파 구 중심·반지름 그대로 그리고, 구는 선택 대상이 아니다(주변 잔기는 선택 가능). 오버레이 중 M9 저장·PNG와 M8 요청을 비활성화하고 이유를 보여 준다. M10 비교 중에는 포켓 검출·오버레이를 막는다. 최소화 구조의 포켓은 OpenMM 최소화 보기와 같은 상태로 보여 준다. run·소스가 바뀌면 늦은 포켓 응답은 패널과 페이지 두 곳에서 버린다.
- 참조 주석 패널: 구조 분석 탭 메인 화면에만 둔다(화학 작업 화면·지식 탭에 없음). 표시 소스가 원본·전처리 구조일 때만 동작하고, 최소화·화학 구조면 숫자·컨트롤 없이 이유만. 번호 대응·접촉 결과·주석 목록은 표시 소스와 구조 handle이 같은 것만 보이고(`mapsForSource`·`contactSetsForSource`·`annotationsForSource`), 하나뿐이어도 자동으로 고르지 않는다("접촉 결과 없이"도 사용자가 고름). 이전 스냅샷 기준 대응은 M15 `snapshotBadge` 규칙. 부위 표는 계산하지 않음·접촉 도구가 검사하지 않는 잔기·접촉 결과 없음·cutoff 안 접촉 없음을 0과 다른 문장으로 보여 주고(`contactCountText`·`minDistanceText`), 거리는 저장값을 소수 둘째 자리 `ROUND_HALF_UP`(10진 문자열 기준)으로만 표시한다. 이유 코드는 "한국어 (code)". 다섯 상태를 구분하고 `null_result`면 부위별 이유를 함께 보여 준다. run·소스가 바뀌면 늦은 응답을 패널과 페이지 두 곳에서 버리고 켜진 주석을 끈다.
- 참조 주석 뷰어 표시: 이름표 문자열은 서버 `display_label` 그대로, 점선 거리는 저장된 `distance_A`(뷰어가 다시 재지 않음). 점선 끝 원자는 7필드 + 원자 이름이 검증된 카탈로그에서 정확히 하나로 풀릴 때만 그리고(`resolveAtom`), 아니면 그리지 않은 쌍으로 이유와 함께 남긴다. 포켓 오버레이처럼 자체 revision·세션·세대·소스·카탈로그로 보호하고 native readback 뒤에만 적용됨을 보고한다. 점선·거리 이름표는 선택 대상이 아니고, 부위·리간드 잔기 클릭은 기존 잔기 선택과 같다. 구역 색은 디자인 토큰(`site-*`), 토큰이 없으면 오류이며 색을 추측하지 않는다.
- 참조 주석과 다른 기능: 포켓 오버레이와 동시에 켜지지 않는다(막힌 쪽은 `data-pocket-overlay-blocked` 등으로 이유 표시). M10 비교를 시작하면 끄고 비교 중에는 켤 수 없다. 켜진 동안 M8 자연어 요청은 막고(`naturalLanguageDisabledReason`, 로컬 `/` 명령은 허용), M9 저장·PNG는 허용한다. 화학 작업 화면에 들어가거나 `viewer_scene@1`을 복원하면 끈다. 주석이 켜진 저장은 `viewer_scene@2`(`sceneSaveBody`), 꺼진 저장은 `viewer_scene@1` 본문을 바이트 그대로 보낸다. `viewer_scene@2` 복원은 포켓 오버레이·비교 중이면 부작용 전에 거절하고(`sceneRestoreDecision`), 저장된 주석을 읽기 API로 읽어 뷰어 prop에 먼저 넣은 뒤 복원한다(도구 호출 없음). 거부되면 적용·거부를 나눠 보여 주고 그 요청을 거둔다. PNG 범례는 보기의 `legend`가 참이고 그린 점선이 있을 때만 같은 글자 크기로 합성하며, 들어가지 않으면 그림을 저장하지 않는다(`FIGURE_LEGEND_NO_FIT`). 범례 문구(`FIGURE_LEGEND_TEXT`)를 바꾸거나 없애지 않는다.
- 리간드 탭: run이 없으면 안내만, capability를 쓸 수 없으면 숫자·컨트롤 없이 이유만 보여 준다. 다섯 상태를 구분하고 후보 0개는 빈 결과(거부 이유별 개수와 함께)이지 실패가 아니다. 점검 객체·후보 집합은 자동으로 고르지 않는다. 번호 붙은 그림은 저장된 SVG를 `<img>` data URI로만 보여 주고 DOM에 넣지 않는다. 원자 번호는 서버의 SDF 번호 그대로이며 점검 전에는 부위 체크를 비활성으로 두고 이유를 보여 준다. 부위·규칙 판정은 미리보기 API 응답을 보여 주기만 한다. 생성 요청에는 규칙 텍스트가 아니라 `rule_ids`만 보낸다. 속성·통과/실패는 서버 값만 표시하고(분자량·logP·TPSA는 `decimalHalfUp` 소수 둘째 자리, 개수는 정수), 필터 경계는 입력한 문자열 그대로 행 읽기 쿼리에 보낸다(화면은 경계 비교를 다시 하지 않음). 필터 기본값은 비어 있고, 전체 수와 필터로 숨긴 수를 함께 보여 준다. 문구는 "적용한 필터"("활성"은 보고서 금지어), 속성은 "RDKit 추정값", PAINS는 "구조 경고 일치". 약물 유사성·독성·활성·합성 가능성을 말하지 않는다. 한 번에 한 작업만 진행하고, run·점검 선택이 바뀌면 진행 중 요청을 abort하고 영역별 순번이 맞지 않는 응답을 버린다. 이유 코드는 "한국어 (code)". 패널 안 예산 표시는 작업이 끝나면 다시 읽지만 전역 예산 줄은 기존 규칙대로 탭 전환 때만 읽는다.
- 리간드 탭 도킹 영역: run이 없으면 안내만, capability를 쓸 수 없으면 숫자·컨트롤 없이 이유만(`worker_missing` 등). 다섯 상태를 구분하고 모드 0개는 빈 과학 결과이지 실패가 아니다. 수용체·인스턴스·리간드·후보·부모 SDF·결과는 자동으로 고르지 않는다("없음(단백질만)"도 사용자가 고름). 코어 고정은 후보 출처일 때만, 인스턴스 범위 상자는 인스턴스를 골랐을 때만 고를 수 있고 막힌 이유를 보여 준다. 작업 인자는 `dockingArgs`가 서버와 같은 고정 모양으로 만들고, 시간 상한은 `POST /jobs`의 `timeout_s` 600(`DOCKING_TIMEOUT_S`)으로 고정해 화면에 보이지 않는다. 확인 세 항목이 모두 체크되지 않으면 시작을 막는다. 점수 이름은 "qvina 점수(kcal/mol, Vina 계열 스코어링 함수 값. 친화도가 아님)"(요약), 표 열은 "qvina 점수(kcal/mol)", 행은 자유 도킹 "모드 n(엔진 출력 순서)"·코어 고정 "샘플 n(점수 오름차순 나열)". 순위·best·최적·최고·개선·결합 강도·친화도 낱말을 고정 한계 문장·점수 이름 밖에서 쓰지 않는다(`dockingForbiddenWords`). 점수는 소수 첫째 자리, 거리·상자는 둘째 자리 `decimalHalfUp`, 개수는 정수이며 화면은 점수·접촉을 계산하지 않는다. 상자 좌표계 가정(`BOX_FRAME_NOTE`)과 접촉 안내(`CONTACT_NOTE`)를 항상 보여 주고, 후보 출처를 고르면 제출 전에 한계 문장 7·10·11(`CANDIDATE_SOURCE_NOTES`)을 보여 준다. 결과에는 저장된 `limitations`를 그대로 보여 준다. 수용체 거부(`receptor_unsupported_residue`·`receptor_altloc_present`)는 입장 422와 작업 실패 두 경로 모두 항목(잔기 7필드 null 그대로, 원자 이름, altloc)과 전체 개수를 보여 준다. 실패는 "한국어 (code)", `resource_exceeded`에는 "모드 수를 줄여 다시 시도" 안내. 한 번에 한 작업만 진행하고, 서버가 시작 요청을 작업 종료까지 붙잡으므로 취소는 시작 요청과 별도의 요청 순번·플래그로 제출된 job id에 보낸다(`dockingCancelEnabled`). 시작 오류는 저장된 작업을 다시 읽어 실제 상태를 보여 준다. 포즈 SDF는 사용자가 누른 링크로만 내려받는다(모드별 `pose_sdf`, 전체 `poses_sdf`). run·입력 선택이 바뀌면 run + 선택 키 + 영역별 요청 순번(`dockingResponseCurrent`)이 맞지 않는 늦은 응답을 버린다. Mol*에 포즈를 그리지 않는다. `openRequest`는 마운트 뒤 새 `seq`이고 run이 같을 때만 연다(마운트 전 요청을 다시 재생하지 않음, 아무것도 저절로 열리지 않음).
- 리간드 탭 일괄 도킹 영역: run이 없으면 안내만(`docking-batch-no-run`), capability(`methods.ligand_docking_batch`)를 쓸 수 없으면 숫자·컨트롤 없이 이유만(`docking-batch-unavailable`). 수용체·인스턴스·후보 집합·부모 SDF·후보·요약은 자동으로 고르지 않는다. 고른 후보는 후보 집합 순서로 보낸다(`orderedCandidateIds`, 클릭 순서 아님), 50개를 넘으면 더 체크할 수 없다(`candidateSelectable`). 부모 기준 행은 자유 방식에서만 고를 수 있고 코어 고정이면 꺼지며 이유(`batch_parent_not_allowed`)를 숫자 없이 보인다(`parentDisabledReason`, `patchBatchForm`). 작업 인자는 `batchArgs`가 서버와 같은 고정 모양(`ligand` 키 없음)으로 만들고 `timeout_s`는 7800(`DOCKING_BATCH_TIMEOUT_S`) 고정이다. 시작은 지금 인자와 같은 키(`batchArgsKey`)로 받은 시작 전 확인이 입장 통과·부족분 0일 때만 열린다(`batchStartBlockedReason`). 증액 승인 버튼은 입장 통과·부족분 > 0·dry-run 아님일 때만(`limitApprovalOffered`) 사람이 누를 때만 보내며, 화면이 자동으로 증액하거나 승인 뒤 저절로 시작하지 않는다. 시작 전 확인·증액·진행·요약의 모든 숫자·문장은 서버 값이며 화면은 점수·집계·부족분을 계산하지 않는다. 결과표의 점수 칸은 `scored` 행만 숫자(`decimalHalfUp` 소수 첫째 자리), 그 밖은 비우고 이유 "한국어 (code)"만. 정렬(`sortBatchRows`)은 표시 순서만 바꾸고 점수 없는 행은 방향과 무관하게 늘 끝(행 순서), 순위 열·최고 표시·강조가 없고 `aria-sort`를 둔다. 점수 대상은 서버 `score_row_label`("모드 1(엔진 출력 순서)"/"샘플 1(점수 오름차순 나열)")이며 "best"라 부르지 않는다. 고정 문장 B1–B3·M18 문장은 서버가 준 저장 id의 문장 그대로, B2는 `partial`일 때 표 위에. 금지어는 `batchForbiddenWords`(B1–B3·M18 한계 문장 줄은 예외, 그 밖은 M18 검사). 한 번에 한 작업만, 서버가 시작 요청을 붙잡으므로 진행은 저장된 작업(`batch` 진행: 상태 파일 수·재사용 행·요약 handle·요약 상태)을 2초마다 다시 읽고, 취소는 별도 요청 순번·플래그로 제출된 job id에 보낸다. 다시 마운트하면 이 run의 진행 중 일괄 작업을 다시 붙잡는다(`batchActiveJob`). 작업 기록이 `failed`·`interrupted`여도 요약이 있으면 요약 상태·멈춘 이유를 함께 보인다(`batchJobText`). 늦은 응답은 run + 선택 키 + 영역별 요청 순번(`dockingResponseCurrent`)으로 버린다. 부모 대비 차이·잔기 비교 표·Mol* 표시는 없다. `data-testid`는 모두 `docking-batch-` 접두사(M17 필터도 `idPrefix`로), M17·M18 영역의 testid와 겹치지 않게 한다.
- 단백질 공학 탭 변이 후보: run이 없으면 이유만(`mutation-no-run`), capability(`methods.mutation_candidates`)가 없거나 사용할 수 없으면 이유만(`mutation-unavailable`), 전처리 구조가 없으면 "사용할 수 없음"과 먼저 전처리하라는 이유만(숫자·컨트롤·도구 호출 없음). 변이 구조 모델링은 후보 행에서 따로 시작한다는 한 줄(`MODELING_NOTE`, 숫자 없음, M21에서 "아직 없음" 문장을 바꿈)을 늘 둔다. 후보 표의 "변이 구조 모델링" 버튼(`mutation-candidate-model`)은 `onModelCandidate`가 있을 때만 보이며 요청을 보내지 않고 후보만 넘긴다. 전처리 구조·포켓 결과·리간드는 자동으로 고르지 않는다(리간드가 하나뿐이어도, 명세 10절 문구와의 의도된 편차, 결정 0028). 예외는 구조를 고를 때 같은 구조의 가장 최근 주석과 그 주석이 기록한 번호 대응을 미리 고르는 것뿐이다(`preselectAnnotation`, 구조를 바꾸면 그 구조에 묶인 선택을 모두 지움). 포켓 결과·번호 대응·주석은 같은 구조 것만(`pocketSetsForStructure`는 포켓 있는 결과만), 번호 대응이 주석의 지도와 다르면 충돌 문구(`MAP_CONFLICT_TEXT`)를 보이고 요청을 막는다. 주석이 없으면 요청 영역에 `KLIFS_NOT_CHECKED_NOTICE`를 눈에 띄게 보인다. 요청 인자는 `mutationRequestArgs`가 서버와 같은 모양으로 만들고(허용 잔기는 20종 순서 문자열, 거리는 지수·부호 없는 10진 숫자만), 막히는 이유를 모두 보인다. 서버 거절은 "한국어 (code)"(`mutationErrorText`, `too_many_positions`는 위치 수와 상한). 모든 숫자는 서버 응답이며 화면은 거리·개수·보호 판정을 계산하지 않는다. 거리는 `decimalHalfUp` 소수 둘째 자리, null은 "—"와 이유(`ligandDistanceText`·`klifsSitesText`·`numberingText`). 검사하지 않음·사용할 수 없음을 0이나 "없음"으로 보이지 않는다. 보호 판정을 "안전", 후보를 "추천·좋은·유망", 목록 순서를 순위로 부르지 않고(`LIST_ORDER_NOTE`), 점수·순위 열·막대 그래픽이 없다. 금지어는 `mutationForbiddenWords`(고정 한계 문장 5줄은 예외). 고정 한계 문장은 저장된 `limitations`를 그대로 보인다. 다섯 상태(`mutationPanelState`)를 구분하고 후보 0개는 저장된 제외 사유별 개수와 함께 빈 결과(`mutation-null-result`)이지 실패가 아니다. 늦은 응답은 두 층으로 버린다: 언마운트·run 바뀜 때 abort, 그리고 run + 연 결과 handle + 영역별 요청 번호(`mutationResponseCurrent`)가 모두 같을 때만 반영. 보고서 생성이 늦게 끝나 화면 표시를 버려도 run이 같으면 보고서 목록을 다시 읽게 한다(`mutationReportSavedForRun`). `data-testid`는 모두 `mutation-` 접두사. Mol* 강조·내려받기(CSV·JSON)는 없다.
- 단백질 공학 탭 변이 구조 모델링(M21): 영역은 `MutationPanel` 밖 형제 요소로 둔다(M20 패널 안 문구·요청 검사 범위와 `data-testid="mutation-panel"` 선택자를 바꾸지 않기 위해). `data-testid`는 모두 `mutation-model-` 접두사. run이 없으면 이유만, capability(`methods.mutation_model`)가 없거나 사용할 수 없으면 숫자·컨트롤 없이 이유만, 같은 조건 도킹은 `methods.ligand_docking`을 쓸 수 없으면 그 영역만 이유와 함께 막힌다. 후보·모델·리간드·결과를 자동으로 고르거나 열지 않고, 후보 전달은 요청 칸만 채운다(seed 비움, 확인 체크 안 됨, cutoff 4.0·시간 120 기본). 요청은 `modelRequest`가 서버와 같은 모양(인자 여섯 + 최상위 `timeout_s`)으로 만들고 막히는 이유를 모두 보인다. 비싼 계산 1단위 안내와 명시적 "비싼 계산 승인"(첫 계산)은 M7 방식이다. 모든 숫자는 서버 저장값이며 화면은 전위·SASA·접촉·점수를 계산하지 않는다. 전위·SASA·거리는 `decimalHalfUp` 소수 둘째 자리, null은 "—"와 이유(`nullText`). 두 구조의 차이·증감·개선 표시, 화살표, 구조 간 막대·색 비교, 순위 열이 없고 두 구조 칸은 같은 스타일이다. 금지어는 `modelForbiddenWords`(고정 한계 문장 `MODEL_LIMITATIONS` 줄은 예외, 그 밖의 줄은 M18 점수 이름만 지운 뒤 검사). 한계 문장은 저장된 `limitations` 그대로. 접촉 0개는 "0개, 계산한 결과"이지 null이 아니다. 다섯 상태(`modelAreaState`·`pairAreaState`)를 구분한다. 늦은 응답은 run + 모델 handle + 영역별 요청 번호(`modelResponseCurrent`, 영역 `list`·`detail`·`contacts`·`pairs`·`report`·`model_job`·`pair_jobs`)가 모두 같을 때만 반영하고, 보고서 생성이 늦게 끝나도 run이 같으면 목록을 다시 읽는다(`modelReportSavedForRun`). 같은 조건 도킹은 SDF 리간드만(후보 출처는 `PAIR_SDF_ONLY_REASON`과 함께 막힘), 자유 도킹만, 인스턴스 범위 상자 막힘, 2단위 확인 체크 뒤 한 번의 동작으로 `pairDockingRequests`가 만든 두 요청(`receptor_source.side`만 다름)을 야생형 기준 → 변이형 순서로 제출하고 하나씩 시작한다. 한쪽 거절·실패가 다른 쪽을 숨기지 않는다. 시간 상한은 M18 `DOCKING_TIMEOUT_S` 600. 짝 동작이 진행 중(`pairBusy`)이면 다른 모델을 열 수 없고 이유(`MODEL_SWITCH_PAIR_BUSY_REASON`)를 보인다. 짝 표는 서버 `docking_pairs` 그대로(점수는 `both_published`일 때만, 아니면 쪽마다 작업 상태와 "없음(이유)"), 점수 이름은 서버 `score_label`. Mol* 표시·저장된 보기·브리지는 건드리지 않는다. M18 `DockingPanel`은 바꾸지 않았다(M18 순수 함수 `dockingConditionArgs`를 추출해 함께 씀).
- 체인을 모두 해제한 상태로 포켓 검출을 실행하지 못한다(빈 목록은 서버에서 전체 체인을 뜻하므로).
- 분석 흐름 패널은 서버가 컴파일한 계획만 보여 주고 단계를 보내지 않는다. 입력은 목표를 고르거나 "화면 선택 다시 가져오기"를 누를 때만 화면에서 가져오며, 만든 계획은 이후 화면 선택으로 바뀌지 않는다. 원자 두 개·CA 대응표·화학 준비 요청은 읽기 전용이고 없으면 "기존 화면에서 먼저 만드세요" 선행 조건이다. 리간드·체인을 자동으로 고르지 않는다.
- 계획 미리보기는 "로컬 규칙으로 만든 계획이며 모델 판단이 아닙니다"와 계획은 측정 결과가 아니라는 안내를 보여 준다. 계획 승인과 계산 승인은 따로 각각의 상태로 보여 준다("이 run에서 이미 계산 승인됨" 포함). 자연어 계획은 누를 수 없는 항목으로 이유와 함께 보여 준다. dry-run run에서는 미리보기 전용 안내를 보여 준다.
- "다음 단계 실행"은 한 번에 한 단계다. 여러 단계를 이어 누르는 자동 진행을 만들지 않는다. 모든 거절(409·412) 뒤에는 실행 기록을 다시 읽는다. 자동으로 다시 보내는 것은 `stale_revision`을 받은 중지 한 번뿐이다(`stopResend`). 폴링은 단계·작업이 진행 중이거나 이 패널의 요청이 도는 동안의 읽기만 하며 이벤트를 쓰지 않는다.
- 화학 구조 결과는 화학 작업 화면에서만 연다. 메인 패널은 "화학 작업 화면에서 열기"로 안내한다. run·실행이 바뀌면 늦은 응답은 패널과 페이지 두 곳에서 버린다.
- 사용할 수 없는 기능은 숫자 없이 이유를 보여 주고, 구현하지 않은 컨트롤은 누를 수 없게 한다.
- 요청 중에 run이나 선택이 바뀌면, 늦게 도착한 응답이 새 화면을 덮거나 다운로드를 시작하면 안 된다. 대기·결과·오류 상태는 run과 handle 기준으로 관리한다.

## 구현 패턴
- API 호출은 `src/lib/api.ts`에 모으고, 응답 타입은 `src/lib/contracts.ts`에 정의한다.
- 상태 판단 로직은 `src/lib/*.ts`의 순수 함수로 분리해 `tests/*.test.cjs`에서 테스트한다(예: `report-selection`, `saved-scene`, `event-model`).
- 한국어 문구를 쓰되 도구 식별자는 번역하지 않는다. 식별자와 사용자 입력 문자열은 이스케이프해서 렌더링한다.
- 오프스크린 QA 조작은 Playwright locator의 실제 마우스·키보드·파일 선택 입력으로만 한다. DOM `.click()`이나 애플리케이션 핸들러를 직접 호출하지 않는다. 읽기 전용 관찰은 뷰어의 data 속성이나 제한된 관찰 브리지로 하고, 이 브리지로 성공을 만들어 내면 안 된다.
