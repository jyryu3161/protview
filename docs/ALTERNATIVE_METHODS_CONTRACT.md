## Pre-implementation numerical correction: Lee–Richards replaces rejected Shrake–Rupley

Before any M6 approval, root and Astra independently found that FreeSASA2.2.1 `calcCoord` with Shrake–Rupley1000 points/probe1.4Å/thread1 returned33.451301584305675Å² for a single radius1.7Å sphere, instead of analytic120.76282160399167Å². Two spheres separated by100Å returned154.2141231882973Å² instead of241.52564320798334Å². This observed engine numerical defect is sufficient to reject that configuration; its internal cause has not been asserted. No production or experimental value was approved from it. Root's failed evidence remains `/tmp/protview-qa/m6-independent-sasa-reference.json`; Astra's independent evidence is `/tmp/protview-qa/m6-astra-engine-analytic-probe.json`.

With the same explicit inputs, Lee–Richards100 slices/probe1.4Å/thread1 returned120.76282160399181Å² for the single sphere and241.52564320798362Å² for separated spheres. Equal spheres at center distance3.1Å returned181.18842396692094Å² against analytic181.14423240598748Å² (about0.0244% error). Therefore the selected production algorithm is changed to Lee–Richards100 slices, with the analytic tolerances below. Do not special-case isolated atoms, multiply output by a correction factor, copy expected numbers into product code, weaken conservation checks or silently retain SR in a fallback. Every result/cache/report records the actual changed algorithm and resolution. The interrupted Sol invocation was a design-correction interruption, not a successful phase or a fabricated failed approval. Its partial implementation is preserved for the next Sol invocation.

## 2. M6 scientific definition

Tool: `compute_interface_sasa`, emits `interface_sasa@1`. Input: one same-run `prepared_structure@1` handle and one exact full ligand ResidueRef. Derive these from the currently inspected interaction when applicable; otherwise use the explicitly selected prepared structure/ligand. Never combine historical ligand/results with a latest unrelated structure.

Define P as the prepared model's standard amino-acid protein heavy atoms across all included protein chains; L is exactly the selected nonpolymer ligand's heavy atoms. Require both sets nonempty and disjoint. Use a declared canonical20-amino-acid classification; a nonstandard polymer is unsupported, not silently reclassified as ligand or dropped from protein. Preserve model/auth/label/insertion identity. Exclude water, ions, other ligands and nonprotein components from this particular two-partner analysis and record their exact residue references/counts and policy. Never claim the value represents the full crystal/asymmetric-unit environment. Hydrogens/deuterium are excluded explicitly. Duplicate/ambiguous atom identities, unresolved altlocs or nonfinite coordinates fail before calculation. Before any FreeSASA C call, also reject coincident selected atom centers (different identities at exactly the same coordinate), numerically indistinguishable centers within1e-6Å, empty arrays, count/shape mismatch and nonpositive/nonfinite radii; no silent deduplication. Bound absolute coordinate magnitudes to1e6Å and each selected bounding-box extent to1e4Å, then translate all three calculation inputs by the same documented origin to avoid pathological native arithmetic. These are explicit input-support limits, not experimental corrections. Preserve original immutable coordinates and record the analysis-only translation. Exact ligand comparison uses the complete ResidueRef, not display text, residue name or a subset of author identifiers.

Use FreeSASA `calcCoord` on explicit coordinates/radii, avoiding PDB reserialization and implicit HETATM/unknown-atom parser behavior. Fixed protocol defaults:

- Lee–Richards algorithm,100 slices per atom, probe radius1.4Å, one thread. Use method ID `freesasa_lee_richards_v1`; record `algorithm=LeeRichards` and `n_slices=100` in effective parameters, cache identity, scientific result and report. Shrake–Rupley/n_points is not a selectable production alternative in this protocol.
- Explicit `gemmi_vdw_elements_v1` radius policy for C,N,O,S,P,F,Cl,Br,I only. Use installed Gemmi Element.vdw_r values, validate finite positive values, persist the actual element→radius table and Gemmi version. Label this as Gemmi element van der Waals radii, not a claim of a pure Bondi or ProtOr parameter set. Unsupported/unknown elements fail rather than receiving a guessed radius or being dropped.
- At most6000 selected heavy atoms in P∪L for the synchronous MVP path. Reject larger work with typed resource/input information; no arbitrary resolution/algorithm/radius-table input in this first protocol. Version the method if these constants change.

Compute three real calculations with identical fixed settings: SASA(P), SASA(L), SASA(P∪L). Preserve the atom-index→full residue/atom mapping and per-atom areas. Let P_bound and L_bound be the corresponding atom-area sums within the combined calculation. Report:

- `protein_sasa_isolated_A2`, `ligand_sasa_isolated_A2`, `complex_sasa_A2`, `protein_sasa_bound_A2`, `ligand_sasa_bound_A2`.
- `protein_burial_A2 = protein_sasa_isolated_A2 - protein_sasa_bound_A2`.
- `ligand_burial_A2 = ligand_sasa_isolated_A2 - ligand_sasa_bound_A2`.
- `total_sasa_loss_A2 = SASA(P) + SASA(L) - SASA(P∪L)`, equal to the sum of the two partner losses within declared floating-point tolerance.

Do not silently divide by2 and call that a universal interface area. The UI names partner burial and total SASA loss explicitly. Per-protein-residue rows aggregate isolated/bound/buried areas from full atom identities; preserve zero rows or disclose a display filter while full JSON retains them. Å² is the only unit. This is probe/radius/resolution-dependent solvent-accessible geometry, not binding strength, energy or a validated hydrogen-bond measure.

Keep exact finite values. Validate atom counts, nonnegative areas, sums and partner accounting. Store raw differences; any tiny floating-point normalization must have a named numerical tolerance (for example1e-6Å² absolute plus1e-10 relative), retain original values and disclose it. A materially negative burial is a calculation error. Two-decimal rendering uses the existing checked ROUND_HALF_UP policy, not a scientific acceptance tolerance. A valid separated partner gives zero burial while retaining positive SASA; it is a successful measurement, not a missing-ligand or failed-read state.

## 4. M7 scientific definition and explicit preprocessing

Protocol: `openmm_protein_minimize`, version1; distinct from `relax_structure`, estimate_stability and every Rosetta protocol. Use OpenMM8.6.0 CPU platform, Threads=1, fixed built-in `amber14-all.xml` plus `implicit/gbn2.xml`, NoCutoff, no constraints, no periodic box/explicit solvent. Set pH7.0, minimization tolerance10kJ/mol/nm and maxIterations50; never pass zero/unbounded iterations. The job timeout defaults60s, bounded by the run's remaining wall allowance; a bounded allowlisted request may select up to120s. No arbitrary platform, XML path, integrator, executable, force-field upload or command is accepted.

Require explicit `selection_policy=protein_only` and `hydrogen_policy=rebuild_pH7` in the normalized request/UI action. Select canonical standard protein residues; list every omitted ligand/water/ion/nonprotein component, source hydrogen removal and every added hydrogen. Unsupported/modified polymer residues, unresolved alternate sites, missing heavy atoms, missing terminal atoms, invalid bonds/templates or ambiguous residue/atom identities are typed unsupported/input failures. Do not silently cap termini, fill heavy atoms, mutate residues or install/use PDBFixer. Do not ignore unmatched templates/external bonds to force acceptance. Nonprotein exclusions are part of the named protein-only calculation, never concealed preparation of the full complex.

Build topology using an explicit immutable atom/residue mapping from Gemmi identities. Do not rely on lossy PDB numbering or duplicate author chain names. Generated OpenMM chain/residue indices are internal keys with a stored bijection to full source references; added hydrogens carry their parent residue and a new atom identity. Preserve original heavy atom coordinates before H rebuilding. Validate atom/bond counts and mapping at each stage. Record protonation variants actually chosen by Modeller.addHydrogens, disulfide handling, pH and RNG seed. Seed supported Python/NumPy construction RNGs in the isolated worker; record platform/version and do not promise cross-version bitwise reproducibility.

Persist a method-specific preparation manifest and actual hydrogenated input coordinates before energy evaluation, then actual final coordinates. Do not overwrite the original prepared object or call protein-only/minimized coordinates the original complex. A dedicated `openmm_minimized_structure@1` envelope with mapped mmCIF bytes is acceptable; only explicitly supported viewer/read paths consume it. Existing interaction tables remain bound to their original input; the minimized protein has no retained ligand for a fabricated complex-contact recalculation.

Record native potential energies before and after minimization in kJ/mol, `potential_change_kJ_mol=after-before`, force-field/settings/versions/seed, atom/residue counts, actual exclusions, input/model/topology/System-XML hashes and the minimized-coordinate handle. Hash the fixed force-field XML files and their transitive built-in includes; no caller-controlled include path is permitted. Include these dependencies in cache identity. Keep finite exact values and declared rendering. Enforce consistent topology/settings for before/after; reject malformed/nonfinite outputs. A substantial potential increase is a calculation failure; retain any tiny numerical deviation with its declared tolerance instead of changing the measured energy. Do not label completion as converged solely because the iteration cap returned; use `convergence_not_claimed` unless the chosen implementation has actual convergence evidence. Do not invent an iteration count when the API does not report it.

These are method-specific potential energies and a local minimization change, not REU, ΔΔG, binding energy, stability improvement or an across-protein ranking. GBn2 is an implicit-solvent model, not experimental solvent. Parent feasibility: explicit protein-only1HSG fails missing terminal OXT and must remain a clear failure under this policy. Public1UBQ (SHA056f98710cb2b36f633c45e41902a02eb446e82871da21ff2dd44f74a56ca0f6) with58waters excluded, H rebuilt and1231 resulting atoms ran successfully. Its feasibility energies are not production expected constants; actual production job results must be independently recomputed and attributed.
