## Scope and scientific meaning

Add actual two-click atom distance in Å and rigid comparison of two explicitly selected immutable same-run structures using explicit CA atom correspondences. Render the reference and transformed moving structure together, allow aligned/unaligned and layer visibility controls, inspect correspondence rows, and produce immutable field-cited measurement/comparison reports. Preserve original coordinates and identifiers. No automatic sequence/chain alignment, atom-name guessing, mutation ranking, ensemble, affinity, stability or quality inference is included. RMSD describes only the declared atom pairs and rigid fit. Stored overlay transforms are display operations, not modified scientific structures.

Depend on accepted M9 guarded native bridge/source lifecycle and exact artifact/recovery patterns. Review actual accepted interfaces before coding; this document anticipates them and does not authorize bypassing their guards. Existing M9 single-source scenes cannot silently serialize a two-source overlay. During comparison, disable single-scene Save/Export with a visible reason until returning to a single source; existing saved scenes continue to restore. A later explicit multi-source scene schema is separate work, not a mislabeled single-source save.

## Authoritative atom identity

Introduce strict `AtomRefV1`: `structure_handle`, complete `ResidueRef` including model/auth/label/insertion/resname, `atom_name`, normalized `altloc` (empty means no alternate), `element`, and `site_index` (zero-based index in the server's deterministic traversal of actual selected-source atoms). Every field is server-derived and must agree at resolution; site_index is source-bound, never reused for a changed source. Atom names/altloc/element are original parsed values, not display-string parsing. Preserve nullable source label IDs. Model choice comes from the immutable structure selection; no implicit first-model override. Duplicate name/altloc records remain distinguished by site_index and cannot silently become the first match.

Provide a bounded paginated local atom catalog for accepted source kinds (`structure_selection@2`, `prepared_structure@1`, validated `openmm_minimized_structure@1`). Use the same source readers as science/viewer services. Map Mol* atom loci uniquely back to these references using source identity and parser mappings; if the native index cannot be safely reconciled, return an ambiguity error rather than guessing. Handle alternate locations retained in original structures and stripped/selected prepared sources independently. Human labels show chain/auth number/insertion/atom/altloc/model and source layer.

Mapping clarification after the accepted M9 gate (`479d961`): authoritative `site_index` is assigned by the immutable selected-source traversal, not by a separately reparsed viewer file. Bind an explicit viewer-input row→AtomRef mapping to the SHA-256 of the exact bytes served for that viewer source. Installed Mol*5.11 exposes `StructureProperties.atom.sourceIndex` through `atomicHierarchy.atomSourceIndex`, which preserves input row indices despite internal atom sorting. Native element indices, PDB serials, generated label IDs and name/coordinate nearest matches are not substitutes. Verify a bijection for the loaded model, exact source identity and atom fields, with coordinates as a consistency check rather than a way to select a candidate. Identical duplicate records require explicit serialization provenance or fail as ambiguous; never choose the first. A deterministic derived mmCIF view with explicit row IDs is an allowed display adapter when needed, provided it does not mutate source objects or redefine authoritative null labels/coordinates. Unit and actual-picking fixtures must verify both PDB and mmCIF originals, prepared/minimized sources, alternates, duplicate sites and nonfirst models. Mol* may synthesize PDB label atom names and missing residue label IDs, so these generated display values cannot overwrite the authoritative AtomRef. Authoritative residue identity is the same selected-source `_res_ref` used by existing structure/M9 services: retain its actual nullable values, including a Gemmi-assigned nonnull subchain when present; do not force all PDB labels to null based only on file format. If raw-file label absence is useful provenance, expose it separately rather than changing the shared ResidueRef.

## Numerical tools and immutable results

Register `measure_distance` and `align_structures` in the existing validated `Run.call` tool lane with bounded local cost, cancellation/deadline checks and canonical cache keys. Do not implement a second scientific execution path in UI routes. No external engine/model or expensive scientific approval is needed for these bounded calculations; normal runtime limits apply. Read APIs cannot execute them on reopen. Proposed limits: distance2 atoms; alignment3–1000 explicit pairs and source atom limit consistent with the accepted small-structure runtime.

`atom_distance@1` contains schema, two complete AtomRefs, source handle, two resolved source coordinates, `distance_A`, unit `angstrom`, method `euclidean_atom_distance@1` and limitations. Both atoms must belong to the same displayed immutable source; cross-source distance is rejected with a clear explanation, including during overlay. The Euclidean norm comes from actual original coordinates. Identical/overlapping coordinates legitimately yield zero and are not scientific_null. Finite-coordinate validation and independently computed test oracles are required. Do not reuse rounded on-screen values for result storage.

`rigid_alignment@1` contains reference and moving source handles/model numbers, ordered explicit pair table, method/version, native dependency version, `rotation` (3×3 row-major), `translation_A` (3-vector), transform convention, aligned `rmsd_A`, `unaligned_rmsd_A`, pair count, fit singular values, degeneracy thresholds and per-pair before/after residuals in Å. Each pair stores complete reference/moving AtomRefs. Reject duplicate sites on either side, non-CA/non-protein atoms, source mismatch, ambiguous/missing atoms or nonfinite coordinates. User cannot supply transform/result scalars. No missing correspondence is silently omitted; a rejected pair must be corrected before fitting.

Algorithm is unweighted proper-rotation Kabsch in float64. Let P be moving coordinates and Q reference, with row vectors and matching pair order. Center X=P−mean(P), Y=Q−mean(Q); H=XᵀY; compute U,S,Vt=`numpy.linalg.svd(H, full_matrices=False)`. D=diag(1,1,det(VtᵀUᵀ)); R=VtᵀDUᵀ; t=mean(Q)−R mean(P). Apply a coordinate as column `q_fit = R p + t`, or row `P_fit=P Rᵀ+t`. Aligned RMSD=sqrt(mean(sum((P_fit−Q)^2,axis=1))); unaligned RMSD uses original P−Q with the identical pair set. Reflection is forbidden: det(R)≈+1 and RᵀR≈I must pass numerical validation.

Require at least3 pairs and rank≥2 for centered P, centered Q and H. For each singular-value sequence reject when second singular value <=max(1e-12,1e-8×first); coordinate-matrix values are in Å, H values in Å² and thresholds have the corresponding units. Three noncollinear planar points are valid; all-collinear/coincident points and numerically ill-conditioned mappings are explicit input_invalid. Publish these fixed method thresholds in result metadata. Do not claim unique orientation for rejected degenerate maps.

Installed NumPy2.4.6 was inspected directly: `numpy.linalg.svd(a, full_matrices=True, compute_uv=True, hermitian=False)` and `numpy.linalg.det(a)` are available. A design-only planar rigid-transform probe gave maximum coordinate residual8.88e-16 Å and det(R)≈1; this is not implementation acceptance. NumPy is currently transitive, so declare an explicit tested dependency/version during implementation and record actual execution version. No SciPy dependency is necessary.

The Mol*5.11 local `mol-plugin-state/transforms/model.d.ts` exposes `TransformStructureConformation` with named `matrix` transform. Use a separate display structure/tree node for moving coordinates and test the row-major3×3/translation to native4×4 conversion explicitly. Never mutate parsed source coordinates, files or stored scientific handles to implement alignment.

## API, UI and overlay lifecycle

Expose validated atom-catalog reads and normal tool submission with typed handles. Result/report reads remain bounded and source-specific. The comparison panel selects explicit reference and moving sources from same-run valid structures, then adds/removes exact CA pairs through local atom/residue selectors or native picking; label which side is active. Show complete correspondence before Compute. No automatic chain matching or first-CA selection among alternates. User chooses the exact CA altloc/site. Invalid input has actionable errors, not an apparently successful partial fit.

After successful fit create a fresh comparison scene identity bound to both source handles and alignment handle. Render distinct named/color-coded reference and moving layers with a legend, aligned/unaligned toggle, per-layer visibility and return-to-single-source. Original/unaligned mode explicitly removes display transform. Hide/disable irrelevant single-source interaction rows and M8 prompt actions while in comparison; M8's one-source schema must not target the wrong layer. Manual camera orbit/zoom remains available. Reopen/result selection restores a new comparison context from the immutable alignment result without refitting.

Native overlay picks include source-layer identity even if residue/atom names and coordinates coincide. Correspondence-row focus selects its actual two endpoints; ordinary single-atom inspection shows authoritative source coordinates and, when aligned, separately labeled display coordinates. Direct measurement is allowed only when both picks are on the same source; its value is the original-source Euclidean distance (rigid transformation preserves it). Never combine one aligned coordinate with one original coordinate to invent cross-layer distance. Crossing layers during Measure displays a clear reset/choose-same-source instruction.

Use the accepted native operation queue and source/session/generation/manual-revision guards for source fetch, representation, transform, picks and focus. Rapid alignment A→B/read/run switch cannot apply A to B. A new comparison invalidates outstanding single-source viewer intents without issuing new ones. Partial load/transform/context loss is visibly failed with retry reads; no falsely applied result. Updating UI toggles alone does not establish actual overlay transform. Source-byte/hash checks before/after must demonstrate immutability.
