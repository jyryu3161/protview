- 명세 이름과 저장 이름이 다르거나 파생이 필요한 곳(구현 조건, 멈춤 아님) — 아래 (b) 표의 ★:
  ★1 M17 후보 `origins`에는 종류 필드가 없다. `generation_kinds`(`fixed_replace`·`user_rule`)는 저장 값이 아니라

     `rules_used[].method` = `replace_single_bond_v1` / `user_reaction_smarts_v1`).
  ★2 `generation_order`는 저장 필드가 아니라 저장 배열 위치다(ligand_filters.query_candidates 정의와 같음). id 문자열 순서와

  ★3 M20 위치 `sources`는 이름 목록이 아니라 객체 목록 `{kind, pocket_rank}`·`{kind, radius_A}`·`{kind:"user"}`이다. 와이어
     `sources`(닫힌 이름)는 `kind`에서 만들고, 포켓 순위가 여럿이면 `pocket` 하나로 합쳐야 한다(순위 값은 와이어에 없음).
  ★4 `protection_checks.<검사>`는 문자열이 아니라 객체(상태 + 개수·threshold·handle·이름표)이다. 와이어는 `.status`만.
     `pockets`에는 `pocket_set` handle이 들어 있어 와이어에서 빼야 한다.
  ★5 부모 정규 SMILES·속성은 집합 필수 필드(`parent_canonical_smiles`·`parent_properties`)이고 검증이 점검 객체와 같은지까지
     본다. 명세의 "없으면 점검 객체에서, 그래도 없으면 smiles 빼기"는 유효한 집합에서는 도달하지 않는 경로다.
  ★6 `property_methods`의 서버 검증은 "1–200자 문자열"뿐이다. 실제 저장 값 8개(아래 (b))의 문자 집합은
     ` (),-.2=A-Za-z^`, 최대 48자 → T2 패턴 후보 `[A-Za-z0-9 (),.=^_-]{1,200}` 또는 관측 8문자열 정확 일치.
- 주의(구현 조건 C1–C8, 아래 각 항목에 근거):
  C1 예약식 여유: M8 실호출 3건(커밋된 증거)에서 JSON 본문 ≈2.24–2.25 B/입력 토큰. 같은 바이트면 예약식
     `4096 + ceil(bytes/2)`는 보고 사용량보다 31–32% 크다(뷰어형 JSON 기준). SMILES 밀도가 높은 리간드 본문의 비율은 재지
     못했다. 사용량이 예약을 넘으면 기존 규칙대로 그 run의 모든 온라인 전송(뷰어 포함)이 `budget_exhausted`로 멈춘다.
     T10 첫 실호출에서 확인하고 상수만 고치는 명세 경로 그대로 두되, 리간드 본문 첫 호출의 사용량/바이트를 꼭 기록할 것.
  C2 async 전송이 run 실행 잠금(`_mutation`)을 HTTP 동안 잡으므로 같은 run의 다른 `_mutation` 사용자는 503 busy다(실측).
     → `/jev/sends`는 `_mutation` 전에 `ACTIVE_SENDS`를 보고 409, `/jev/preview`·`/jev/status`는 잠금 없이 읽고,
     `/jev/consent`는 `set_online`처럼 `_transition()`만 써야 한다. 전송 중 `build_jev_projection`(Run.call)은 503.
  C3 전송 중 `run.cancelled`(메모리 플래그)는 갱신되지 않는다(실측 False). 늦음·취소 판정은 이벤트(또는 `cancel.request`
     파일)로 해야 한다(명세 "이벤트 순서만으로"와 일치).
  C4 `_reconcile_egress`는 "보내지 않음"을 `dispatch_skipped` 감사 또는 `delta.expensive_calls == -1`로 안다. 과학 환불에는
     비싼 계산 축이 없으므로 `dispatch_skipped` 감사만 표지다. 음수 정산 뒤·`dispatch_skipped` 전 충돌이면 재시작 때
     `wall_charged`(egress, 남은 시간 상한) 하나가 더 붙는다(usage_unknown은 아님, 실측). 순서를 뒤집으면(감사 먼저) 그 틈의
     충돌이 미정산 예약 → usage_unknown이 되므로 뷰어와 같은 "정산 → 감사" 순서를 유지할 것. 오케스트레이터 수정 불필요.
  C5 예약 이벤트에는 `external_tokens`·`usd` 둘 다 있어야 한다(`_settle_egress`가 `reservation[axis]`로 읽음, 없으면 KeyError).
  C6 증액 AST 테스트 셋은 mw 아래 모든 .py의 **본문 문자열**에서 "raise_limits"·"limit_approval"을 찾아 파일 집합을 고정한다.
     새 M24 모듈은 주석에서도 이 두 문자열을 쓰면 안 된다.
  C7 `EventLog.append`는 매번 로그 전체를 다시 읽는다. 50 MB 로그에서 append 0.09 s, `_mutation` 진입·종료 0.54 s
     → 전송 한 번(이벤트 약 10개 + 객체 1개)에 이벤트 루프를 약 1.5 s 막는다(뷰어 전송과 같은 성질).
  C8 경계·수치: NumPy 최소거리와 `math.dist`는 비트가 19% 쌍에서 다르다(최대 7.1e-15 Å). 포함 여부는 전부 같고 5.0 Å
     경계까지 최소 여유 0.00126 Å. 거리 비교 테스트는 허용 오차(≤1e-9)로 할 것.
