# M8 — actual prompt-to-agent-to-viewer contract

Design/review: GPT-6 Astra. Implementation: GPT-6 Sol. Date: 2026-09-25. Baseline: accepted M7 commit `e0abffc`; real new branch `phase/m8-agent-viewer`. This is authorized implementation scope, not a claim of working behavior or a request for another planning approval. Existing M0–M7 scientific contracts and immutable reports remain authoritative. Current extension review must explicitly supersede changed shared-source coverage; historical gate hashes are not implicitly current.

## 1. What must work

A user can enter a natural-language viewer request, explicitly enable online interpretation, have the actual pinned model choose a bounded viewer plan, and see the requested representation/selection/camera change in the actual local Mol* scene. The application records the model decision separately from the browser's actual application acknowledgment. Merely displaying a suggested command or changing React state is insufficient.

Selected actions are representation (`cartoon`, `ball-and-stick`, `surface`), exact residue or ligand selection/focus, clear selection, zoom in/out and reset camera. Compound requests may change one representation, one selection and one camera operation in a fixed order. No arbitrary JS, shell, files, URLs, remote structure downloads, model-selected tool names, scientific computation, report generation, job submission/approval or automatic expensive job launch is enabled by this planner. Requests outside the viewer scope produce a visible unsupported/clarification result. Model text is not used as a scientific claim.

Manual controls remain fully local. New runs remain `local_only`; dry-run never sends or applies a model action. Provide an explicit local command path (for example `/representation surface`, `/focus <catalog target>`, `/clear`, `/zoom in`, `/zoom out`, `/reset`), labeled `source=local_command`. A natural-language request must not be silently labeled model-assisted when only a regex or rule ran. Offline text entry explains available local commands and the optional online path. Online failures do not invent a successful model result or silently execute a different natural-language guess.

## 2. Why the existing adapter is insufficient

`mw.llm.openrouter.decide_inspection_view` currently selects one of four table views from numeric aggregates. The public API has no viewer-agent route, and the current MolstarViewer has no general acknowledged command interface. The registry's old L1 snapshot placeholder is not an implemented capability. M8 adds an explicit viewer-intent adapter and browser command bridge; it must not advertise every scaffold tool as available.

Retain the verified Decisions endpoint `POST https://openrouter.ai/api/alpha/decisions`, request pin `typesafe/jev-1.13`, and permitted served snapshot `typesafe/jev-1.13-20260917`. No blind latest-model change or chat-completions conversion. Official [request/response schemas](https://github.com/OpenRouterTeam/ai-sdk-provider/blob/main/src/evaluation/schemas.ts) and [evaluation types](https://github.com/OpenRouterTeam/ai-sdk-provider/blob/main/src/evaluation/types.ts), rechecked 2026-09-25, support shared state and multiple named choice questions with named criteria. Wire usage remains input_tokens/output_tokens/cost. Preserve the stricter existing response-model requirement, privacy routing policy, bounded response and usage settlement. The API is alpha; fixtures and actual bounded live proof are both required.

## 3. Local scene session and exact target catalog

Create a local viewer session bound to `(run_id, client_instance_id, viewer_session_id, scene_generation, structure_handle)`. A fresh browser mount gets a new unpredictable client/session identity; each displayed structure/model/history/minimized-source change increments generation. Server validates the supplied same-run immutable handle kind/schema and obtains the model and residues from the actual local bytes. Allowed sources are implemented structure selection, prepared structure and validated OpenMM minimized structure. Never infer the target from latest pipeline handles when the display is historical or minimized.

The server stores a catalog hash and mapping from generated aliases `t0001`… to complete local `ResidueRef` identities. Full model/auth/label/icode/resname identity stays authoritative locally. Same author numbering in different models, chains, insertion codes or label IDs must not merge. Resolve focus against the actual loaded Mol* structure and reject empty/multiple unintended matches. A ligand name alone must not pick the first instance. The local UI can select a target from the catalog before a prompt; this also makes unusual identifiers usable.

The model-facing catalog has at most256 targets and a total request body at most64KiB. For larger structures, require the user's explicit local scope/target filter rather than silently claiming a partial catalog is complete. Representation/zoom/reset remain usable with an empty or explicitly scoped catalog. A minimal scope selector by exact local chain or selected residue/ligand is sufficient; no search index service is needed. Each exported target contains only generated alias, category, model number, author chain/number/insertion code and optional label chain/number. Source-derived string identifiers are exported only under a short reviewed ASCII identifier grammar (e.g. letters/digits/_/- and at most16 characters); otherwise export only alias/category and require explicit local target selection. Never export ordered amino-acid/residue names, sequences, atom names, ligand names, file names or arbitrary metadata. The local display may show complete identities without putting them into egress.

A missing/not-ready WebGL scene can receive a local explanation but cannot acknowledge an applied command. A scene session is an application context, not proof that the browser rendered it.

## 4. Deliberate new egress surface

M3's `EgressInspectionStateV1` remains unchanged and strict. Add a separate `EgressViewerIntentV1` and gate entry point. Unlike the aggregate-only M3 decision, M8 explicitly allows **the text the user types for this viewer request**, plus the safe catalog above. This scoped change follows the user's request for actual prompt control. The UI must state that the entered prompt and the displayed limited identifier catalog go to OpenRouter; coordinates, source files, sequences, paths, local handles and prior conversation do not. Show the exact projection or a faithful payload preview before/alongside sending. Do not present a generic keyword sanitizer as a guarantee that arbitrary user-typed text cannot contain sensitive material.

Outbound fields are fixed: schema=`viewer_intent@1`, prompt (1–512 Unicode characters, at most2048 UTF-8 bytes, no NUL/control characters other than normal whitespace), representation enum, selected target alias or null, scope-complete flag, and the strict catalog. Reject unknown fields and invalid numeric/string bounds. The server constructs all fields except the explicitly entered prompt from validated local state; the browser cannot submit arbitrary state/questions/provider/destination/headers. No raw goal/context/history, source summaries, run IDs, handles, camera coordinates, atom coordinates or filesystem content is interpolated. The server never reads a path or credential mentioned in the prompt. Prompt instructions attempting to override the application cannot expand the command allowlist.

Keep the server's existing environment/root-dotenv credential resolver. Keys never enter browser configuration, localStorage, request bodies, logs, events, errors, screenshots or model state. Do not add a browser key field. Do not read the key during design/review. Metadata from unrecognized model IDs/errors remains sanitized under M3 rules.

## 5. Mode and scoped consent

Provide explicit online enable/disable controls for the current run with an accurate mode badge. Enabling records a reviewed fixed policy and **viewer-model-only consent**, including a small request cap; it does not approve OpenMM or set the global expensive-calculation approval bit. Keep `expensive_first_call` for scientific jobs unchanged. The viewer gate accepts its separate persisted consent, and still charges the existing run budget for each physical outbound attempt. Refactor shared gate internals as needed; do not introduce a second independent network owner or loosen the existing inspection-view approval path.

A bounded `run_egress_changed`/viewer-consent event (or equivalent event-backed record) may update effective mode without rewriting `run_started`. Reopen reconstructs the latest valid effective mode and fixed policy; new runs are still local. Configuration changes are strict enums, not arbitrary pins/endpoints. Disable must immediately invalidate pending viewer requests and prevent future dispatch without waiting on a long egress owner; a current physical request remains honestly accounted. Dry-run cannot be promoted by the viewer route. Show missing credential/config/provider capability as unavailable, never switch mode merely because a key exists.

Selected defaults: at most4 viewer-model physical requests per run/consent allocation; a request reserves1 expensive unit,16384 external tokens and$0.05, constrained by existing remaining run limits. A grant cannot reset the already-consumed cumulative counter by toggling online off/on. No automatic retry, hidden second model or background loop. A manual retry is a new explicit intent and requires remaining consent and budget. Existing unknown-usage and overrun stop behavior remains in force. M8 live QA uses at most4 physical model requests in its dedicated QA run and at most$0.20 reservation capacity; deterministic error/race tests use injected transport fixtures. Exhausting the cap is a visible outcome, not permission to open another run silently for more tests.

## 6. Model questions and bounded compiler

Use one real model request with four named choice questions under a versioned checked-in instruction set:

| Question | Allowed choices |
| --- | --- |
| disposition | apply, clarify, unsupported |
| representation | keep, cartoon, ball_and_stick, surface |
| selection | keep, clear, and aliases from the exact exported catalog |
| camera | keep, focus_selected, zoom_in, zoom_out, reset |

Instructions are application constants. Dynamic selection criteria are generated only from catalog aliases and safe fields; no source/user text becomes system instructions. The model is told to choose clarify for an ambiguous target, unsupported for non-viewer/scientific/file/execution requests, and keep for unspecified axes. Reset camera and clearing selection are distinct. At most one value per axis is supported; contradictory requests must not invent an unbounded sequence.

Validate every required answer's `type=choice`, exact allowed choice and permitted served model before compiling. Missing/extra unexpected answer IDs, invalid target, malformed probabilities/confidence, nonfinite usage or response shape yield typed rejection; independently valid usage still settles even if the plan is rejected. A selected target must resolve through this scene's immutable catalog; the model never emits a raw handle or ResidueRef. If disposition is not apply, return no commands. focus_selected requires a new valid target or the scene's actual selected target; clear plus focus_selected is invalid. A keep-only apply yields no_change, not fabricated application.

Compile at most3 typed commands in order representation → selection → camera. Each command has locally generated command_id, intent_id, session/generation, structure handle, catalog hash and schema version. Payloads are a finite enum plus resolved local target; zoom factors are fixed bounded1.25/0.8 semantics, not model-provided arbitrary numbers. Runtime capabilities control which commands are offered. A model cannot reach registry Run.call or job APIs through this compiler.

## 7. API, cancellation and durable intent lifecycle

Suggested routes (names may be adapted consistently):

- POST `/runs/{id}/viewer/sessions`: validate displayed handle/model and create a catalog/session.
- POST `/runs/{id}/viewer/online`: strict enable/disable + viewer-scoped consent/cap, with accurate effective mode response.
- POST `/runs/{id}/viewer/intents`: prompt, exact scene/session/generation and client request UUID only; returns a stored typed plan/outcome. Offline explicit commands use the same local compiler with source=local_command.
- GET intent/list endpoints: safe local history and status; no new model request on read.
- POST `/viewer/intents/{intent_id}/cancel`: cancel only this known intent; it must not cancel unrelated jobs or silently revoke their approvals.
- POST `/viewer/intents/{intent_id}/ack`: bounded per-command browser outcome tied to the exact issued plan/session; no arbitrary event append API.

Suggested data modules: a small viewer-intent service/compiler, strict egress projection/adapter and frontend command bridge. Keep this distinct from scientific tools and reports. The renderer exposes legitimate read-only readiness/current source/session/representation/selection/command status data attributes or a bounded test-observation bridge reflecting actual Mol* state. A debug bridge cannot manufacture application success, bypass the typed executor or inject a model answer into the production path. Intent states distinguish requested, interpreting, planned, applying, applied, partial, no_change, clarification, unsupported, rejected, cancelled, failed and detached/unacknowledged. They may be represented by fewer typed fields if these meanings remain distinguishable. Persist prompt/projection hash, policy/question version, requested/served model, audit link, exact local target mapping, issued commands and each acknowledgment. Browser acknowledgments are client-reported execution evidence, not independently observed scientific truth; actual offscreen QA verifies Mol* behavior.

The same client request UUID plus identical canonical payload is idempotent and never sends again; conflicting reuse is409. Persist the intent before dispatch. A reload restores its history but never automatically resends a model call or replays an unacknowledged command. Unknown delivery/usage or missing browser ack remains unknown/detached, not applied. Saved scientific reports retain exact bytes and are not re-rendered merely because viewer events were appended.

Cancellation must be effective while the egress owner is busy: use an intent-scoped durable flag/event through a short transition guard, not the long execution lock. Recheck before credential use, reservation and dispatch; monitor it inside the owned async HTTP operation and close/cancel the request scope without a detached credential-bearing thread. Keep the existing total deadline and sent=false/unknown/true distinctions and response/usage settlement/recovery. Do not equate AbortController or HTTP disconnect with proven provider cancellation. If already sent, retain the charge/unknown usage as appropriate. Cancel or mode-revoke must also suppress a late successful response and unapplied browser commands. No automatic replay on crash/reopen.

## 8. Actual Mol* application, not state-only success

Expose a narrow bridge on the live viewer instance. It serializes commands, validates session/generation/source identity immediately before and after each awaited Mol* operation, and produces one final ack per command. Run switch, model/history change, new upload, minimized/original transition, component unmount or newer cancelling intent invalidates old work. A manual conflicting camera/selection/representation action increments the viewer action revision so a delayed model plan cannot overwrite newer user intent.

Representation acknowledgment follows the actual representation commit, not setState. Selection/focus validates a nonempty exact-model/full-residue loci and confirms the selection/camera operation. Clear removes both Mol* selection and the local highlight/legend. Zoom/reset must operate on the actual camera and check finite observed state, direction/target or no_change; do not fabricate a camera change when at a limit. Read-only before/after camera/selection/representation state may be stored locally for QA, never sent to the provider. Success toast/agent transcript says applied only after acknowledgment; partial batches list applied vs rejected commands and never falsely claim atomic rollback. Command timeout or WebGL error has a visible retry/manual path.

Manual representation/focus controls may share the bridge to avoid divergent semantics. New zoom/reset/clear controls must also work without online mode. Historical structures and minimized proteins are legitimate viewer targets with their exact identities; original complex contact rows must remain hidden/disabled on minimized coordinates. Fix the known generic minimized-view legend to explicitly identify the OpenMM minimized protein.

## 9. Required acceptance evidence

Tests must cover strict projection, typed compiler, scoped consent (no accidental job approval), offline/dry no transport even with credentials, fixed endpoint/pin/served mapping, per-run cumulative cap, request-id idempotence, total deadline/cancel/revoke, usage on rejected responses, crash recovery, exact alias binding, injection attempts, unavailable/no-op outcomes, malformed/stale/duplicate acknowledgments and no application after run/scene/manual-intent changes. Keep all existing M3/M4 scientific/accounting tests meaningful; injected transports cannot be selected through production API fields.

Root owns **actual offscreen rendering** click QA, with the full inventory in `M8_OFFSCREEN_QA_PLAN.md`. Orca hidden/background tabs did not expose a verifiable offscreen setting, so the selected QA host is a separate Sol-owned Electron BrowserWindow with `show:false` and `webPreferences.offscreen:true`. Record `webContents.isOffscreen()===true`, exact Electron version, window visibility and real paint output. Retain hardware acceleration/WebGL; disabling GPU to satisfy bitmap capture would invalidate Mol* coverage. Playwright may drive that actual Electron renderer through CDP for mouse/key/upload/screenshot actions; it may not silently substitute its own headless Chromium page. See the official [Electron offscreen rendering guide](https://www.electronjs.org/docs/latest/tutorial/offscreen-rendering). All production controls are exercised individually with actual input and observed outcome; unavailable/disabled controls are checked as such. Failing functions are corrected by Sol and retested. Do not call planned UI clicks completed tests.

Actual bounded online proof uses the production API/gate/pin and harmless viewer prompts on a local public structure. Suggested three compound prompts cover surface+exact residue focus, ball-and-stick+exact ligand focus, and cartoon+clear+reset; reserve the fourth for zoom-out or one explicit unsupported request if needed. Confirm provider served ID/usage, issued typed commands, actual Mol* acknowledgment and changed pixels/camera/selection. Capture no key/header/raw provider error. Model quality is not benchmarked; if the actual model chooses an unusable action, report it and correct the adapter within the cap rather than replacing the live answer with fixture output. All other cancellation/race/failure cases use labeled fixture responses. No extra scientific ranking, agent chat history service, screenshot tool, arbitrary tool orchestration or cloud execution is selected.
