Synthetic PDB fixtures are explicitly labeled algorithm and identity tests, never experimental data. A known rigid transform and a reflection are setup coordinates, not backend fit outputs. Read-only API inspection supplies durable handles and source bytes; product mutations use visible Electron actions except an explicitly labeled API fault/invalid-input fixture when no visible control can express that malformed payload. Native read-only QA projection must expose source-specific original atom coordinates, per-layer world transform/visibility and exact picked site identity; screenshots alone do not prove geometry. Do not use a React mock or fabricated application success. Save immutable failure rows and rerun in a new artifact directory after any fix.

Numerical fits and distances use the ordinary guarded `Run.call` lane. Use separate labeled local-only runs for independent invalid-input/fit matrices when repeat/no-progress/budget guards would otherwise intervene; record actual attempts and cache outcomes. Do not raise or bypass guards to force success. Reopen and result/report reads must issue no new scientific call. Seeded prior M9 runs supply prepared/minimized native identity and historical report-byte baselines, not newly clicked M10 computation evidence.

The planned native-picking source matrix is: a sparse synthetic distance PDB with separately clickable 3–4–5 endpoints and two deliberately coincident sites; synthetic original PDB with CA altloc A/B; synthetic identity PDB with two models, insertion A and duplicate CA/A sites; synthetic mmCIF with near-degenerate CA geometry; actual locally supplied 1HSG mmCIF original and prepared handles; and the previously completed real OpenMM minimized handle from preserved local events. On each supported source, use a real pointer pick and reconcile native loci against the server atom catalog. A duplicate/ambiguous native mapping must report ambiguity rather than choosing the first matching name. These are distinct cases; a synthetic fixture pass cannot stand in for real mmCIF, prepared, or minimized observations. Coincident sites may be impossible to distinguish by a pointer hit; use a labeled exact-site API fixture and real result reopen if so, while proving the ordinary two-click path with separate 5 Å endpoints. The parent will supply isolated same-run fixtures/events and their actual handles before execution.

The concrete Electron script is `frontend/tests/offscreen/comparison-flow.cjs`. `measure`, `alignment`, `identity`, and `source-matrix` require independent artifact directories; `source-matrix` takes the seeded 1HSG `--run` and OpenMM `--other-run`. `adapter` takes the real sparse PDB `--run` from `measure` plus its exact original `--reference` source handle and uses visible history, local target `/focus`, `/clear`, M9 Save/Restore, and reload; it writes the selected scene handle for events-only replay. The supported local grammar has `/focus <alias>` and `/clear`, not `/select`. `catalog-race` takes an existing `--run`, holds its unchanged atom-catalog GET across a fresh page reload, and requires a native structure with atoms and `catalogReady=false` before releasing the response. This proves a late catalog after native readiness and disabled controls while pending. It does **not** force or prove the narrower startup interval where the catalog effect completes after the initial-catalog snapshot but before native instance assignment; controlled lifecycle tests cover that interval. `faults` needs an already persisted alignment `--run` and `--result`, with `--other-result` for the held same-run A→B lane and `--other-run` for the held-detail run-switch lane. Its 503 and malformed response are labeled renderer route fixtures; its context-loss case uses the live canvas's `WEBGL_lose_context`. `replay` requires an events-only backend root prepared by the parent plus existing `--run`, `--result`, and `--report` handles, and rejects new scientific/report POSTs while exercising actual saved-result and browser download controls. The script copies its exact source bytes and SHA-256 into every artifact directory. The executed eleventh-build cases, prior retained failures, and completed replay are mapped below; final Astra review and phase recording remain separate. `overlay` and `regression` are reserved fail-closed modes until implemented.
