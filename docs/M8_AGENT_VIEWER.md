# M8 viewer request implementation

M8 adds a viewer-only interpretation path to the existing local structure workspace. New runs remain `local_only`. No prompt, catalog, or structure is sent merely by loading the page or choosing a run. The user explicitly enables **온라인 해석 허용** for that run before a natural-language viewer prompt can be sent. This consent is separate from OpenMM/scientific job approval. Dry-run cannot enable it. The UI shows the current run's mode, used/remaining four-request cap, exact fixed outbound `state` projection, and local command help.

The prompt panel is at the top of the workflow strip so it remains available while the inspector scrolls through measurement rows. Local commands `/representation cartoon|ball-and-stick|surface`, `/focus tNNNN`, `/clear`, `/zoom in`, `/zoom out`, and `/reset` work in offline mode and use no model call. The nearby target selector submits an exact alias focus. A structure or selected chain with more than 256 targets gets an empty catalog and `scope_complete=false`; representation and camera commands remain available. The user can explicitly narrow by chain or an exact residue to enable focus. The full target identity stays local. The model projection omits coordinates, sequence, atom/residue names, raw handles and source paths. User-entered prompt text is sent as typed, so the UI makes that explicit rather than claiming to sanitize arbitrary text.

The OpenMM submit control separately recognizes a typed `plan_only` response on a dry-run. It displays that the plan was returned without creating a job or using computation/budget, and clears that local notice when the run, input, job, or reopened context changes. This notice describes the returned plan rather than a completed minimization.

The backend creates a viewer session from an actual same-run structure, prepared structure, or validated minimized structure. It stores the exact source handle, client/session/generation, alias-to-`ResidueRef` map, catalog hash, and action revision in events. The model-facing catalog includes only short validated identifiers; unsafe source identifiers become alias/category only and require local selection before model targeting. Every accepted model reply is compiled to at most three typed commands in representation → selection → camera order. The compiler cannot invoke scientific tools, jobs, reports, shell, files, or arbitrary viewer code.

The online adapter uses the shared `EgressGate`, pinned Decisions request `typesafe/jev-1.13`, permitted served snapshot `typesafe/jev-1.13-20260917`, fixed provider routing policy, a four-physical-attempt run cap, and the existing run budget. Each attempt reserves one expensive call, 16,384 external tokens, and USD 0.05, then settles observed usage or retains unknown usage conservatively. The browser supplies a UUID before its POST starts. Stop records a scoped cancellation even if a delayed POST has not yet reached admission. The server checks cancellation, run cancellation, consent epoch, scene revision, and remaining deadline before dispatch and while the owned HTTP task runs. A repeated UUID with identical payload returns the stored result; a conflicting reuse fails. Reopen never automatically resends an intent or applies an unacknowledged command.

The browser bridge binds each command to its exact live session, generation, source handle, catalog hash, and revision. It serializes Mol* operations, checks WebGL readiness/context loss, resolves selection against the loaded structure, and reads actual committed representation, selection loci, and finite camera state before acknowledging. A direct canvas click selects one residue; another click replaces it, including with modifier keys, and a blank click clears it. This also works while a scientific command is busy and when minimized coordinates are displayed. Programmatic focus suppresses intermediate selection notifications. Manual pointer/wheel actions invalidate a pending plan immediately; state POSTs for one session are then sent in order while the backend's strict revision check remains active. A superseded queued update cannot overwrite the latest scene, and a failure of the latest update remains visible. Applied status is recorded only after the browser reports an actual Mol* operation; those acknowledgments remain client-reported evidence, and offscreen QA independently checks the instance. `window.__protviewQaSnapshot()` is a read-only local observation surface returning readiness, source/session/generation, committed representation label, actual selected residue, actual camera position/target/radius/distance, and last command acknowledgment. It accepts no command or provider answer.

Relevant API routes are `POST /runs/{id}/viewer/sessions`, `GET /runs/{id}/viewer/sessions/{session_id}`, `POST /runs/{id}/viewer/sessions/{session_id}/state`, `GET|POST /runs/{id}/viewer/online`, `GET|POST /runs/{id}/viewer/intents`, `GET /runs/{id}/viewer/intents/{intent_id}`, `POST /runs/{id}/viewer/intents/{intent_id}/cancel`, and `POST /runs/{id}/viewer/intents/{intent_id}/ack`. The cancel body can scope a not-yet-admitted UUID to the current client/session/generation; after admission it also verifies any provided scope.

The checked-in viewer selection question is `viewer_questions@2`. Its instructions state that `selected_target` is the existing scene context, that an explicit English or Korean deselection request means `clear`, and that a catalog alias means a newly requested exact target. The compiler still executes the returned choice as given; it does not rewrite a model answer based on prompt words. This version change followed an actual third live call in which the earlier question caused the model to reselect the current target for a Korean clear request. That semantic failure is preserved in [the QA archive](qa/m8/raw/live-v1-semantic-failure.json). The fourth and final bounded call with the same Korean request and version 2 produced cartoon, clear, and reset commands, each acknowledged against Mol*, as recorded in [the version 2 result](qa/m8/raw/live-v2.json). The dedicated live run consumed all four permitted physical requests; no additional live model calls are needed for that run.

Deterministic error and race QA uses a separate loopback fixture API and `httpx.MockTransport`, never the provider. The [final hidden GPU Electron fixture run](qa/m8/raw/agent-adversarial-final.jsonl) recorded 24 passing A01/A02 and A09–A19 rows, including native Mol* representation and selection after Stop, a manual-action race, lost ACK response, preservation of a prior selection before command application, and a subsequent working local command. A partially applied command remains cancelled or detached with **zero server ACKs**; the toolbar and next outbound projection are reconciled from the guarded actual Mol* snapshot, without inventing a successful ACK. The separate [source-transition evidence](qa/m8/raw/agent-source-transitions.jsonl) covers history/raw, loaded models, a busy-denied model load followed by successful retry, and an actual completed OpenMM minimized source. [Direct canvas QA](qa/m8/raw/canvas-pick-final.jsonl) confirms rapid residue replacement and blank clear against native selection, visible controls, and server projection without a revision alert. Fixture responses establish lifecycle behavior, not model quality. The runner and isolation instructions are in [the fixture README](../backend/tests/offscreen_agent_fixture/README.md); the broader real-input results and preserved evidence are in [M8 QA results](M8_QA_RESULTS.md) and [the archive manifest](qa/m8/archive.json). Existing scientific reports and M3 inspection-decision schema remain unchanged by viewer intents. Phase completion and review remain with the root/Astra gate.
