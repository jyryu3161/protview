# M1 local API contract

Run the editable backend with `uvicorn mw.api.app:app --host 127.0.0.1 --port 8000`. The default run root is `./runs`; `MW_RUNS_DIR` may override it. The main workflow is `local_only`. All scientific commands use `POST /runs/{rid}/commands`; the API exposes only the implemented M1 tools.

## Workflow

1. `POST /runs` with `{"goal":"...","context":[],"dry_run":false,"egress":"local_only"}` returns 201 and `{"run_id","goal","context","dry_run","egress","last_seq"}`. `GET /runs` lists runs; `GET /runs/{rid}` reopens one from its event log. Run IDs are generated by the server.
2. `POST /runs/{rid}/uploads?filename=example.cif` with raw PDB/mmCIF bytes (`application/octet-stream`) returns 201 and `{"upload_id","sha256","size","format","n_models","model_numbers"}`. Maximum size is 25 MiB. The extension must be `.pdb`, `.cif`, or `.mmcif` and match parseable content. Uploads are immutable and scoped to the run. The original filename is not persisted.
   The server rejects a symlinked upload directory or upload file with a structured input error. Repeating an upload with identical bytes reuses the same upload ID; a conflicting regular file is rejected. `load_structure` consumes verified uploaded bytes without reopening the upload path.
3. `POST /runs/{rid}/commands` with `{"tool":"load_structure","args":{"source":"upload://<rid>/<sha256>.cif","model_index":0},"decided_by":"human"}` returns `{"ok":true,"handle":Handle}`. The HTTP surface accepts only this run's `upload_id` as `source`; local paths and remote IDs are rejected. `model_index` is zero based.
4. Call `prepare_structure` with `{"structure":"obj://..."}`; optional policies are `altloc: highest_occupancy|first`, `waters: keep_all|strip_all`, `hydrogens: strip|keep`, `missing_residues: leave_gaps`, and `symmetry_mates: ignore`. The returned `prepared_structure` summary includes coordinate and preparation-manifest handles.
   Handle inputs are scalar unless the tool contract explicitly declares a collection. `compile_state.inputs` is a list of handles; passing a list to `prepare_structure.structure` or a scalar to `compile_state.inputs` returns HTTP 422 before tool execution.
5. `GET /runs/{rid}/structures/residues?handle=<prepared-handle>` returns `{"model_number","residues":[...],"ligands":[...]}`. Each residue has `model_number, chain_auth, chain_label, seq_auth, seq_label, icode, resname, atom_count, category`. Each ligand selector has the identity fields without atom count/category. Label IDs may be null. Use one returned ligand identity in `compute_interactions`.
6. Call `compute_interactions` with `{"structure":"obj://...","ligand":{"model_number":1,"chain_auth":"B","seq_auth":902,"icode":"","resname":"MK1","chain_label":"C","seq_label":null},"cutoff_A":4.0,"types":["contact","polar_contact","hydrophobic_contact"],"engine":"geometric"}`. Omit `ligand` only when exactly one candidate exists. Duplicate residue names never select or merge implicitly. `cutoff_A` is 2.5–6.0 Å. Empty measured results return `ok:true`, `null_result:true`, and zero rows.

`Handle` is `{"handle":"obj://<rid>/<kind>/<sha256>","kind","schema","summary","preview","produced_by","null_result"}`. Preview contains at most five measured rows. An interaction object is immutable content `{"structure","selection":{"ligand":ResidueRef},"parameters":{"cutoff_A","types"},"method":{"name","version","unit","limitations"},"rows":[...]}`. Its identity therefore changes with the prepared input, selected ligand, cutoff, requested types, method, or measured rows. The method is heavy atom distance in angstroms; types are geometric labels, not validated hydrogen bonds or energy.

`load_structure` summary field `chains_auth` is the order-preserving set of author chain IDs. Gemmi may represent one author chain in multiple segments; `n_residues` still counts all segments. The changed summary uses tool version `0.1.1` and `structure_selection@2`, so existing `structure_selection@1` objects and metadata remain immutable. The source object remains identified by its original bytes.

## Reads

| Endpoint | Response |
| --- | --- |
| `GET /capabilities` | `mode`, `supported`, and specific `unavailable` reasons |
| `GET /tools?levels=L2,L4` | Implemented M1 tool specs only |
| `GET /runs/{rid}/objects/meta?handle=...` | Handle metadata: handle, kind, schema, fmt, size, produced_by, summary, null_result |
| `GET /runs/{rid}/objects?handle=...&offset=0&limit=50&columns=residue,distance_A` | `{"meta","rows","total","offset","limit"}`; interaction envelope rows are unwrapped, projected, and paginated; limit 1–100 |
| `GET /runs/{rid}/structures/bytes?handle=...` | Selected structure or prepared coordinate bytes; `X-Structure-Format: pdb|cif`, local Mol* input |
| `GET /runs/{rid}/events?after=0&limit=200` | Ordered events after sequence; maximum page 500; object payload bytes are omitted from this UI view |
| `GET /runs/{rid}/budget` | Per-axis `{"used","limit"}`; M1 tools are cheap |

Unknown or foreign handles return 404 on reads or an `input_invalid` tool error. Invalid selection, parameters, columns, pages, uploads, and tools return structured 4xx responses. Tool errors have `{"ok":false,"error","message","fix","detail"}`; other HTTP errors use FastAPI `{"detail":{"error","message"}}`. Unsupported energy, job, report, remote lookup, and model paths are listed in capabilities and are not exposed as M1 commands.
