# M11 local chemical-interaction API, version 1

This is the bounded frontend/backend contract for the selected prepared-input lane. It describes endpoints to implement, not a claim that the M11 gate has passed. Every handle belongs to one run. All coordinates are Å in one supplied frame; neither import mode aligns, protonates, optimizes, or fetches a structure. Existing M8–M10 source selectors and report schemas are unchanged.

## Immutable input and inspection

`POST /runs/{rid}/chemical/imports?kind=receptor|ligand_sdf|receptor_bonds&filename=...` takes raw bytes (`Content-Type: application/octet-stream`, at most 10 MiB). It returns `201`:

```json
{"schema":"chemical_raw_input@1","handle":"obj://run_x/chemical_raw_input/<sha>","kind":"ligand_sdf","format":"sdf","sha256":"<64 hex>","size":1234}
```

The three kinds are separate immutable, events-replayable objects. Receptor format is PDB or mmCIF; the selected ligand parser accepts bounded **V2000 SDF** records only. V3000 is rejected with a typed malformed-input error. Connectivity sidecar is UTF-8 `receptor_bonds@1` JSON. The sidecar has `source_handle` (for attach) or `receptor_input_handle` plus `model_number` (for create-new), `complete: true`, and `bonds:[{"first":<complete source or staging atom ref>,"second":<complete source or staging atom ref>}]`. In create-new mode these are **M11 `chemical_staging_atom_ref@1` values**: they have the same complete field shape as M10 AtomRef, but `structure_handle` is the immutable receptor raw-input handle and resolution is restricted to the M11 raw-input/model atom inventory. They do not make raw inputs eligible for M10 measurement, M8 sessions, or any existing source allowlist. PDB CONECT can be chosen instead of a sidecar only when its serials are unique and complete. Reciprocal records describe one bond. Self, dangling, cross-source, and ambiguous bonds fail.

`GET /runs/{rid}/chemical/imports/inspect?handle=...` returns raw kind/hash and bounded source inventory: receptor `model_numbers`, residue/atom/H/water counts and connectivity status; or SDF `records:[{"index":0,"title":"...","atom_count":...,"heavy_atom_count":...,"hydrogen_count":...,"has_3d":true}]`. It does not run chemistry inference. At most 100 SDF records and 256 atoms in the selected ligand are accepted; errors name the exact unsupported record. Import bytes and record/model selection are separate.

`GET /runs/{rid}/chemical/imports/atoms?handle=...&model_number=1&offset=0&limit=1000` returns `{schema:"chemical_staging_atom_page@1",input_handle,model_number,total,offset,limit,rows:[{"ref":<complete chemical_staging_atom_ref@1>,"coordinate_A":[x,y,z],"element":"N","water":false}]}` with M11-only limit 1–1000 (default 100) against the existing 10,000-receptor-atom cap. Every page still validates the bounded immutable raw bytes, same-run input kind and chosen model. It is the authoritative paginated staging inventory for receptor sidecar authoring; source/site identifiers are stable across preview and preparation. It never yields an M10 atom catalog or a renderable source.

`POST /runs/{rid}/chemical/preview` accepts either discriminated preparation request below, with one deliberate relaxation: `mapping` may be absent or partial in attach mode, and acknowledgement flags may be false. It performs bounded read-only syntax, identity, model, atom-count, mapping and connectivity checks. It returns `200` with `schema:"chemical_preparation_preview@1"`, `ready:boolean`, `blockers:[{"code":"...","message":"...","atoms":[<AtomRef>]}]`, `included_receptor_atoms`, `excluded_water_atoms`, `selected_ligand_atoms`, `ligand_atoms`, `ligand_mapping`, `mapping_proposals`, `terminal_extensions`, and `limitations`. `ligand_atoms` lists every selected SDF index, supplied name/map tag, element, H status and source coordinate. Each row has `name_generated:boolean`; if the SDF supplies no atom name, `atom_name` is a disclosed deterministic display/derived-source name such as `L1` and `name_generated:true`. Such a name is never treated as a supplied exact-name mapping proposal. `mapping_proposals` gives zero or more exact source AtomRefs and measured discrepancy per SDF index; ambiguous names or map tags have no proposal and have a blocker. `ligand_mapping` repeats only explicit submitted choices. `excluded_original_ligand_hydrogens` explicitly lists old H AtomRefs removed only by `replace_from_sdf`; `map_existing` requires a two-sided bijection over every old ligand atom and every selected SDF atom. SDF preview elements and new chemical AtomRefs use uppercase symbols, including `CL` and `BR`; `ligand_atoms` also carries the V2000 formal charge. A proposal is never submitted implicitly; the job requires a complete explicit mapping and true acknowledgement flags. `ready` means prerequisites for the durable conversion job, not validated inferred chemistry or a completed ProLIF result. Expensive native inference remains behind job approval. Valid preview syntax with missing mapping/acknowledgement produces actionable blockers rather than HTTP 422.

Every preview also returns `derived_coordinate_policy`: `new chemical source keeps receptor original coordinates and selected SDF conformer coordinates; attach requires <=0.002 A discrepancy and never aligns`. The immutable manifest repeats that exact value, while each attached site records its original coordinate and measured discrepancy. The abbreviated illustrative previews below omit this explanatory field.

The selected V2000 stereo policy accepts explicit tetrahedral atom parity only when its independently assigned R/S matches the selected same-index 3D conformer. Ambiguous parity, wiggly/crossed bond stereo and unsupported forms reject. For nonplanar 3D coordinates, wedge/dash bonds are depiction cues: [RDKit's documented molfile rule](https://www.rdkit.org/docs/RDKit_Book.html#interpretation-of-the-2d-3d-flag-and-stereochemistry) derives chirality from 3D and ignores wedge direction. The manifest stores this limited `stereochemistry_policy`; it does not claim independent E/Z validation or complete stereochemistry support.

## Prepare request: exactly one mode

Both `POST /runs/{rid}/chemical/preview` and `POST /runs/{rid}/jobs` use these validated `args` for `protocol_id:"prolif_prepare_v1"`.

Create a new chemical source from a prepared receptor and one selected SDF pose:

```json
{"protocol_id":"prolif_prepare_v1","args":{"schema":"chemical_prepare_request@1","mode":"create_new","receptor_input_handle":"obj://run_x/chemical_raw_input/<sha>","receptor_model_number":1,"connectivity":{"kind":"pdb_conect","sidecar_handle":null},"ligand_sdf_handle":"obj://run_x/chemical_raw_input/<sha>","sdf_record_index":0,"ligand_instance":{"model_number":1,"chain_auth":"L","chain_label":null,"seq_auth":1,"seq_label":null,"icode":"","resname":"LIG"},"terminal_extensions":[],"acknowledgement":{"schema":"chemical_preparation_ack@1","supplied_graph_complete":true,"supplied_hydrogens_complete":true,"use_supplied_protonation_tautomer":true,"infer_receptor_orders_charges":true,"description":"prepared locally","ph_annotation":null}},"timeout_s":120}
```

`connectivity.kind` is `pdb_conect` or `sidecar`; `sidecar_handle` is required only for `sidecar`. The ligand identity is the complete seven-field authoritative residue; its model must equal the selected receptor model and may not collide with a receptor residue. Missing SDF atom names are deterministically generated from zero-based SDF indices and disclosed in the manifest. Both modes also require `terminal_extensions:[{"residue":<complete seven-field residue>,"atom_names":["CAY","CY","OY"],"approve_supplied_graph":true}]` for every nonstandard merged terminal extension present; use `[]` when none. The `atom_names` may instead name additional existing atoms of one exact supported terminal protein residue. Each name resolves uniquely to a source AtomRef; the declared extension and attached H vertices must be connected and have exactly one supplied bond to that residue’s terminal N or C. Preview returns each extension row as `{residue,atom_names,declared,resolved_atoms,terminal_anchor,attachment_bonds,extension_bonds}`; bond endpoints are full AtomRefs. The manifest saves the same resolved inventory and bonds. CAY/CY/OY is a known declaration trigger, but HY1/HY2/HY3 names are not required when the three H vertices and graph are equivalent. Ambiguous/nonterminal declarations fail, and unfamiliar undeclared extensions cannot be exhaustively detected. Preview inventories unapproved extensions as blockers, and the job never silently removes or renames them.

Attach supplied SDF chemistry to one exact ligand instance in an existing prepared complex:

```json
{"protocol_id":"prolif_prepare_v1","args":{"schema":"chemical_prepare_request@1","mode":"attach_existing","complex_handle":"obj://run_x/prepared_structure/<sha>","complex_model_number":1,"selected_ligand":{"model_number":1,"chain_auth":"A","chain_label":"B","seq_auth":501,"seq_label":82,"icode":"","resname":"LIG"},"connectivity":{"kind":"sidecar","sidecar_handle":"obj://run_x/chemical_raw_input/<sha>"},"ligand_sdf_handle":"obj://run_x/chemical_raw_input/<sha>","sdf_record_index":0,"hydrogen_policy":"map_existing","mapping":[{"sdf_atom_index":0,"source_atom":{"structure_handle":"obj://run_x/prepared_structure/<sha>","residue":{"model_number":1,"chain_auth":"A","chain_label":"B","seq_auth":501,"seq_label":82,"icode":"","resname":"LIG"},"atom_name":"C1","altloc":"","element":"C","site_index":5012}}],"terminal_extensions":[],"acknowledgement":{"schema":"chemical_preparation_ack@1","supplied_graph_complete":true,"supplied_hydrogens_complete":true,"use_supplied_protonation_tautomer":true,"infer_receptor_orders_charges":true,"description":"prepared locally","ph_annotation":null}},"timeout_s":120}
```

`complex_handle` accepts only a same-run `(structure,structure_selection@2)` or `(prepared_structure,prepared_structure@1)` object with explicit prepared-input acknowledgement; the raw source's existing atom mapping remains immutable. `mapping` is a two-sided bijection: it covers every selected SDF heavy atom and every existing source ligand heavy site exactly once. `map_existing` additionally covers every SDF and existing ligand H site exactly once. `replace_from_sdf` maps all heavy sites, explicitly enumerates excluded old ligand H AtomRefs, and derives new H identities from the SDF. Every mapped element must agree and the coordinate difference must be ≤0.002 Å. The new chemical source uses the selected SDF conformer coordinates for the ligand and original source coordinates for the receptor; it never aligns a conformer. Preview shows each discrepancy, and the manifest/report save every original source coordinate, exact source AtomRef, discrepancy and this derived-coordinate policy. Mapped derived ligand AtomRefs preserve the original atom name, altloc and authoritative residue fields; null labels remain null. Any deterministic PVn mmCIF label is a served-view adapter only. New H is never assigned a nonexistent parent AtomRef. Additional nonprotein instances and receptor–ligand covalent bonds reject. Proposals use only exact unique supplied names or unique map tags, never nearest-coordinate or symmetry guesses; all ambiguous names remain unproposed. Every mapping is shown before submission.

In both modes, input is capped at receptor 10,000 atoms, ligand 256 atoms, 20,000 total bonds, 10 MiB per raw file. The full receptor is included; water is the only permitted counted exclusion. Unsupported metals, cofactors, alternate states, radicals, disconnected ligand, partial H and invalid inferred graph fail with typed, exact-identity diagnostics. The preview can be ready while the native conversion later rejects a chemistry inconsistency.

## Durable jobs and approval

`POST /runs/{rid}/jobs` for `prolif_prepare_v1` returns the existing public job shape with `job_id`, `protocol_id`, `status:"queued"`, `blocked_reason`, `attempt_ordinal`, and `output_handles`. The new `artifacts` map below is an additive M11 public-job field, not an existing field; budget remains separately read at `GET /runs/{rid}/budget`. `POST /runs/{rid}/jobs/{job_id}/start`, `/retry`, `/cancel`, `GET /runs/{rid}/jobs/{job_id}`, and `GET /runs/{rid}/jobs` retain existing semantics. A start without required approval returns HTTP 409 `{"ok":false,"approval":{"gate":"expensive_first_call","tool":"prepare_chemical_structure","reason":"..."}}`; `POST /runs/{rid}/jobs/approve` approves only an actual pending supported expensive job gate, never an arbitrary tool or request-chosen executor. A failed launched attempt consumes its reservation. Global job concurrency, guardian recovery, timeout and cancellation rules apply.

Successful preparation job `output_handles` are in fixed order `[preparation_manifest, chemical_structure, chemical_graph]`; the public job also has `artifacts` with those named handles. The immutable acyclic object links are raw imports/choices → `chemical_preparation_manifest@1` → `chemical_structure@1` → `chemical_graph@1`. The manifest maps stable derived local site IDs, not its own future handle. The graph expands each site into a complete derived AtomRef and records actual engine coordinate precision, supplied/inferred fields, all bonds, native index bijections, settings and warnings.

Fingerprint an existing complete graph in a separate job:

```json
{"protocol_id":"prolif_detect_v1","args":{"schema":"chemical_detect_request@1","graph_handle":"obj://run_x/chemical_graph/<sha>","categories":["HBDonor","HBAcceptor","Hydrophobic","Cationic","Anionic"]},"timeout_s":120}
```

The category array must equal the fixed version-1 allowlist; clients cannot pass SMARTS, cutoffs, executable paths or callbacks. `prolif_detect_v1` uses the same approval/reservation lane with tool `compute_chemical_interactions`; its sole output/artifact is `chemical_interaction_set@1`. Jobs publish outputs only after parent-side versioned validation, never on partial worker completion. A native valid empty set is a successful job with `null_result:true` and zero rows.

## Chemical source, assignments and reports

`GET /runs/{rid}/chemical/structures/view?handle=...` reads only a validated same-run `chemical_structure@1` and returns `{schema:"chemical_structure_view@1",handle,kind:"chemical_structure",format:"mmcif",text,model_number,viewer_source_sha256,manifest_handle,manifest_sha256}`. The manifest hash is the exact canonical object payload SHA, revalidated against the same-run manifest link; `text` is the exact served local mmCIF bytes decoded as UTF-8. `GET /runs/{rid}/chemical/structures/atoms?handle=...&offset=0&limit=1000` returns an `atom_catalog@1` shaped like M10, with complete derived AtomRefs, coordinate_A, protein flag and viewer_source_index. Its default is 100 and this M11-only route accepts limits 1–1000, against a validated whole-source cap of 10,256 atoms. Every page retains the same-run completed-publication, source/manifest byte/hash, and authoritative atom-site checks. The client must fetch every page and validate the exact served-byte SHA/native source-index bijection. The M11 staging page has the same new 1000 maximum; M10/general atom catalog and chemical result-row page keep their existing smaller limits. `GET /runs/{rid}/chemical/graphs?handle=...` returns `{meta,graph}` with `chemical_graph@1` atom/bond rows, actual engine coordinates, recording receptor MDAnalysis float32 and ligand SDF/RDKit precision separately, native parent-index mappings, source AtomRefs and manifest/source links. These endpoints do not widen M8 session, M9 saved-scene, M10 distance or comparison allowlists.

`GET /runs/{rid}/chemical/preparation-manifests?source_handle=...` is a read-only source-linked immutable-object reader returning `{meta,manifest}`. It accepts only a same-run `chemical_structure@1` source, validates its exact saved mmCIF/atom mapping and `chemical_preparation_manifest@1` link, checks the source's canonical manifest payload SHA-256, and returns the stored manifest body rather than reconstructing choices from the current form. Source and manifest reads enforce actual descriptor-level byte caps of 32 MiB and 8 MiB respectively, then verify the content hash before parsing. The manifest includes the submitted ligand identity/SDF record, acknowledgement and pH annotation, exact terminal-extension inventory, attached source-site mapping, graph-derived histidine states and stereochemistry policy. `stereochemistry_audit` has one row for every declared supported V2000 parity center: `{sdf_atom_index,declared_parity,declared_CIP,observed_CIP,signed_tetrahedral_determinant_A3,method:"rdkit_v2000_parity_vs_3d@1",outcome:"match"}`; the determinant uses the first three atom coordinates minus the fourth, with the four SDF neighbor indices sorted ascending; it is six times signed tetrahedron volume. The saved-object reader independently checks coverage and coordinates. `histidine_states` rows contain `{residue,ring_h_sites,ring_formal_charge,ring_n_charges,represented_state,annotation}` from the actual aromatic ring/H/charge graph. A foreign, wrong-kind, corrupt or mismatched source/manifest is rejected; reads do not start a worker, change events or recompute chemistry. This additive reader was selected after the initial M11 transport draft so browser and reopen flows can verify the persisted preparation choices against the rendered source.

Illustrative view/catalog relationship: `{ "schema":"chemical_structure_view@1", "handle":"obj://run_x/chemical_structure/<sha>", "kind":"chemical_structure", "format":"mmcif", "text":"data_chemical...", "model_number":1, "viewer_source_sha256":"<SHA-256 of exact text bytes>", "manifest_handle":"obj://run_x/chemical_preparation_manifest/<sha>", "manifest_sha256":"<canonical manifest payload SHA-256>" }`; a matching catalog page has `{ "schema":"atom_catalog@1", "structure_handle":"<same chemical_structure handle>", "viewer_source_sha256":"<same served-byte SHA-256>", "model_number":1, "total":5067, "offset":0, "limit":1000, "rows":[{"ref":<complete derived AtomRef>,"coordinate_A":[12.1,4.2,-1.0],"protein":true,"viewer_source_index":0}] }`. All catalog pages share that hash and exactly cover source indices 0 through total−1; mismatch is a fatal mapping error.

`GET /runs/{rid}/chemical/results?handle=...` is a selected-handle read, not a list. The UI derives admissible result history only from matching successful completed publication; `object_created` events supply immutable kind metadata, not completion proof by themselves. It returns `{meta,result}` where result is `chemical_interaction_set@1`: `{schema,chemical_structure_handle,graph_handle,manifest_handle,method,dependency_manifest,criteria,rows,total,null_result,limitations}`. The `criteria` object includes the pinned five-category ProLIF default ligand/protein SMARTS and their SHA-256, plus exact distance, angle and 6.0 Å vicinity settings; the dependency handshake binds the installed interaction source hashes. `GET /runs/{rid}/chemical/results/rows?handle=...&offset=0&limit=50&category=HBDonor` returns `{schema:"chemical_interaction_page@1",handle,total,offset,limit,rows}` with limit 1–100, category optional. Each row has stable `row_id`, `category`, `backend_category`, exact ligand and receptor `AtomRef` arrays, `roles` (`donor`,`hydrogen`,`acceptor` for H bonds), `native_parent_indices`, `native_within_residue_indices`, `distance_A`, `distance_roles`, optional `DHA_angle_deg`, and bounded `native_metadata`. Hydrogen-bond distance is D···A. Rows come from actual `Fingerprint(..., count=True).generate(..., metadata=True)`, with independently checked geometry against graph engine coordinates; no implied affinity or energy.

Rows have one `roles` entry per geometric endpoint. The `ligand_atoms` and `receptor_atoms` arrays contain complete derived chemical-source AtomRefs for every native matched index in native order; `native_parent_indices` and `native_within_residue_indices` have parallel ligand/protein arrays, not scalar indices. `role_coordinates_A` copies the source-view coordinates at those AtomRefs; `engine_role_coordinates_A` copies the actual RDKit conformer coordinates used by ProLIF, retaining component-specific precision. Both are checked against the immutable graph; independent distances/angles use engine coordinates, and the report discloses coordinate precision. `distance_roles` identifies the two actual sites used for the reported distance. For `HBDonor`, ligand is D,H and protein is A; for `HBAcceptor`, ligand is A and protein is D,H. `Cationic` means ligand cation/protein anion; `Anionic` means ligand anion/protein cation. Charged and hydrophobic pattern matches may have additional atoms in the native arrays; their geometric roles identify the exact first matched endpoint from native metadata while the full arrays remain available for audit. No category is inferred from geometry alone.

The following are **synthetic schema examples**, not measured observations or production constants. Every AtomRef is complete; the compact JSON is intended to pin field shape and role direction.
