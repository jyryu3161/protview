## M11 input and chemistry contract

This selection intentionally does not solve protonation, tautomer assignment, missing-atom reconstruction, or general chemical perception from PDB coordinates. The first usable contract must accept an immutable **chemistry sidecar** bound to an exact prepared structure handle, model, and ligand instance. It supplies bonds, bond orders/aromaticity, formal charges, and atom mapping for the selected ligand and protein region. Coordinates come from the selected structure. Every mapped hydrogen must have supplied coordinates; none is silently generated.

A practical import path may use supplied SDF/mol blocks with explicit atom maps and a complete source-atom mapping table. Protein chemistry can be supplied as a complete mapped graph; requiring a ligand SDF alone is insufficient for donor/acceptor assignment on the protein. A convenient standard-residue template importer is a separate implemented sub-contract: if chosen, it must identify its local template source/license, handle peptide bonds/termini/disulfides explicitly, require explicit histidine/protonation decisions, and reject unsupported states. Do not invent that importer in the capability response. Sol and Astra should finalize the user-facing chemistry upload format before enabling M11 controls.

Recommended initial supported matrix:

| Input | Initial behavior |
| --- | --- |
| One selected ligand, mapped complete ligand/protein chemistry, explicit H, valid valence, fixed coordinates | Run the declared ProLIF categories |
| Ordinary PDB/mmCIF without required chemistry | Structured precondition `chemistry_required`; existing geometric contacts remain available |
| Missing relevant hydrogen coordinates | `explicit_hydrogens_required`; no implicit-H fallback disguised as the same method |
| Incomplete graph, ambiguous atom map, mismatched source/coordinates | `input_invalid`, before worker dispatch |
| Metal coordination, covalent ligand, unresolved alternate states, unsupported residues/valences | Specific unsupported-input reason; do not silently omit them |
| Valid supported graph with no detected assignments | Successful `scientific_null` |

Initial category allowlist: `HBDonor`, `HBAcceptor`, `Hydrophobic`, `Cationic`, `Anionic`. Broader pi, halogen, water-bridge and metal categories remain unavailable until separately specified and tested. Use ProLIF's actual SMARTS and geometry, not custom proximity rules bearing ProLIF names. Hydrogen-bond defaults in 2.2.2 are donor–acceptor distance 3.5 Å and donor–H–acceptor angle 130–180 degrees. Pin parameters explicitly; serialize the exact effective SMARTS and thresholds or an immutable configuration digest with locally stored configuration. Recheck charged/hydrophobic thresholds from the pinned installed source rather than copying numbers from a different documentation version. [Pinned interaction implementation](https://raw.githubusercontent.com/chemosim-lab/ProLIF/v2.2.2/prolif/interactions/interactions.py).

Construct RDKit molecules with explicit bonds/charges and conformers, sanitize with controlled failure handling, then wrap them using ProLIF's direct molecule API. `Fingerprint(..., count=True).generate(lig, prot, metadata=True)` yields all qualifying combinations with parent atom indices and geometry metadata. No trajectory reader or file-path lookup is needed. Persist JSON-compatible native metadata; never use pickle/dill for imported or replayed objects. [ProLIF API](https://prolif.readthedocs.io/en/stable/source/modules/interaction-fingerprint.html).

Identity is owned by ProtView. Assign unique synthetic backend residue numbers and keep an immutable bijection from backend atom index to full M10 atom reference: source/model, author and label chains/sequences, insertion code, residue name, atom name and resolved altloc. Never parse a ProLIF display residue string back into scientific identity. Verify parent-index semantics after molecule splitting and sanitization; preserve ordering or explicitly retain the remapping. Two same-name ligand instances, duplicate author numbering across chains, insertion variants and unknown label IDs must remain distinct. Reject duplicate/unmapped indices and output references outside the input allowlist.

Result proposal: a new chemical-interaction-set schema containing exact source/chemistry/preparation handles; engine/library versions; effective category configurations; hydrogen/protonation/bond-order provenance; per-assignment ligand/protein atom references; role-labeled donor/H/acceptor atoms where applicable; native metadata; named distances in Å and angles in degrees; completeness/limitations; and deterministic row ordering. Do not call every native distance “H···A”: the H-bond threshold above is D···A. Formal-charge proximity annotations are not salt-bridge energies. All assignments are model-dependent annotations, not experimentally established hydrogen bonds, affinity, ΔΔG, or stability.

## M12 detector contract

fpocket is selected because it has an actual arm64 distribution and a native geometric output suitable for cavity overlays. The official repository documents arm64 compilation and bundled tests. If the conda build fails, preserve the solver/runtime error and build exact tag `4.2.3` locally using `make ARCH=MACOSXARM64`, recording compiler, flags, linked libraries and binary hash. Do not run `sudo make install`; use an application-configured executable under the dependency directory. The upstream build documentation mentions netcdf and bundled molfile support, so actual link dependencies must be checked rather than assumed. [Official build instructions](https://github.com/Discngine/fpocket/blob/4.2.3/README.md).

Use selected, resolved, protein-heavy-atom coordinates with explicit exclusions of ligand, water, ions and hydrogens recorded in a detector input manifest. Initially support standard protein residues; malformed or incomplete inputs need explicit handling. The ligand must not remain as an obstacle in an allegedly ligand-free cavity calculation. Keep original immutable bytes. A temporary normalized PDB with synthetic residue/atom IDs is acceptable as an adapter transport only when it has a complete reversible mapping and explicit format limits; never replace the scientific source with it. Reject identifier/coordinate ranges exceeding the transport rather than truncating. Record coordinate quantization if using three-decimal PDB coordinates; independently reconcile to that actual engine input within its precision. An mmCIF transport can supersede this only after output mapping is exercised.

Invoke the fixed executable through argv in a private per-job directory with fixed safe basename and private `TMPDIR`. The exact release contains temporary-file generation and native computation; no user shell string or arbitrary flag passthrough is allowed. Capture bounded stdout/stderr and output files. Only parse known relative files under the job root; reject links, excessive files/bytes, nonfinite numbers, unknown/missing atom references and inconsistent pocket IDs. [Pinned Voronoi code](https://raw.githubusercontent.com/Discngine/fpocket/4.2.3/src/voronoi.c).

**Fresh fpocket runs are not promised deterministic.** Release 4.2.3 calls `srand(time(NULL))` in Voronoi code and seeds its random utility from wall time; its volume calculations include Monte Carlo sampling. Record `seed_control: unsupported`, native release/build, complete effective parameters and the observed output. Do not falsely set `seed: 0`, monkeypatch results, or round values to manufacture agreement. Repeated calls in one run must return the stored completed call; events-only replay restores results without rerunning. Separately requested recomputation may differ and must produce its own provenance. [Random utility](https://raw.githubusercontent.com/Discngine/fpocket/4.2.3/src/utils.c), [parameter declarations](https://raw.githubusercontent.com/Discngine/fpocket/4.2.3/headers/fparams.h).

Set parameters explicitly after reconciling actual CLI help with source: the pinned header's alpha-sphere radius constants are 3.4 and 6.2 Å while help/comments contain different historical values. Do not rely on documentation defaults. Record clustering parameters, minimum sphere count, volume sampling iterations and every other effective knob. The final M12 contract must list actual accepted argv and values before implementation acceptance. [4.2.3 parameter source](https://github.com/Discngine/fpocket/blob/4.2.3/headers/fparams.h).

Store the native pocket rank/score, alpha-sphere centers/radii, mapped lining atoms/residues, and parsed native descriptor names. Geometry coordinates/radii are Å; genuine volume fields are Å³; actual surface-area fields are Å². Native scores stay dimensionless detector scores with their exact names; an fpocket “druggability score” must not become a validated druggability claim. Do not infer physical units for every descriptor from its name. Preserve bounded native output so interpretation can be audited. If the adapter computes a display center as a mean of sphere centers, label it as that derived display quantity rather than an engine-native center.

Default display top-k may be 10 with an allowed bounded range, but save the entire accepted bounded pocket set and total count. Mark display truncation separately from engine/output resource truncation; the latter should fail rather than claim completeness. Selecting a pocket displays its actual stored sphere geometry and mapped residues on the exact source scene. A centroid marker alone does not prove that cavity rendering works. No-pocket success requires valid engine completion and validated empty output; an absent output directory after a crash is not scientific_null.

## Alternatives and fallback boundaries

PLIP remains a fallback, not the first backend. Its official documentation warns about matching OpenBabel Python bindings and about varying hydrogen placements between runs, recommending prepared input with `--nohydro` for reproducibility. PLIP is GPL-2.0. It could support an explicit OpenBabel-derived chemistry protocol, but that would need its own preparation/mapping and license treatment; switching does not remove the chemistry contract. No PLIP installation failure was observed here because installation was not attempted. [Official PLIP documentation](https://github.com/pharmai/plip).

P2Rank 2.5.1 is the M12 fallback if native fpocket cannot be made to execute reliably. Its official release runs with Java 17–24 and ships trained local models; prediction emits pocket/residue CSV and surface-point data. No JVM is installed here. Before selecting it, pin/install a local JRE and release/model hashes, audit the pinned BioJava chemical-component provider and prove offline parsing under denied network access. Do not use a web service or allow automatic chemical-dictionary downloads. The offline audit remains unresolved in this research; it is not evidence that P2Rank cannot work offline. Native probabilities/scores would require their own interpretation, never affinity labels. [P2Rank 2.5.1 release](https://github.com/rdk/p2rank/releases/tag/2.5.1), [official usage and output](https://github.com/rdk/p2rank/blob/master/README.md).

## Concrete next prototype: prepared receptor plus mapped ligand SDF

The recommended first public positive demo is the **prepared ProLIF docking example**, not unprepared 1HSG: pinned package files `prolif/data/vina/rec.pdb` and first record of `prolif/data/vina/vina_output.sdf`. The official tutorial reads the receptor via `MDAnalysis.Universe` then `prolif.Molecule.from_mda`, and the ligand via `prolif.sdf_supplier`. These inputs include a supplied prepared receptor and ligand chemical representation. Preserve the package version, original example bytes, provenance and any fixture-specific notice. Call the result a docking-example assignment, not an experimental validation. [Official example](https://prolif.readthedocs.io/en/stable/notebooks/pdb.html).

This supports a second explicit preparation protocol in addition to the strict supplied-complete-graph lane above: `prepared_receptor_mdanalysis_2_10_explicit_h`. The UI must state that the receptor has supplied explicit H but its chemical graph is **inferred by MDAnalysis**, not supplied experimental chemistry. MDAnalysis 2.10 documents bond-order/charge inference from connectivity and explicit H; its converter is experimental. Store resulting connectivity, formal charges, aromaticity, bond orders and mapped graph as immutable chemistry objects. Record whether initial connectivity was supplied or guessed, the exact guesser/radii/settings, and reject incomplete/mixed connectivity. Include graph-level independent assertions for amide nitrogens, carboxylates and protonated/neutral histidines. This named protocol must not be silently substituted for the strict lane. [Versioned converter documentation](https://docs.mdanalysis.org/2.10.0/documentation_pages/converters/RDKit.html).

For product import, require one selected ligand instance and one SDF record with explicit H. A JSON mapping relates each SDF heavy-atom index to a complete selected source atom reference (or use explicit unique atom-map tags). Require a bijection over selected heavy atoms, matching elements and coordinates in the same frame within a declared precision tolerance; reject duplicates, missing atoms and ambiguous symmetry. Do not align a freely generated conformer silently. SDF supplies ligand bonds/formal charges; source heavy coordinates supply displayed geometry. If source lacks ligand H, retain SDF hydrogen coordinates in a **new derived chemically prepared structure**, with generated/supplied-H identities and parent links, rather than inventing references to atoms absent from the source. All calculations and selection bind that derived structure. The same logic applies when importing the prepared receptor beside an existing source.

A later convenience route for ordinary standard-protein inputs can explicitly apply the already installed OpenMM 8.6.0 `Modeller.addHydrogens` with the reviewed force-field family, heavy atoms fixed, declared pH and recorded residue variants, then feed its actual connectivity plus explicit H to the versioned MDAnalysis converter. This is a new chemistry preparation operation, not reuse of protein minimization results as ligand chemistry. OpenMM documents variant overrides and preservation of existing atom positions. Reject missing heavy atoms/unsupported residues as the current OpenMM adapter does; do not patch missing termini merely to make 1HSG work. Protein-only H placement is not jointly optimized with the ligand and must carry that limitation. [OpenMM Modeller API](https://docs.openmm.org/latest/api-python/generated/openmm.app.modeller.Modeller.html).

Next Sol probe should first execute the unchanged pinned prepared public example, print native per-assignment indices/geometry, and demonstrate a negative by separating the ligand in a clearly labeled synthetic derivative. Then establish source-to-backend index bijections and independent graph/angle checks. Only after that evidence should Astra choose whether the first release exposes the prepared-input inference protocol, the strict graph protocol, or both. This is an actionable real-engine demonstration path; no unavailable-for-all M11 release is proposed.
