# 0015. 과학 데이터(구조·좌표·서열·리간드)의 외부 모델 전송을 허용한다

- 상태: 채택 (사용자 결정 2026-09-29). 0005의 "좌표·구조·서열은 외부로 나가지 않는다" 부분을 대체한다.

## 배경
사용자는 JEV(OpenRouter의 `typesafe/jev` 계열) 같은 외부 모델로 단백질 서열 공학과 리간드 구조 변경 공학을 다양하게 시도하려 한다. 그러려면 모델이 실제 서열·구조·리간드·분석 결과를 봐야 한다. 기존 규칙(0005)은 이것들을 절대 외부로 보내지 않게 막고 있었다.

## 결정
- 구조 파일 내용, 좌표, 서열, 잔기·원자·리간드 이름과 구조, 분석 결과(접촉·SASA·포켓 등)를 외부 모델 서비스로 보내는 것을 허용한다. 주 목적지는 JEV다.
- 바꾸지 않는 것:
  - 외부 HTTP는 여전히 `EgressGate` 하나로만 나간다. 전송 전에 감사 기록을 남기고, 실제로 보낸 내용을 기록한다.
  - API 키·자격 증명은 어떤 경우에도 요청 본문·이벤트·로그·보고서·커밋에 넣지 않는다.
  - 서버는 `127.0.0.1`에만 바인딩한다. 이것은 데이터 전송 정책이 아니라 인증 없는 서버를 네트워크에 여는 문제다.
  - 과학 계산 결과는 실제 엔진으로만 만든다. 외부 모델이 낸 제안(서열 변경안, 리간드 변경안 등)은 계산 결과가 아니라 제안으로 따로 기록한다.
- 현재 코드는 아직 바뀌지 않았다. 게이트의 허용 목록 투영은 지금도 뷰어 의도(`viewer_intent@1`)와 inspection 집계(`inspection_state@1`)만 만든다. 새 데이터 종류를 실제로 보내려면 다음 단계에서 게이트 투영·UI 미리보기·예산을 새로 만든다. 이 결정은 그 설계를 막던 규칙을 없앤다.

## 검토한 대안
- 규칙 유지 + 로컬 모델만 사용: 사용자가 JEV를 쓰려는 목적과 맞지 않는다.
- 게이트 없이 각 모듈이 직접 전송: 무엇이 나갔는지 추적할 수 없고 키 노출 위험이 커진다.

## 결과
- 미공개 구조·서열이 외부 모델 제공자에게 전달될 수 있다. 이 위험은 사용자가 받아들였다. 제공자 정책(`data_collection=deny`, `zdr=true`)은 게이트 설정으로 유지한다.
- M12 포켓 검출 자체는 로컬 fpocket만 쓰므로 외부 요청 0건 조건이 그대로다.
- 이미 기록된 과거 계약 문서(`docs/EGRESS_CONTRACT.md`, `docs/M3_EGRESS.md`, `docs/M8_AGENT_VIEWER_CONTRACT.md`)는 당시 기록이므로 바꾸지 않는다. 현재 규칙은 `docs/security.md`와 이 결정이다.
