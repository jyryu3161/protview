# 0032. M24 JEV 과학 데이터 전송은 게시된 후보 집합(M17 리간드·M20 변이)에서 사용자가 고른 최대 20개로 "먼저 계산할 후보 하나"를 고르게 하는 선택지형 질문 둘만, 전송마다 본문 해시 승인 + run 수준 별도 동의, 비싼 계산 단위 없이 외부 토큰·USD만 쓰고, 응답은 제안 객체로 따로 기록한다

- 상태: 채택 (사용자 결정 2026-10-06, M24 명세 확정과 독립 점검 두 차례 뒤 질문에서 모두 추천안을 골랐다. 아래 "조율 세션이 정한 것"은 사용자가 최종 확인에서 바꿀 수 있다). 결정 0015(과학 데이터 전송 허용)의 구현이다.

## 배경
결정 0015는 구조·좌표·서열·리간드·분석 결과를 외부 모델(JEV)로 보내는 것을 허용했지만 전송 경로를 만들지 않았다. 게이트는 뷰어 의도와 접촉 집계만 만들었고, 새 데이터 종류를 보내려면 투영·미리보기·감사·예산을 새로 만들어야 했다. JEV decisions API는 판정형(선택지·예/아니오·점수)이라 새 SMILES·서열을 쓰지 못하고, 실호출로 확인한 형식은 선택지형(`choice`)뿐이다(M3·M8). 위험은 다섯 가지였다: 미리보기와 실제로 나가는 바이트가 다른 것, 허용 목록 밖 데이터(handle·경로·좌표·번호 대응·키)가 나가는 것, 뷰어 동의와 과학 전송 권한이 섞이는 것, 외부 모델의 선택이 순위·추천·예측처럼 읽히는 것, 예산 한도 증액 경로가 늘어나는 것.

## 결정 (사용자, 2026-10-06)
- **범위 = 후보 고르기 한 가지를 처음부터 끝까지**: 통로(보낼 내용 틀·미리보기·기록·예산)와 선택지형 질문 하나. 소스는 게시된 M17 `ligand_candidate_set@1`·M20 `mutation_candidate_set@1` 둘이고 질문은 고정 둘(`ligand_candidate_choice@1`, `mutation_candidate_choice@1`). 예·아니오·점수형·계속/멈춤은 하지 않는다(실호출로 확인한 적이 없다).
- **보낼 내용 = 식별자·계산 수치 + 부위 주변 정보까지**(후보 번호·SMILES·변이 표기·엔진 이름·단위가 붙은 수치, 변이 위치 주변 잔기 이름·서열 구간·포켓 요약). 구조 좌표·전체 서열은 보내지 않는다. 번호 대응 참조값(UniProt 번호·accession·KLIFS 이름표)과 보호 사유 이름은 보내지 않는다(검사별 상태 문자열과 `protection_released`만).
- **전송마다 승인**: 보낼 정확한 본문을 화면에서 보고 승인할 때만 전송하고 본문 SHA-256이 다르면 보내지 않는다. run당 과학 전송 10회, 본문 64 KiB 이하, 후보는 사용자가 직접 고른 최대 20개(리간드는 필터 통과만, 초과는 자르지 않고 거절). **run 수준 "과학 데이터 외부 전송 허용" 스위치**(기본 꺼짐)를 전송마다 승인과 별개로 둔다. 뷰어 동의와 서로 권한을 주지 않는다.
- **화면 = 지식·보고서 탭 한 곳**(다른 탭 내용 불변). 선택을 도킹·모델링 요청 칸으로 넘기는 단추는 두지 않는다(반복 루프는 M25).
- **응답 = 제안 객체 + 보고서**: 고른 후보·확신도·후보별 확률을 받은 그대로 별도 `jev_choice@1`로 저장한다. 화면은 고른 후보와 확신도만 "JEV 판정(모델 선택)"으로 보이고 후보별 확률은 접힌 상세에 값만(후보 순서 그대로). 보고서 `jev_choice`는 확률을 넣지 않는다.
- **예산**: 비싼 계산 단위를 쓰지 않는다. 외부 토큰·USD 예약과 run당 10회 상한만 쓴다. 뷰어와 외부 토큰·USD 예산과 "사용량 모름" 중지 상태를 공유한다(분리는 M25).
- **질문 기준 = 고정 질문만**(기준·목표 문구·자유 입력 없음).
- **후보 순서 = 소스 집합의 저장 순서 고정**(섞지 않음) + 고정 문장 J4. **같은 목록 재전송 허용**(새 전송, 상한 소모, 제안을 시간순으로 따로 나열, 합치기·다수결 없음). 리간드에는 수용체·포켓 정보를 더하지 않는다. 늦게 도착한 응답은 검증을 통과하면 저장하고 `late` 표시.
- **실호출 합계 6회**(결정 0012). 2026-10-06에 모두 썼다.

## 조율 세션이 정한 것 (사용자가 최종 확인에서 바꿀 수 있음)
- **닫힌 이름**(`backend/mw/jev_constants.py`): 도구 `build_jev_projection`(값싼 도구, 불변 객체 `jev_projection@1`), 와이어 스키마 `jev_ligand_candidates@1`·`jev_mutation_candidates@1`, 제안 `jev_choice@1`, 기록 `jev_send@1`·`jev_status@1`·`jev_preview@1`, 이벤트 `jev_science_consent_changed`·`jev_send_approved`·`jev_science_dispatch_started`·`jev_send_outcome`, 투영 입장 사유 9개(사전 검사 8 + `payload_too_large`)와 저장 형태 거절 `projection_invalid`, 거절 8·실패 8·차단 7·늦음 2 이유, 전송 상태 `completed`·`rejected`·`failed`(읽기 전용 파생 `in_progress`).
- **고정 문장** J1–J7(제안 한계)·U1–U3(화면 안내: 재전송 응답 합치지 않음, 뷰어와 예산 공유, 서열 구간·이웃으로 단백질이 알려질 수 있음). 질문 지시문(영어, 대기열 순서 선택일 뿐 예측이 아님).
- **상수**: 이웃 5.0 Å(중원자, M20 위치와 같은 단백질 잔기)·서열 구간 앞뒤 5, 본문 64 KiB, 응답 64 KiB, 제한 시간 15초, HTTP 1회·재시도 없음.
- **투영을 값싼 도구가 저장하는 불변 객체로**: 이웃 잔기·구간·거리가 좌표에서 오므로 프로젝트 규칙(과학 계산은 `Run.call`·`JobQueue`)대로 만들고, 미리보기·승인·전송은 그 저장 객체만 가리킨다.
- **승인 구조**: 라우트 `POST /runs/{id}/jev/sends` 하나가 `jev_sends.run_send`를, 그것이 `request_science`를 부르는 유일한 경로다(AST 테스트). 게이트는 승인 콜백(`admit`)이 없으면 어떤 이벤트도 쓰기 전에 거절하고 콜백 뒤 로그에서 승인을 다시 대조한다. JEV POST는 `application/json`만 받는다(교차 사이트 단순 POST 방지).
- **예약식**: 외부 토큰 `min(50000, 4096 + ceil(body_bytes × 2 / 3))`, USD 0.10. 첫 실호출 실측(본문 3,539 B → 입력 2,087 + 출력 65 토큰, 본문 바이트/입력 토큰 1.70)으로 명세 첫 식(`min(40000, 4096 + ceil(body_bytes / 2))`)을 고쳤다.

## 검토한 대안
- 한 줄 목표 입력(자유 입력이 외부로 나가고 화면·검증이 늘어남), 각 탭 후보 표 옆 "JEV에 묻기"(두 화면과 회귀가 늘어남), 화면 없는 API만(사람이 보내기 전 내용을 못 봄), 전송마다 비싼 계산 1단위(도킹·GA와 서로 막고 증액 경로가 없음), 후보별 확률 미저장(사실상 줄 세우기로 읽히는 것을 막지만 받은 그대로 저장하는 쪽을 골랐다), 세 가지 질문 형식(예·아니오·점수형은 실호출로 확인한 적 없음), 뷰어 동의를 과학 전송에 공유, 번호 대응 참조값 전송, 후보 순서 섞기, 선택 결과 넘기기 단추, 외부 예산 분리.

## 결과
- 착수 확인(`docs/qa/m24-jev-20261006/preflight.txt`): 와이어 허용 목록의 모든 항목이 저장 객체에 있고(일부는 파생: `generation_kinds`·`sources` 이름), 20개 후보 본문 최대 29,828 B로 64 KiB 안, 예약·정산·재생이 `expensive_calls` 축 없이 동작, 취소된 run에서도 감사·결과 이벤트와 제안 객체 저장 가능, 전송이 HTTP 동안 run 실행 잠금을 잡아 같은 run의 다른 변경 요청은 503 busy.
- 독립 검토: 명세 점검 두 차례(지적 7건 → 사용자 질문, 새 지적 3건 → 반영), 실행 가능성 검토(막는 지적 6건 → 문서 반영), T2·T4 명세 검토(T4: 게이트 승인 필수화·순서 테스트 보강), 코드 검토 둘(백엔드 approved, 프런트 1건 → 수정).
- 실호출 6회가 모두 `completed`(응답 모델 `typesafe/jev-1.13-20260917`, 외부 요청 중지·예약 초과 없음). 응답에 `confidence`와 후보별 `probabilities`가 있었다. 본문 바이트/입력 토큰은 1.63–1.79. **6회 모두 목록의 첫 후보(`c01`·`m01`)를 골랐다**(같은 본문 재전송 포함). 기준 문구가 없는 고정 질문의 선택이 목록 순서의 영향을 받을 수 있다는 J4의 근거이며, 6건으로 일반화하지 않는다. 목표를 담는 질문은 M25의 몫이다.
- 변경하지 않은 파일(해시 대상): M17·M18·M19·M20·M21·M22·M23 코드·상수·결과. 덧붙인 기존 코드는 등록 파일(`config/tools.yaml`·`workspace.py`·`app.py`)·`gate.py`의 위임 메서드 하나·`core/events.py` 이벤트 종류 넷·화면 연결(`page.tsx`·`WorkspaceTabs.tsx`)뿐이다. 덧붙인 기존 프런트·설정은 `lib/api.ts`·`contracts.ts`·`report-library.ts`·`design/components.css`·`package.json` 스크립트·`.codex/hooks/stop.py`·`docs/standards.md` 목록이다. 기존 테스트는 도구·capability 이름 집합을 하드코딩한 네 파일(`test_api.py`·`test_ligand_api.py`·`test_reference_site_annotation.py`·`test_residue_numbering.py`)과 `report-library.test.cjs`의 단언 한 줄만 최소로 고쳤다(M24 새 JEV 테스트의 원시 본문 거절 테스트는 JSON 헤더를 붙인다).
