# 0001. Opus 5.5 서브에이전트로 조율·구현·검토 분리

- 상태: 채택 (2026-09-27)

## 배경
M0–M10은 Codex에서 GPT-6 Sol(구현)과 GPT-6 Astra(설계·검토)로 진행했고, 상위 세션이 커밋과 단계 기록을 맡았다. 앞으로는 Claude Code로 작업을 이어 가며, 사용자가 GPT 대신 Opus 5.5를 쓰고 역할은 메인 세션과 분리한 서브에이전트로 나누기로 했다.

## 결정
- 메인 세션: 사용자와의 대화, 설계 결정, Git 전이, 단계 기록.
- 구현 서브에이전트(Opus 5.5): 코드, 테스트, QA 스크립트 작성과 수정.
- 검토 서브에이전트(Opus 5.5): 해당 코드를 쓰지 않은 새 에이전트가 과학 계약과 구현을 검토한다. 지적 사항은 해결하거나, 범위 밖이라고 기록한 뒤에만 완료로 표시한다.

## 검토한 대안
- 메인이 직접 구현하고 검토만 분리: 메인 대화 맥락에 구현 세부가 쌓이고, 설계 결정과 구현 판단이 한 에이전트에 섞인다.
- 검토자를 과학·코드 둘로 분리: 독립성은 높아지지만, 매 작업마다 서브에이전트가 하나 더 들고 두 검토 결과를 조정해야 한다. 지금 규모에서는 과하다고 판단했다.

## 결과
- 같은 에이전트가 구현하고 승인하는 것은 금지다.
- 과거 검토 기록의 GPT-6 이름은 역사 기록으로 그대로 둔다. 새 기록에는 실제 실행한 모델을 적는다.
- `scripts/execute.py`는 검토자를 `gpt-6-astra`로 고정하고 있어, 새 역할 구조로는 새 단계를 기록할 수 없다.
