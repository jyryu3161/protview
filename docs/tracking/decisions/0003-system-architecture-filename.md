# 0003. 새 시스템 구성 문서 이름을 `docs/system-architecture.md`로

- 상태: 채택 (2026-09-27)

## 배경
작업 디스크(APFS)는 대소문자를 구분하지 않는다. 새로 만들 `docs/architecture.md`는 기존 `docs/ARCHITECTURE.md`와 같은 파일이 된다. 기존 파일은 M6·M7·M8 검토 기록에 SHA-256으로 묶여 있다.

## 결정
기존 대문자 문서는 모두 그대로 둔다. 새 시스템 구성 문서는 `docs/system-architecture.md`로 만든다. 다른 새 문서(`business-rules.md` 등)는 기존 파일과 이름이 겹치지 않는다.

## 검토한 대안
- 기존 `ARCHITECTURE.md`를 새 내용으로 교체: 해당 단계의 `--verify`가 오래된 검토로 판정되고, 당시 설계 원문을 잃는다.
- 기존 문서를 `docs/archive/`로 이동: 검토 기록의 경로가 바뀌어 과거 단계 재검증이 모두 깨진다. README·단계 명세의 링크도 깨진다.

## 결과
- `docs/`에는 옛 단계별 설계·계약 문서(대문자)와 새 프로젝트 문서(소문자)가 함께 있다. 옛 문서는 당시 기록이자, 진행 중·예정 단계(M11–M13)의 상세 계약이다.
- 대문자 문서와 소문자만 다른 이름의 새 파일을 만들면 안 된다.
