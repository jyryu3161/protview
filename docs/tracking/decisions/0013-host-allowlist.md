# 0013. Host 헤더 허용 목록을 백엔드와 프런트엔드 두 곳에 둔다

- 상태: 채택 (사용자 결정 2026-09-28)

## 배경
인증이 없는 loopback 서버(결정 0011)는 사용자가 브라우저로 연 외부 페이지가 DNS 리바인딩으로 `127.0.0.1` API에 요청을 보내는 경로를 막지 못했다. 브라우저는 백엔드(:8000)가 아니라 Next(:3000)의 `/api` 프록시로 들어오고, 프록시는 백엔드에 Host를 `127.0.0.1:8000`으로 바꿔 보낸다.

## 결정
Host 이름이 `127.0.0.1`, `localhost`, `[::1]`(포트 유무 무관, 대소문자 무시)인 요청만 받는다. 백엔드는 가장 바깥 ASGI 미들웨어, 프런트엔드는 모든 경로에 적용되는 `frontend/middleware.ts`에서 검사한다. 그 밖의 Host는 400 고정 문구로 거부하고 Host 값을 되돌려 주지 않는다.

## 검토한 대안
- Origin 확인 추가: 다른 탭의 악성 페이지가 보내는 상태 변경 요청까지 막지만, 이번에는 고르지 않았다.
- 로컬 토큰: 가장 강하지만 프록시·QA·스크립트를 모두 고쳐야 한다.
- 백엔드만 검사: 프록시가 Host를 바꾸므로 :3000 경로의 리바인딩을 막지 못한다.

## 결과
- 알려진 한계: :3000에 Host 헤더를 두 개(허용 값이 먼저) 보내면 Node가 첫 값만 남겨 통과한다. 브라우저는 Host를 하나만 보내므로 리바인딩 방어에는 영향이 없다. 코드로 막지 않고 기록만 한다(사용자 결정 2026-09-28).
- :8000에서 Host가 없거나 여러 개인 요청은 uvicorn이 앱 전에 400으로 거부한다.
