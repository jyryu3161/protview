# 0031. M23 서열 GA는 게시된 M20 후보 집합의 다중 변이 조합을 개체로, 개체마다 PDBFixer + OpenMM 모델링 뒤 사용자 SDF 리간드 qvina 자유 도킹 점수만을 적합도로 쓰고, 한 작업이 도킹 환경에서 모델링을 자식 프로세스로 실행한다

- 상태: 채택 (사용자 결정 2026-10-05, M23 명세 확정과 독립 검토 뒤 질문에서 추천안을 골랐다. 아래 "조율 세션이 정한 것"은 사용자가 최종 확인에서 바꿀 수 있다)

## 배경
M23은 단백질 공학 탭의 셋째 기능이고 여는 시나리오는 "GA 기반 서열 설계"다(로드맵 M23: GA 설계를 서열 공간에 적용, 선행 M22·M21). M20은 동시 변이를 M23으로 미뤘고(결정 0028), M21 모델링은 변이 한 곳만 지원하며(결정 0029), M22는 리간드 GA의 작업 모양을 정했다(결정 0030). 위험은 일곱 가지였다: 서열이 다른 두 구조의 OpenMM 전위가 비교되거나 ΔΔG·안정성으로 읽히는 것, 개체마다 수용체가 달라 점수가 순위처럼 읽히는 것, 모델링(프로젝트 환경의 OpenMM·PDBFixer)과 도킹(도킹 환경의 Meeko·RDKit·qvina)이 서로 다른 인터프리터에 있는 것, 여러 곳 변이를 한 곳 전용 M21 함수로 만드는 것, 기존 M18·M21 코드를 바꿔 이미 저장된 결과의 자동 재사용이 끊기는 것, 실패한 개체가 환불 없는 예약 단위만 태우는 것, 조합 공간이 커서 첫 세대가 모두 최대 변이 수가 되는 것.

## 결정 (사용자, 2026-10-05)
- **개체 = 서로 다른 위치의 M20 후보를 1~N개 묶은 조합**(동시 변이). 위치·보호 잔기·허용 아미노산은 M20 결과 그대로이고 이 단계에서 바꾸지 않는다. 동시 변이 수 상한 1–4(기본 3).
- **적합도 = 개체 변이 구조에 사용자 SDF 리간드를 같은 상자·seed·값으로 자유 도킹한 qvina 점수 하나**(다목적 제외, OpenMM 전위는 서열이 다른 구조라 비교할 수 없어 제외). 동점은 변이 수가 적은 쪽, 그다음 선택 순서.
- **야생형 기준 행은 항상 평가**하고 값만 보이는 참고 행이다(차이·개선 표시 없음, 선택·종료에 쓰지 않음, 개체마다의 HIS·CYS 상태 차이 기록에 필요). 야생형 기준 모델링·도킹이 실패하면 개체 평가 전에 `reference_failed`로 끝낸다.
- **계산 구조**: GA 작업 하나가 도킹 환경에서 돌며(M22와 같음) 개체마다 프로젝트 환경의 모델링 프로그램을 자식 프로세스로 실행한다(qvina를 자식으로 실행하는 것과 같은 방식, 같은 프로세스 그룹). 설치 환경은 바뀌지 않는다.
- **기존 M21·M18 바이트 불변 우선**: M21 모델링·M18 도킹 작업 모듈과 상수는 바꾸지 않고 새 모듈이 불러 쓴다. 새 수용체 출처 종류는 서버 쪽만 확장한다(저장 스키마로 `mutation_model@1`과 `mutation_set_model@1`을 구분, `docking_constants.py`의 `kind` 문자열 `mutation_model`과 `side` 집합은 그대로). 불가피하면 멈추고 사용자에게 묻는다.
- **연산자 = 이어받음 + 교차 + 변이 편집(추가·교체·이동·삭제) + 무작위**(교차는 두 부모 변이의 합집합에서). 첫 세대와 무작위 자리는 변이 수 1~최대를 균등하게 먼저 정한 뒤 위치·치환을 균등하게 뽑는다.
- **예산**: 새 평가 1건 = 비싼 계산 2단위(모델링 1 + 도킹 1), 시작 전 `reserved_units = 2 × (reserved_evaluations + 1)`을 한 번 예약하고 환불하지 않으며 재사용은 무과금이다. 규모 개체 4–16(기본 8)·세대 1–8(기본 5)·새 평가 ≤ 64(기본 32)·시간 기본 7200초·최대 14400초(작업 한도 15000초).
- **실패 제동**: 개체 평가가 연속 5건 실패하면 `repeated_failure`로 끝낸다(`null_result`는 실패가 아님). 예약 단위는 시작 전에 소모되므로 제동이 아끼는 것은 실행 시간·CPU이며 단위가 아니다(사용자에게 알림).
- **seed 둘**(GA seed, 모델링·도킹이 같이 쓰는 평가 seed). 재사용은 모델과 도킹 결과가 둘 다 저장된 개체만이다.
- **여러 곳 변이는 구조 순서대로 한 곳씩 M21 `mutant_projection`을 연속 적용**한다(M21 모듈 불변). M21의 PDBx 쓰기가 좌표를 소수 4자리로 쓰므로 단계 사이에 앞 단계에서 PDBFixer가 놓은 원자 좌표를 소수 넷째 자리로 반올림한다(변경 ≤ 5e-5 Å, M21 `GRAFT_TOLERANCE_A`는 그대로). 적용 순서·곁사슬 크기에 따라 모델이 달라질 수 있어 한계 문장 S6에 적는다.
- **개체 상세는 모델 값만**(변이 목록, OpenMM 전위와 비교 불가 문장 S5, HIS·CYS 상태와 야생형 기준과 다른 목록, 이황화·추가 원자, mmCIF, M18 결과 상세). 변이 위치 SASA·접촉 표는 만들지 않는다.
- **입력 점검**: 서버는 RDKit 없이 가능한 리간드 SDF·상자 부분 점검만 시작 전에 하고(작업 모듈이 같은 이유로 거절할 입력만 거절, 더 엄격하지 않음) 나머지(암시 수소·비틀림 수·준비 실패·수용체 준비)는 야생형 기준 행에서 드러나 `reference_failed`가 된다.

## 조율 세션이 정한 것 (사용자가 최종 확인에서 바꿀 수 있음)
- **닫힌 이름**(`backend/mw/sequence_ga_constants.py`): 프로토콜 `sequence_ga_dock_v1`, 도구 `sequence_ga_design`, 객체 `mutation_set_model@1`·`mutation_set_model_structure@1`·`sequence_ga_result@1`, 이벤트 `sequence_ga_individual_published`·`sequence_ga_published`, 종료 이유 10개(`complete`: `generations_complete`·`no_change`·`space_exhausted`, `partial`: `evaluation_limit`·`time_exhausted`·`cancelled`·`worker_failed`·`resource_exceeded`·`reference_failed`·`repeated_failure`), 출처 5개(`initial`·`carried`·`crossover`·`edit`·`random`), 편집 연산 4개, 평가 둘(`reused`·`computed`), 상태 셋(`scored`·`null_result`·`failed`), 실패 이유(M21 모델링 7 + M18 작업 이유 + `model_timeout`·`docking_timeout`·`worker_failed`, 단계 전용 집합으로 `model_handle` 유무 검증), 입장 사유 순서.
- **고정 문장 S1–S6**(항상 S1·S4·S5·S6, 부분 완료 S2, 재사용 개체 S3)과 다중 변이용 SL5. 모델 객체는 M21 L1·L3·L6를 문자 그대로 쓴다.
- **파라미터 11개와 기본값**: `crossover_fraction` 0.5, `random_fraction` 0.2, `tournament_size` 2–4, `elite_count` 0–4, `patience` 1–8, 모델링 단계 240초·도킹 단계 300초(수용체 준비 포함), 모델 객체 16 MiB·출력 256 MiB·개체당 출력 32 MiB·요약 1 MiB·스테이징 16 MiB.
- **세부 확정**(착수 확인에서 독립 oracle과 대조해 정함, 전체는 `docs/business-rules.md`의 "세부 규칙"): 재시도 횟수는 첫 시도에 더한 50·20·3번, 본 키는 선택 즉시, 슬롯 순서 교차 → 편집 → 무작위, 모든 슬롯을 먼저 선택한 뒤 평가, 종료 이유 우선순위 `generations_complete` > `space_exhausted` > `no_change`, 멈춤 검사 순서 `cancelled` > `evaluation_limit` > `time_exhausted` > 출력 총량.
- **야생형 기준 행**은 개체 평가 전에 먼저, `new_evaluations_used`·`reused_count`·`max_new_evaluations`에 세지 않고, 재사용 가능해도 예약 2단위는 늘 예약한다. 기준 행이 기록되기 전 중단은 요약 없이 작업 실패(M22와 같음), 기록된 뒤에는 모든 종료 상태에서 요약을 게시한다.
- **서버 부분 점검 기준**: M18 인자 값 규칙(수동 상자 한 변 8 Å 미만·margin 범위)은 단독 M18 서버처럼 `box_invalid`로 거절한다(작업 모듈은 5 Å도 통과시키므로 같은 입력에서 이유가 다를 수 있음).
- **읽기**: 한 읽기 안에서 이벤트 로그를 한 번만 읽는 스냅숏(M23 읽기·재사용 색인 전용 새 코드, M18·M19·M22 읽기 경로 불변)으로 165 MB 로그에서 요약 상세 3.0초·재사용 색인 8.8초(T1 측정, 개체마다 로그를 다시 읽으면 28.6–44.3초·44.4초. 구현 뒤 합성 패딩 로그로 다시 잰 값은 상세 0.84초·재사용 색인 1.10초이며 커밋한 증거는 없다).

## 검토한 대안
- 단일 변이 후보만 개체로(M22 방식): 동시 변이가 없어 서열 설계보다 후보 탐색에 가깝다. 사용자가 다중 변이 조합을 골랐다.
- 다목적(qvina 점수 + 변이 수 등), OpenMM 전위·SASA·접촉을 적합도로: 전위는 서열이 다른 구조끼리 비교할 수 없다(M21 L2). 사용자가 점수 하나를 골랐다.
- 도킹 환경에 OpenMM 추가: 잠긴 도킹 환경이 바뀌어 M18 재현성·기존 결과 재사용을 다시 확인해야 한다. 자식 프로세스를 골랐다.
- 필요하면 M21·M18 수정 허용: 호출 키가 또 바뀌어 기존 결과의 자동 재사용이 끊긴다(M21 때처럼 수용하는 방식). 바이트 불변 우선을 골랐다.
- 개체 점수를 GA 요약에만 저장: '점수는 저장된 M18 결과의 값'이라는 원칙과 개체별 포즈·접촉 열람·재사용이 사라진다. 단독 M18 결과와 같은 handle을 골랐다.
- 모델링 단계 사이 반올림 대신 M21 허용오차 완화: M21 모듈 해시가 바뀌어 M21 호출 키가 달라진다.
- 모든 입력 오류를 기준 행에서: 단순하지만 단순한 입력 오류에도 예약분이 소모된다. 서버 부분 점검을 골랐다.
- 새 코드로 여러 변이를 PDBFixer에 한 번에 줌: M21의 안전 검사를 복제해야 한다. 연속 적용을 골랐다.
- 개체마다 SASA·접촉 표(M21 수준 전부): 개체가 최대 65개라 계산·저장·표시가 크게 는다. 모델 값만 골랐다.
- 1단위로 묶기(모델링 + 도킹을 평가 1건으로): 예산 표시가 실제 비싼 계산 두 번을 가린다.

## 결과
- 착수 확인(`docs/qa/m23-sequence-ga-20261005/preflight.txt`): 1UBQ에서 여러 곳 변이 11조합(k = 1–4, 인접 위치·사슬 양 끝 포함)이 반올림 규칙으로 변이 잔기 밖 원자 추가 0·좌표 변경 0으로 모델링되고 같은 입력은 바이트 동일(변이 한 개 평가 약 10초), 반올림이 없으면 8조합 모두 둘째 단계에서 `coordinates_changed`(최대 이동 4.29e-05–4.98e-05 Å). 모델링 자식 프로세스는 도킹 환경 프로세스에서 띄울 수 있고(프로젝트 인터프리터 경로를 `resolve()`하면 안 됨) 취소·시간 초과에서 빈 그룹까지 정리된다. 개체 모델링 mmCIF handle을 저장 전에 계산해 사이드카를 만들면 개체 도킹 결과가 단독 M18 작업 결과와 바이트 동일하다. 서버 쪽만의 M18 확장으로 기존 호출 키·읽기가 그대로(골든 호출 키 고정). 이벤트 로그 165 MB에서 개체마다 로그를 다시 읽으면 읽기 28.6–44.3초(스냅숏 3.0초).
- 변경하지 않은 파일(해시 대상): `docking_worker.py`, `docking_constants.py`, `openmm_mutation_worker.py`, `mutation_model_constants.py`, `mutation_model_math.py`, `mutation_candidates.py`, `ligand_ga_*`. 덧붙인 기존 코드는 명세 8절이 허용한 서버 쪽 두 곳(`docking_bundle.producer()`·`_mutation_receptor`, `docking_batch_inputs.published_m18_results`)과 등록 파일, 화면의 M21 입력 재사용을 위한 `MutationModelPanel.tsx`의 `PairInputs` 내보내기(명세 10절이 허용, 기본 입력에서 M21 마크업 불변)뿐이다. 기존 테스트는 M21 한 테스트(`test_mutation_model_worker.py`의 import 단언), 증액 호출자·목록 기대 테스트 셋, `report-library.test.cjs`의 단언 한 줄만 최소로 고쳤다.
- 하지 않게 된 것: 이어서 하기, 실행 간 개체 합치기, 세대마다 사람 승인, M13 연동, 개체별 SASA·접촉 표, 코어 고정 도킹, M17 후보 리간드 출처, 리간드·물·금속을 모델에 포함, 야생형 대비 차이·개선 표시, 위치·보호 잔기 변경.
