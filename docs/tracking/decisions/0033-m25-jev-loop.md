# 0033. M25 JEV 설계 루프는 게시된 후보 집합(M17 리간드·M20 변이) 하나에서 사람이 고른 풀 2–20개로 리간드·단백질 두 갈래에서 "JEV가 다음에 계산할 후보 하나를 고르고 사람이 그 계산을 승인하는 바퀴"를 반복 상한 1–8 안에서 되풀이하며, 바퀴마다 전송 승인(M24 경로 그대로)과 계산 시작 승인을 따로 받고, 목표 둘(탐색형·활용형)을 담은 고정 질문과 전송마다 기록된 seed로 섞은 순서를 쓰며, 계산은 기존 M18·M21 작업만, 새 한도 증액 경로 없이 run 예산을 M24 전송·뷰어와 함께 쓴다

- 상태: 채택 (사용자 결정 2026-10-07, M25 명세 확정 전 질문과 독립 점검 세 차례 뒤 묶음 확인에서 모두 추천안을 골랐다. 아래 "조율 세션이 정한 것"은 사용자가 최종 확인에서 바꿀 수 있다). 결정 0015(과학 데이터 전송 허용)·0032(M24 통로)의 다음 단계이고, 실호출 할당은 결정 0012대로 사용자가 정했다.

## 배경
M24는 게시된 후보 집합에서 고른 후보를 기준 없는 선택지형 질문으로 JEV에 보내 "JEV 판정(모델 선택)"을 제안으로 기록하는 통로까지 만들었다. 선택은 계산으로 이어지지 않았고(도킹·모델링 입력 넘기기 없음), 실호출 6회가 모두 목록 첫 후보였다(기준 문구 없음, 저장 순서 고정). 로드맵 M25는 "로컬이 후보를 만들고 JEV가 고르고 멈추는" 설계 루프를 리간드·단백질 두 갈래에 여는 단계다. 위험은 여섯 가지였다: 바퀴가 사람 승인 없이 이어지는 것(전송·계산 자동 시작), JEV의 선택이 순위·추천·예측으로 읽히는 것, 목록 순서가 선택을 끄는 것, 루프 때문에 한도 증액 경로가 늘어나는 것, 작업 큐의 같은 호출 키 처리(취소·재시도)와 루프 상태가 어긋나는 것, M24 투영·본문·감사·제안 바이트가 흔들리는 것.

## 결정 (사용자, 2026-10-07)
- **범위 = 리간드·단백질 두 갈래의 루프**, 소스는 게시된 M17 `ligand_candidate_set@1` 또는 M20 `mutation_candidate_set@1` 하나(두 집합 섞기 없음). 풀은 사람이 직접 고른 2–20개(리간드는 M17 필터 통과만)이고 시작 때 고정한다. run·갈래당 진행 중 루프 하나, 연습용 run에서는 만들 수 없다.
- **진행 = 바퀴마다 사람 승인 둘**: JEV로 나갈 본문을 미리 보고 승인하는 전송(M24 경로 그대로)과 고른 후보의 계산 시작 승인. JEV가 고른 후보도 사람이 승인해야 계산되고, 사람은 전송 없이도 후보를 직접 지정할 수 있다. 백그라운드·자동 다음 바퀴·자동 계산 시작은 없다. 한 바퀴의 첫 완료된(늦지 않은) JEV 응답이 그 바퀴의 선택이고 완료 뒤 다시 묻지 않는다.
- **목표 = 탐색형(`explore`)·활용형(`exploit`)**, 루프 시작 때 하나를 고르고 내내 고정한다. 입력은 고정 목표 문장 + 계산된 후보 표시이며 탐색형은 점수 없이(계산된 별칭만), 활용형은 저장된 qvina 점수를 함께 보낸다. 영어 지시문 원문 넷을 승인했다(최종 확인 때 탐색형 두 문장에서 점수 관련 부분을 빼고 계산된 별칭을 알리는 문장 E를 넣은 변경 포함).
- **순서 편향 = 전송마다 기록된 seed로 순서·별칭을 섞고(`sha256_order_v1`) 고른 목록 위치를 값으로 기록**한다. 같은 바퀴의 재전송도 새로 섞고 별칭은 전송마다 다시 매긴다. 섞기의 효과는 실호출 1회로 관찰값만 확인한다.
- **멈춤 = JEV에게 묻지 않는다**: 반복 상한(기본 5·최대 8), 예산, 후보 소진, 사람의 끝내기.
- **계산 = 기존 작업만**: 리간드는 단독 M18 자유 도킹, 단백질은 M21 `openmm_mutation_model_v1` → 그 변이 구조에 M18 자유 도킹을 사람이 차례로 시작(새 작업 모듈 없음, 야생형 기준 없음). 이미 저장된 같은 조건 결과는 계산된 것으로 친다(무과금). 실패·점수 없음도 계산됨이며 다시 고르지 않는다.
- **예산 = 새 증액 경로 없이 기존 run 예산 안에서**: 외부 토큰·USD·전송 10회·"사용량 모름" 중지 상태는 뷰어·M24 수동 전송과 공유한다(분리·루프당 상한 없음). 비싼 계산은 기존 작업 규칙(프로세스 직전 예약, 환불 없음, 재사용 무과금).
- **실행 기반 = 루프 전용 기록**(M13 흐름은 그대로, 연동 없음). **화면 = 리간드 설계·탐색 탭과 단백질 공학 탭에 각각**(지식·보고서 탭은 그대로, 루프 전송은 전송 기록의 읽기 전용 행).
- **범위 밖**: 기준선 비교, 진행 요약(지금까지 최저값·그래프), 최종 후보 표시·기록.
- **점검 뒤 사용자 결정**: 시작 전 취소된 후보는 새 상태 `unavailable`(계산됨으로도 반복으로도 세지 않고 JEV 본문에서 뺌), 단백질 바퀴의 `dock` 작업이 시작 전에 취소되면 후보 `not_run`·바퀴 끝, 후보 상태 우선순위(이 루프가 끝낸 바퀴의 결과 > 저장된 검증 결과(`reused`) > 같은 호출 키의 쓸 수 없는 작업(`unavailable`) > `pending`). 의도 감사 열네 항목(루프 전송의 지식 탭 읽기 전용 행, 지시문 원문, 탐색형 점수 미전송, 계산 상태 규칙, 예산 확인, 사람 지정·늦은 응답·섞기 단위, 자유 도킹만·바퀴마다 계산 시작 승인 이벤트·루프 영역 동의 표시·루프 제안은 새 객체 종류)도 추천안으로 확정했다.
- **실호출 합계 8회**(보정 1 + 리간드 활용형 3바퀴 + 단백질 활용형 3바퀴 + 섞기 확인 1, 리간드·단백질은 다른 run). 2026-10-07에 모두 썼다.

## 이유
- 바퀴마다 두 승인을 따로 받으면 외부로 나가는 바이트(미리보기 = 감사 = transport)와 비싼 계산 시작이 각각 사람의 기록된 동작에 묶이고, 동의·전송 승인이 계산 권한을 주거나 그 반대가 되는 일이 없다.
- 목표 문장과 계산 표시를 보내면 M24의 "기준 없는 질문"을 벗어나되 JEV가 새 후보를 쓰지 못하는 판정 API의 한계 안에 머문다. 탐색형에서 점수를 보내지 않아 점수 쪽으로 기우는 지시를 피한다.
- 전송마다 seed로 섞고 목록 위치를 값으로 남기면 순서 효과를 숨기지 않고 기록할 수 있다. 효과를 판정하지 않는다(LJ3).
- 계산을 기존 단독 작업으로만 하면 결과가 M18·M19·M21·M22와 같은 바이트·handle이 되어 재사용·검증·보고서가 그대로 이어지고, 해시 파일을 바꾸지 않아 기존 재사용이 끝나지 않는다.
- 증액 경로·외부 예산 분리를 만들지 않으면 예산 권한이 늘지 않고 M24·뷰어와 같은 멈춤 규칙이 그대로 적용된다.

## 검토한 대안 (기각, 되돌리지 말 것)
JEV에게 계속/멈춤 묻기, 한 번 승인 후 자동 진행·전송만 승인하고 계산 자동, 사용자 자유 입력 목표, 중립형(기준 없는) 목표, 순서를 뒤집어 두 번 보내 비교, 순서 그대로 두고 안내문만, 새 작업 하나로 모델링 + 도킹 묶기(M23 방식), 루프 전용 사람 증액 승인 경로, 외부 예산 분리·루프당 상한, M13에 목표 템플릿 추가, 지식·보고서 탭 한 곳 화면, JEV 대 규칙 기준선 비교·진행 요약(최저값·그래프)·최종 후보 표시, 한 바퀴 완료 후 다시 묻기, 풀 20개 초과.

## 한계
- JEV 판정은 계산 대기열에 먼저 둘 후보 하나일 뿐이며 그 선택이 좋다는 주장도, 루프가 더 나은 후보를 찾는다는 주장도 하지 않는다. 고른 이유는 알 수 없다.
- 실호출은 8회(리간드 run 5회, 단백질 1UBQ run 3회)뿐이고 공개·합성 표시 입력만 썼다. 섞기 확인은 1회 관찰이다.
- 단백질 루프는 M7 사전 검사를 통과하는 구조에서만 만들 수 있다(로컬 공개 구조 중 1UBQ뿐). 단백질 점수는 후보마다 다른 변이 구조에 도킹한 값이라 같은 수용체 안의 비교가 아니다(LJ7).
- 시작 전에 취소한 후보는 그 run에서 다시 계산할 수 없다(`unavailable`, 새 run에서는 된다).
- 외부 토큰은 늘릴 수 없어 후보 20개 단백질 루프는 run당 약 6번 전송이 한계다.

## 변경하려면 사용자 결정이 필요한 것
갈래·목표·풀 2–20·반복 상한 1–8·seed 범위, 후보·단계·바퀴 상태와 phase·action·축·끝 이유·`decided_by` 집합, 만들기·투영·루프 전송·계산·끝내기 거절 이유와 순서, 질문 id·지시문 넷·와이어 스키마·허용 필드·`values_note`, 섞기 알고리즘 `sha256_order_v1`, 고정 문장 LJ1–LJ8·UL1–UL3과 한계 문장 연결, 본문 64 KiB·객체 1 MiB 상한, 시작 전 취소 후보의 `unavailable` 처리, 새 한도 증액 경로나 외부 예산 분리, 새 실호출 할당. 작업 시간 한도 기본값·화면 반복 기본 5·단백질 cutoff 기본 4.0 Å·읽기 폴링 2초는 조정 가능한 기본값이다.
