# 0008. ProLIF를 해시 잠금된 별도 인터프리터 작업 프로세스로 실행

- 상태: 채택 (M11 설계, 2026-09-27)

## 배경
ProLIF 2.2.2는 RDKit, MDAnalysis 등 무거운 네이티브 의존성을 요구하고 gemmi ≥ 0.7.5가 필요하다. 서버는 이미 검증된 gemmi 0.7.5 파서에 의존한다. 서버 환경에 설치하면 파서 버전과 네이티브 라이브러리가 흔들릴 수 있다.

## 결정
`.deps/prolif/venv-locked`에 CPython 3.11 macOS arm64용 33개 wheel을 해시로 잠가 설치하고, 기존 작업 감독기로 실행한다. 서버와는 제한된 버전 JSON과 입력 바이트로만 주고받는다. 인터프리터 경로는 관리자 설정이며 요청으로 바꿀 수 없다.

## 검토한 대안
- 서버 `.venv`에 `backend[science]` 설치: 서버 파서 의존성과 충돌하거나 조용히 업그레이드될 위험이 있고, 네이티브 크래시가 API 프로세스를 죽일 수 있다.
- 런타임 자동 설치: 오프라인 원칙과 재현성에 어긋난다.

## 결과
- 현재 잠금은 macOS arm64 + CPython 3.11 전용이다. Linux 서버나 다른 아키텍처는 별도 잠금 파일과 검증이 필요하다.
- 작업 프로세스가 없으면 화학 기능만 사용할 수 없음으로 표시된다.
