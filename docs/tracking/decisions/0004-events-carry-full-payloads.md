# 0004. 이벤트가 객체 전체 payload를 담는다 (events-only 복구)

- 상태: 채택 (M0, 2026-09-24)

## 배경
참고 구현의 replay는 호출을 다시 실행했고, 원본 파일이 남아 있어야 했다. 이는 "이벤트만으로 복구"라는 요구와 맞지 않았고, 재계산 결과가 달라지면 과학 기록이 조용히 바뀔 수 있었다.

## 결정
`object_created` 이벤트에 객체 전체 바이트(필요하면 base64)와 메타데이터를 넣는다. 복구는 이벤트를 순서대로 읽어 객체와 SQLite 색인을 다시 만들고, 재계산하지 않는다. 객체 식별자는 SHA-256 전체 길이를 쓴다.

## 검토한 대안
- 이벤트에는 참조만 두고 객체는 별도 blob 저장소에 두기: 로그는 작아지지만, blob을 잃으면 복구할 수 없다. 원자적 기록 순서도 더 복잡해진다.
- 재계산 replay: 원본 입력과 엔진이 필요하고, 엔진 버전이 바뀌면 결과가 달라진다.

## 결과
- 이벤트 로그가 커진다. PNG는 run당 원본 64 MiB(이벤트 약 86 MiB)로 제한했다.
- 큰 궤적이나 대용량 데이터는 이 방식으로 다룰 수 없다. 도입하려면 blob과 복구 방식을 다시 설계해야 한다.
- 이벤트 로그를 자르거나 객체를 그 자리에서 지우는 방식으로는 공간을 확보할 수 없다. run 전체를 보관 위치로 옮기는 방법만 있다.
