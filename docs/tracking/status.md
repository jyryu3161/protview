# 진행 현황

기준: 2026-10-14(기록 초안, 게이트·수락은 2026-10-13 UTC), 브랜치 `dryforge/m29-structure-repair`(`phase/m29-structure-repair` = main `3c5994e4`에서 분기). M28까지 main에 병합됨(M28 병합 `651ea72`, 병합 해시 기록 `3c5994e4`). M29(구조 보완)의 판정은 `검증 통과, 사용자 확인 대기`다(기록 초안. 소스 고정 `52aa4265`, 증거 `docs/qa/m29-repair-20261013/`, 기록 `docs/tracking/m29-acceptance.md`, 결정 0037). 독립 증거·기록 검토(T19)와 그 반영(T20)이 남았고(회귀 사슬 T16은 통과), 판정 문구는 사용자가 확인한 뒤에만 바뀐다. M29의 외부 요청은 사용자가 허용한 RCSB 공개 구조 내려받기 5회(8VF6 1회, 1RNH·4INS·1AY7·1CLL 각 1회)뿐이고 실제 JEV 호출은 0이다. M28(종단 검증과 마감)의 판정은 `완성(범위 명시)`다(사용자 확인 2026-10-12, main 병합 `651ea72`, 확인 전에는 `검증 통과, 사용자 확인 대기`였다. 소스 고정 `a18dd488`, 증거 `docs/qa/m28-final-20261011/`, 기록 `docs/tracking/m28-acceptance.md`, 결정 0036). 독립 증거·기록 검토(T19)의 지적은 T20에서 모두 반영했고 같은 검토자 둘이 읽기 전용으로 재확인해 `approved`를 받았고, 사용자가 확인한 뒤에 판정 문구를 바꿨다. M28의 외부 요청은 사용자가 정한 실제 JEV 호출 2회(둘 다 `completed`, 할당 소진)와 새 컴퓨터 설치 시험의 패키지 저장소 내려받기뿐이다.

1. **M29 마무리**: 판정은 `검증 통과, 사용자 확인 대기`다(기록 초안, `docs/tracking/m29-acceptance.md`). 남은 일은 독립 증거·기록 검토(T19)와 그 반영(T20), 사용자 확인(확인 뒤에만 메인 세션이 판정 줄을 바꾼다)이고, 병합은 사용자가 요청할 때만 한다. 결정 0037의 "조율 세션이 정한 것"(사용자 선택이 아님)은 최종 보고에서 이의를 받는다. M29는 실제 JEV 호출을 하지 않았고 이후 외부 요청은 사용자가 새로 정해 줄 때만 한다.
2. **후속 결정 후보(M29에서 나온 것)**: (a) **M21 시간 상한**(`mutation_model_constants.py`의 120/240초, 호출 키 해시 파일): 보완 뒤 단백질 중원자 약 2,100을 넘는 구조(8VF6·1M17·1A4I)는 M21 작업이 끝나지 않는다(8VF6 M21 한 번 관측, 나머지는 T1 측정에서 옮긴 값). 그 M21 작업을 쓰는 M25 단백질 루프 계산·M21 수용체 출처 도킹도 같은 한계로 보지만 관측하지 않았다. M29에서는 사용자 결정으로 유지했고, 올리면 M21·M23 호출 키·골든 재기록과 옛 결과 재사용 끝이 따르며 8VF6은 M21 작업 하나(구조 둘)에 17분 이상이다(M23 개체 모델링은 구조 하나라 측정하지 않았다)(`docs/tracking/findings.md` 절 139). (b) **guardian 신호 순서 경합**: guardian이 그룹 구성원에게 pid 순서로 SIGTERM을 보내므로 pid가 한 바퀴 돈 뒤 qvina2가 작업 모듈보다 먼저 신호를 받으면 사용자가 취소한 행이 드물게 `engine_failed`로 기록된다. 고칠 자리는 `jobs/guardian.py`(호출 키 해시 파일 아님, 모든 작업이 씀)나 `docking_worker.py`(해시 파일)다(절 141). (c) **Next.js 프록시 시간 제한**: 긴 동기 작업 시작(M21 약 2분, 큰 구조의 보완)이 rewrite 프록시의 기본 30초에 끊겨 브라우저에 500이 보인다(작업은 계속되고 화면은 저장된 작업을 읽어 복구, M29 전부터의 동작). 프록시 시간 제한(`frontend/next.config.mjs`)을 늘릴지, 시작 응답을 작업이 끝나기 전에 돌려줄지 정한다(절 142). 그 밖의 M29 `사용자 결정 필요` 절(140·143–146)도 같은 목록이다.
3. **M28 마무리**: 판정은 `완성(범위 명시)`다(사용자 확인 2026-10-12, `docs/tracking/m28-acceptance.md`). 독립 증거·기록 검토(T19)와 그 반영(T20)은 끝났다. 사용자가 확인해 메인 세션이 기록·이 문서·로드맵 M28 행·`CLAUDE.md`·`AGENTS.md`의 판정 줄을 한 커밋에서 바꿨다. 단계 브랜치는 main에 병합했다(`651ea72`, 사용자가 "확인 뒤 main에 병합"으로 정해 로컬 병합만 했고 push하지 않았다). 남은 일은 없다. 해석 메모 N1–N14(특히 `사용자 결정 필요` 85개와 `보류` (b)의 관계 N10)는 사용자가 받아들였다. 실제 JEV 호출 할당 2회는 모두 썼고 이후 실호출·외부 요청은 사용자가 새로 정해 줄 때만 한다.
4. **단계별 범위(참고)**: M29(구조 보완, 기록 초안)는 사용자가 요청한 전처리 구조에서 승인된 결손 다섯 종류만 PDBFixer로 채운 보완 구조를 모델링 경로(M20 → M21·M23·M24·M25, M21 수용체 출처 M18)에서만 쓰게 하고 하류 화면·읽기·보고서에 "보완 구조 기준"을 드러내는 데까지다(결정 0037: 틈은 내부 1–20잔기만, 비표준 잔기는 MSE→MET만, 체인 조각은 이름 그대로 합침, 충돌은 기록만, 뷰어 표시 없음, M20은 원본 구조 기준 참조 결과를 잔기 식별자로 인계, JEV 전송은 경고(JW1)만 더함). 보완 구조는 실험 구조가 아니고 추가 원자는 PDBFixer가 만든 모델링 좌표이며, 보완 구조에서 나온 전위·SASA·접촉·qvina 값은 실험 구조의 값이 아니다. 보완 뒤 단백질 중원자 약 2,100을 넘는 구조의 M21은 시간 상한 안에 끝나지 않는다. M13 흐름은 보완 구조를 계획 라우트 입구에서 거절한다. M27(kinase 전례·문헌 연결)은 사용자가 실행하는 가져오기 명령 하나가 로컬 `kbase_kinase` 체크아웃의 커밋된 `dist/` 세 파일과 `ref/pubmed` 최신 서지 스냅샷을 네트워크 없이 바이트 그대로 복사한 참조 스냅샷으로, M15 번호 대응 체인의 표적(UniProt accession 하나 + mapped 잔기 1개 이상)과 같은 표적의 전례를 출처·검사 상태와 함께 보이고 보고서에 출처 목록으로 남기는 데까지다(결정 0035: 같은 표적만, 표적 미해석 전례는 연결하지 않고 세트 전체 수로 안내, `moves_flagged`는 기본 제외·포함 선택과 별도 미포함 수, ProtView 무결성 확인과 kbase 기계 검사 분리, 원문 대조·문헌 색인·뷰어 표시·전이 가설·M17/M19 연결 없음). 전례는 kbase가 논문에서 기계로 추출한 미검수 기록이며 ProtView의 판정이 아니고, 방향·크기는 kbase 규칙 v1 산출값이며, 개수·목록 순서는 순위·추천·유망도·성공률이 아니다. "전례 기록 없음"은 포함한 파일에 기록이 없다는 뜻이고 선행 연구가 없다는 뜻이 아니다. M27은 M13 흐름과 연동하지 않았고 M24·M25 전송에 전례를 보내지 않는다. M26(효소 반응 지식 연결)은 사용자가 실행하는 가져오기 명령 하나가 공개 서버 셋(M-CSA·UniProt·Rhea)에서 받은 가공 참조 스냅샷으로 구조 잔기에 촉매 잔기·UniProt 부위·반응 정보를 참조값으로 붙이고, M-CSA와 PDB·체인·번호·잔기 이름이 모두 같은 "대응됨" 행을 M20 v2 후보 집합의 기본 보호 근거로 쓰는 데까지다(다루지 않은 체인은 검사하지 않음, `checked`는 위치를 가진 모든 체인이 `covered`일 때만, UniProt 부위는 보호에 쓰지 않음, 뷰어 표시 없음). 참조값은 ProtView의 판정이 아니며 "대응됨"은 역할·활성을 뜻하지 않고 반응 정보는 활성·속도·특이성·메커니즘 유지의 근거가 아니다. M26은 M13 흐름과 연동하지 않았고 M24·M25 전송에 M26 자료를 새로 보내지 않는다. M25(JEV 설계 루프)는 게시된 후보 집합(M17·M20) 하나에서 사람이 고른 풀(2–20)로 리간드·단백질 두 갈래에서 "JEV가 다음에 계산할 후보 하나를 고르고 사람이 그 계산을 승인하는 바퀴"를 반복 상한 안에서 되풀이하는 데까지다(바퀴마다 전송 승인 + 계산 시작 승인, 목표 탐색형·활용형, 전송마다 seed로 섞은 순서, 계산은 기존 M18·M21 작업만, 새 증액 경로 없음, 실호출 8회 소진). JEV 판정은 계산 대기열에 먼저 둘 후보 하나일 뿐이며 루프는 선택이 좋다거나 더 나은 후보를 찾는다고 말하지 않고 기준선 비교·진행 요약·최종 후보 표시가 없다. 목록 위치는 관찰값이다(섞기 확인 1회에서 두 번 모두 위치 1, 효과 근거 아님). M25는 M13 흐름과 연동하지 않았다. M24(JEV 과학 데이터 전송 통로)는 게시된 후보 집합(M17·M20)에서 고른 후보를 선택지형 질문으로 JEV에 보내 "JEV 판정(모델 선택)"을 제안으로 기록하는 통로까지다(전송마다 본문 해시 승인 + run 수준 별도 동의, 외부 토큰·USD 예약, 실호출 6회 소진). 선택은 순위·추천·예측이 아니고 도킹·모델링으로 자동 이어지지 않으며(M25는 사람이 계산 시작을 승인할 때만 잇는다), 기준 문구가 없는 질문에서 6회 응답이 모두 목록 첫 후보였다. 리간드 쪽은 M22로 게시된 M17 후보 집합 안에서 GA가 세대마다 도킹할 후보를 고르는 탐색까지, 단백질 공학 쪽은 M23으로 게시된 M20 후보 집합의 다중 변이 조합을 GA가 세대마다 모델링(PDBFixer + OpenMM)·도킹해 qvina 점수 순서로 고르는 탐색까지 왔다(개체 점수 = 변이 구조에 사용자 SDF 리간드를 자유 도킹한 qvina 점수, 야생형 기준 행은 값만 보이는 참고 행, 시작 전 예약 단위·재사용 무과금·사람 증액 경로·닫힌 종료 이유·S 문장 방식). GA는 점수 정렬·선택 표시를 순위·추천·개선·변이 효과로 말하지 않고 서열이 다른 구조의 OpenMM 전위를 비교하지 않는다. M13 흐름의 계획·승인·한 단계 진행·중지·복구는 그대로이고, M22·M23·M25는 M13과 연동하지 않았다(M25는 사용자 결정으로 루프 전용 기록을 쓴다, 결정 0033).
5. **공용화 이어서**: 소스·저장 보기·작업·계획 패널 공용화는 그것을 처음 필요로 하는 탭 단계에서 한다(결정 0021). 다른 탭 알림·run 전체 작업 목록은 M28에서 범위 밖으로 기록했다(사용자 결정 ③, 새 기능 없음). 하려면 새 단계로 정한다(M17–M27은 새 공용 구성 요소를 만들지 않았다. M27은 지식·보고서 탭에 `KinasePrecedentsPanel` 하나를 효소 반응 지식 영역과 JEV 판정 영역 사이에 더하고 기존 번호 대응 목록 읽기(`lib/numbering.ts`)를 가져다 쓴다. M26은 지식·보고서 탭에 `ReactionKnowledgePanel` 하나를 더하고 후보 집합을 고르는 다섯 곳(M20 목록·M21·M23·M24·M25)이 `lib/mutations.ts`의 순수 함수 `catalyticBadge` 하나로 같은 "촉매 잔기 검사 안 함" 표시를 쓴다. M25는 리간드·단백질 탭의 `JevLoopPanel` 하나를 두 갈래가 함께 쓰고 M17 `FilterForm`·M21 `PairInputs`·M18 `lib/docking.ts`·M24 `lib/jev.ts`의 순수 함수를 그대로 가져다 쓰며, M24 `JevPanel`에는 전송 기록의 루프 행 표시 prop 하나만 더했다. M24는 지식·보고서 탭 안에서 M17 `FilterForm`을 그대로 가져다 쓰고 전역 줄에 "과학 전송 허용" 표시만 더했다. M23은 단백질 공학 탭 안에서 M18 순수 입력 로직(`lib/docking.ts`)과 M21 `PairInputs`(`MutationModelPanel.tsx`에서 export)를 그대로 가져다 쓴다. M22는 리간드 탭 안에서 M17 `FilterForm`·M18 `RefusalList`·`lib/docking.ts` 입력 로직을 그대로 가져다 쓴다. M21은 M18 순수 입력 로직(`lib/docking.ts`, `dockingConditionArgs` 추출)을 같은 조건 도킹에 다시 쓴다. M20은 기존 목록 읽기(포켓·번호 대응·주석)와 `decimalHalfUp`을 가져다 쓴다. M19는 리간드 탭 안에서 M17 `FilterForm`과 M18 `RefusalList`를 export해 함께 쓴다).
6. **미해결 문제**: M28에서 `docs/tracking/findings.md`의 137절 모두가 최종 분류를 하나씩 받았다(해결 14·수용 33·사용자 결정 필요 85·범위 밖 5, 맨 위 요약 표와 `docs/qa/m28-final-20261011/findings-triage.md`). `사용자 결정 필요` 85개(본문 근거 24 = 닫힌 집합·해시 고정 파일·한도·저장 형식·명세 동작을 바꿔야 하는 것, 기본값 61 = 관찰 공백·읽기 성능·작업 경계·화면 작은 결함·참조 세트 운영·코드 정리 등)는 고칠지·언제 할지를 사용자가 정한다. `범위 밖` 5절은 Linux·Intel Mac용 작업 환경 잠금(절 8), 외부 구조 새로 받기·실제 결합 맥락의 변이 도킹이 필요한 것(절 75·86·121), 다른 탭 알림(절 122)이다(명세 §11.3의 한 줄 정의보다 넓게 명세 §1의 범위 밖 목록에 근거한 해석, 기록의 N13).
