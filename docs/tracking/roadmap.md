# 전체 로드맵 (M12 이후)

기준: 2026-09-29 사용자 결정. M12와 M13은 기존 설계대로 유지하고, 그 뒤 단계를 작게 나눠 늘린다. 각 단계의 세부 구현(엔진 버전, 스키마, 파라미터 기본값, 화면)은 그 단계를 시작할 때 사용자와 함께 정한다. 이 표는 순서와 범위의 약속이지 구현 명세가 아니다. 배경 분석·출처·라이선스 조사·결정 후보 전체는 `docs/tracking/roadmap-analysis-20260929.md`에 있다.

## 완성의 정의

탭 네 개가 각자 제 일을 하고, 아래가 실제 데이터로 한 번 끝까지 돌아가 검토를 통과하면 완성이다.
1. **구조 분석**: 구조를 열어 부위·상호작용·표면·공동을 로컬 계산으로 보고 논문용 그림을 낸다.
2. **지식**: 그 부위가 계열 지식(kinase·enzyme·GPCR 순서 후보)에서 무엇인지 잔기 단위로 확인한다.
3. **리간드 설계·탐색**: 바꿀 부위·building block·reaction rule로 후보를 만들고 필터·도킹으로 점수 표를 낸다.
4. **단백질 공학**: 촉매·보호 잔기를 지킨 채 변이 후보를 만들고 변이 구조를 모델링·평가한다.
5. 3·4에서 GA 설계와 JEV 설계를 각각 파라미터를 바꿔 가며 예산·승인 안에서 돌린다.
6. 모든 수치는 handle·필드·단위로, 모든 인용은 출처·버전으로 역추적되는 보고서를 얻는다.

## 단계 (M13 이후 15단계, M13 포함 16단계)

| 단계 | 탭 | 목표 | 여는 시나리오 | 선행 |
|---|---|---|---|---|
| M13 | 구조 분석 | 결정적 로컬 분석 흐름(기존 설계 그대로): 분석 목표 템플릿, 계획 미리보기, 계획 승인과 계산 승인 분리, 단계 실행·취소·복구 | 반복 분석의 기반 | M12 |
| M14 | 전체 | 탭 4개 골격(구조 분석 / 단백질 공학 / 리간드 설계·탐색 / 지식·보고서), 기존 화면 이관, 공용 구성 요소(소스·보기·작업·보고서). 완료: 공용화는 run·예산·보고서 목록만, 나머지는 결정 0021 | 모든 시나리오의 화면 전제 | M13 |

| M16 | 구조 분석·지식 | 참조 주석 표시(예: hinge 잔기), 상호작용 강조, 고해상도 그림 내보내기 검토 | kinase hinge 상호작용 논문용 시각화 | M15 |
| M17 | 리간드 | 리간드에서 바꿀 부위 지정, reaction rule·building block으로 후보 생성, 필터(속성·PAINS 등) | 부분 교체 후보 만들기 | M14 |
| M18 | 리간드 | 도킹 엔진 격리 설치·버전·seed 고정, 단일 리간드 도킹(코어 고정/자유), 포즈·점수·상호작용 표 | 리간드 배치와 점수 | M17 |
| M19 | 리간드 | 후보 일괄 도킹, 결과표·비교·보고서, 후보 수·시간 상한 | building block 교체 설계, 여러 리간드 비교 | M18 |
| M20 | 단백질 | 변이 후보 생성: 포켓 주변 위치 × 허용 잔기, 촉매·보호 잔기 기본 제외 | 포켓 잔기 변이 스캔 | M15 |
| M21 | 단백질 | 변이 구조 모델링(PDBFixer+OpenMM 경로)과 전후 비교(접촉·SASA·기질 재채점, 에너지는 엔진 이름 그대로) | 기질 결합을 위한 서열 변경(로컬) | M20, M18 |
| M22 | 리간드 | GA 설계 엔진(리간드 공간)과 파라미터 편집 화면·가드, seed·세대 기록 | GA 기반 리간드 설계 | M19 |
| M23 | 단백질 | GA 설계를 서열 공간에 적용 | GA 기반 서열 설계 | M22, M21 |
| M24 | 전체 | JEV 과학 데이터 전송 통로: 보낼 내용 스키마, 전송 전 미리보기, 감사 기록, 예산 | JEV 사용의 전제 | M14 |
| M25 | 리간드·단백질 | JEV 설계 루프(두 갈래 공통): 로컬이 후보를 만들고 JEV가 고르고 멈춘다. 반복·예산 상한, 제안과 계산 분리 기록 | JEV 기반 리간드·서열 설계 | M24, M22, M23 |
| M26 | 지식 | 효소 반응 지식 연결(M-CSA 촉매 잔기, Rhea·UniProt 반응 주석) | 반응 정보를 보며 효소 서열 변경 | M15 |
| M27 | 지식 | kinase 전례·문헌 연결(`kbase_kinase` 읽기 전용, 인용 검증), 필요하면 문헌 검색 색인 | 전례·문헌 근거 보기 | M15, M19 |
| M28 | 전체 | 종단 검증과 마감: 완성 정의 전체를 실제 데이터로, 오프스크린 QA 전량, 문서·미해결 문제 정리 | 완성 | 전부 |

병행 가능: M15는 M14 뒤 리간드 쪽(M17–M19)과 나란히 갈 수 있다. M24는 M14 뒤 언제든 시작할 수 있지만, 루프 안전장치를 외부 요청 없이 먼저 검증하도록 GA(M22) 뒤를 권장한다.

## 하지 않는 것 (정직하게 할 수 없거나 범위 밖)

- 친화도·ΔΔG·안정성 주장(검증된 엔진 없이). 도킹 점수는 "Vina 점수, 친화도 아님"처럼 엔진 이름으로만 부른다.
- 지금 연결된 JEV 판정 API로 SMILES·서열을 직접 생성하는 것(후보는 로컬 엔진이 만들고 JEV는 고른다). 자유 생성 모델 추가는 별도 결정이다.
- 효소 활성(kcat·kM)·특이성 향상 주장, "합성 가능" 판정.
- 복합체 OpenMM·MD·자유 에너지, 수만 규모 스크리닝, 실행 중 원격 DB 조회, 사람 승인 없는 무인 자율 실행.
- 다중 사용자·인증·공유 서버, 외부 공개, 플러그인 SDK, GUI 파이프라인 편집.

## 단계별로 그때 정할 주요 결정

- M14: 탭 구성 확정(4탭 권장).
- M15: 첫 계열(kinase 권장), 참조 출처와 라이선스 범위.
- M16: 고해상도 그림 상한을 올릴지.
- M17: reaction rule·building block 출처(사용자 정의·사용자 SDF부터 권장), 생성 상한.
- M18: 도킹 엔진(Vina 권장), 점수 표시 문구.
- M20–M21: 보호 잔기 기본 정책, FoldX 사용 여부, 로컬 모델 가중치(ProteinMPNN·ESM) 허용.
- M22: GA 기본 파라미터와 상한, 다목적 방식.
- M24–M25: JEV에 보낼 범위, 실제 호출 할당, 루프 반복·예산 상한.
- M27: `kbase_kinase` 사용 허용 범위(현재 `docs/standards.md`가 과학 데이터 사용을 막고 있음).
- ODDT: 쓰려면 격리 환경에서 현재 고정 버전과의 호환성부터 실제로 확인(유지 보수가 2021년에 멈춤). 필요해지는 단계에서 결정.
