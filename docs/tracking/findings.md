# 미해결 문제

## 과거 단계 재검증이 대부분 오래된 검토로 판정된다
- **현상**: 현재 작업 트리에서 `scripts/execute.py <phase> --verify`를 실행하면, `README.md` 해시가 검토 당시와 달라 protview-mvp(step5), protview-methods(step0·1), protview-agent-ui, protview-scenes, protview-comparison이 오래된 검토로 판정된다. protview-methods는 `AGENTS.md`와 `docs/ARCHITECTURE.md`도 이미 불일치다. 새로 쓴 `AGENTS.md` 때문에 protview-agent-ui도 추가로 불일치가 된다.
- **영향**: 끝난 단계를 "현재 해시 기준으로 검증됨"이라고 주장할 수 없다. 기능 자체의 회귀 여부는 전체 테스트 게이트로 따로 확인해야 한다.
- **지금 해결하지 못하는 이유**: 검토 해시를 고치면 과거 증거를 위조하는 것이다. 제대로 해결하려면 현재 공유 소스에 대한 새 통합 검토가 필요한데, 이는 M11 완료 게이트의 일부다.
- **방향**: M11 검토에서 바뀐 공유 파일(README, AGENTS.md, app.py, queue.py 등)과 M8–M10 회귀를 명시적으로 다시 검증하고, 대체한 과거 범위를 기록한다.

## M11 오프스크린 QA 입력이 `/tmp`에 있다
- **현상**: M11 오프스크린 QA 계획 문서의 실행 안내(`create`·`attach` 모드 입력과 replay helper)가 `/tmp/protview-m11-qa-20260927/` 아래 파일(수용체·SDF·매핑 JSON·`replay_probe.py`)을 가리킨다. `chemical-flow.cjs` 자체에는 사용법 예시 경로만 있다. 재부팅하거나 임시 파일이 정리되면 사라진다.
- **영향**: M11 QA를 다시 돌릴 수 없고, 남은 모드(attach, empty, faults, replay)를 검증할 수 없다.
- **지금 해결하지 못하는 이유**: 해당 파일 일부는 부모 세션이 만든 run(`run_e665f09046f644229e00a06e887f7d86`)에 묶인 매핑이다. 어떤 파일을 저장소 fixture로 옮길지는 M11 구현 작업 안에서 결정해야 한다.
- **방향**: 공개 fixture와 해시가 같은 입력은 `backend/tests/fixtures/chemical/`의 기존 파일로 대체한다. run에 묶인 매핑은 QA 스크립트가 직접 만들게 한다.

## 접촉 행 초점 직후 "camera still moving" 오류
- **현상**: M11 Release2 오프스크린 실행에서 회전·표현 변경 직후 바로 행 초점을 누르면 사용자에게 "camera still moving" 오류가 보였다. 카메라가 멈출 때까지 기다린 실행은 통과했다.
- **영향**: 사용자가 빠르게 조작하면 초점 명령이 실패한 것처럼 보인다. 과학 결과에는 영향이 없다.
- **지금 해결하지 못하는 이유**: 네이티브 초점 대기에 상한을 두는 수정은 M11 UI 작업 범위에 들어 있고, 공유 MolstarViewer 브리지를 바꾸므로 M8–M10 회귀를 함께 돌려야 한다.
- **방향**: 초점 요청을 카메라 정지까지 제한 시간 안에서 기다리게 하고, 시간을 넘기면 재시도 가능한 오류로 표시한다.

## M11 스타일이 생성된 복사본에만 있다
- **현상**: 커밋되지 않은 M11 작업이 `frontend/src/design/components.css`(생성된 복사본)에 19줄을 추가했지만, 원본 `design/components.css`는 바뀌지 않았다.
- **영향**: 누군가 `npm --prefix frontend run tokens`를 실행하면 M11 화학 화면 스타일이 사라진다.
- **지금 해결하지 못하는 이유**: M11 코드 변경이라 M11 작업 안에서 처리해야 한다.
- **방향**: 추가한 19줄을 원본으로 옮기고 tokens를 다시 실행해 복사본과 같은지 확인한다.

## 옛 Claude 명령이 GPT 역할을 전제로 한다
- **현상**: `.claude/commands/harness.md`와 `review.md`가 "GPT-6 Sol implements; GPT-6 Astra reviews"와 `execute.py --record-review`를 안내한다. `/harness`, `/review`로 실행하면 새 흐름과 충돌하는 절차를 따르게 된다.
- **영향**: 에이전트가 기록 불가능한 실행기 절차를 시도하거나, 검토자 모델 이름을 잘못 기록할 수 있다.
- **지금 해결하지 못하는 이유**: 명령 설정을 삭제할지 새 흐름용으로 다시 쓸지는 사용자가 정해야 한다.
- **방향**: 삭제하거나, 새 역할 구조에 맞게 다시 쓴다.

## 공유 서버 사용을 막는 장치가 없다
- **현상**: 백엔드는 인증 없이 `127.0.0.1:8000`에서 열린다. 여러 사람이 계정을 가진 서버에서 실행하면, 다른 계정도 모든 run의 구조·보고서를 읽고 계산을 실행할 수 있다.
- **영향**: 미공개 구조가 같은 서버의 다른 사용자에게 노출될 수 있다.
- **지금 해결하지 못하는 이유**: 현재 사용 방식은 인스턴스당 한 사람(서버도 혼자 사용)으로 정했다. 인증과 run 소유권은 설계되지 않았다.
- **방향**: 공유 서버나 외부 공개가 필요해지면 인증, 사용자별 runs 루트, 포트 격리를 설계한다.

## ProLIF 작업 프로세스가 macOS arm64 전용이다
- **현상**: `config/chemical/`의 잠금 파일과 `setup_prolif_worker.py`가 CPython 3.11 macOS arm64만 허용한다.
- **영향**: Linux 서버에 설치한 인스턴스에서는 M11 화학 기능을 쓸 수 없다.
- **지금 해결하지 못하는 이유**: 다른 플랫폼 wheel 조합을 조사하고 해시 잠금·검증을 새로 해야 한다.
- **방향**: Linux x86_64용 잠금 파일과 설치 경로를 따로 만들고, 같은 네이티브 테스트로 검증한다.

## Host 헤더 검증이 없다
- **현상**: 백엔드에 Host 헤더 확인(신뢰 호스트 목록)이 없다. 사용자가 브라우저로 악성 웹 페이지를 열면, 그 페이지가 DNS 리바인딩으로 `127.0.0.1:8000` API에 요청을 보낼 수 있다.
- **영향**: 인증이 없으므로 그런 페이지가 run 데이터를 읽거나 계산을 시작할 수 있다. loopback 바인딩만으로는 막을 수 없다.
- **지금 해결하지 못하는 이유**: 대응 방식(허용 Host 목록, Origin 확인, 로컬 토큰)을 정해야 하고, 백엔드·프록시·오프스크린 QA 설정을 함께 바꿔야 한다.
- **방향**: `127.0.0.1`/`localhost` Host만 허용하는 미들웨어를 추가하고, 프런트엔드 프록시와 QA 경로가 계속 동작하는지 확인한다.
