# 미해결 문제

## 과거 단계 재검증이 대부분 오래된 검토로 판정된다
- **현상**: `scripts/execute.py <phase> --verify`를 실행하면 공유 파일(README.md, AGENTS.md, `docs/ARCHITECTURE.md` 등) 해시가 검토 당시와 달라 M0–M10 단계 대부분이 오래된 검토로 판정된다. M11이 공유 소스(app.py, queue.py, guardian.py, MolstarViewer.tsx, page.tsx 등)를 더 바꿨으므로 이 상태는 계속된다.
- **영향**: 끝난 단계를 "과거 검토 해시 기준으로 검증됨"이라고 주장할 수 없다.
- **지금 해결하지 못하는 이유**: 검토 해시를 고치면 과거 증거를 위조하는 것이다.
- **현재 상태**: M11 완료 검토가 바뀐 공유 소스와 M8·M9·M10 회귀를 현재 기준으로 다시 확인했다(`docs/tracking/m11-acceptance.md`의 "대체한 과거 검증 범위"). 과거 기록은 그대로 둔다.

## :3000에 Host 헤더가 두 개면 검사를 지나간다
- **현상**: `Host: 127.0.0.1:3000` 다음에 외부 Host를 보내면 200이 나오고 `/api` 요청이 백엔드까지 간다.
- **영향**: Host를 두 개 보낼 수 있는 로컬 프로그램은 프런트엔드 Host 검사를 피할 수 있다. 브라우저는 Host를 하나만 보내므로 DNS 리바인딩 방어에는 영향이 없다.
- **지금 해결하지 못하는 이유**: 사용자 결정(2026-09-28)으로 알려진 한계로 둔다. 막으려면 Next를 자체 Node 서버로 띄워 원시 헤더를 검사해야 한다.
- **방향**: 공유 사용이나 외부 공개를 검토할 때 함께 다룬다. 증거: `docs/qa/m11-chemical-20260928/host-check.json`, 결정 0013.

## 이벤트 로그를 읽을 때마다 전체를 다시 파싱한다
- **현상**: 작업 상태 읽기와 이벤트 추가가 run의 `events.jsonl` 전체를 다시 파싱한다. M11 작업 기록이 커서(작업당 수 MB) 한 번에 약 0.3초 CPU가 든다.
- **영향**: 정확성 문제는 아니지만, 화학 작업이 많은 run에서 폴링과 작업 시작이 느려진다.
- **지금 해결하지 못하는 이유**: `core/events.py`의 읽기 구조를 바꾸는 일로 M11 범위 밖이다. 이벤트 형식은 바꾸지 않아야 한다.
- **방향**: 추가 전용 로그의 오프셋 기반 증분 읽기를 설계하고 events-only 복구 테스트로 확인한다.

## GO 전에 guardian이 끝나면 작업이 running으로 남는다
- **현상**: guardian이 GO를 받기 전에 끝나면(상한 초과 등) 작업은 `guardian_result_missing`과 함께 running으로 보이다가, 백엔드를 다시 시작해야 interrupted로 정리된다.
- **영향**: GO 대기 상한을 작업 시간에 맞춘 뒤로는 드물지만, 생기면 사용자가 재시작해야 한다.
- **지금 해결하지 못하는 이유**: 부모 쪽 즉시 정리 경로는 작업 수명 주기 전체를 다시 검증해야 하는 변경이다.
- **방향**: guardian 종료를 부모가 감지하면 과학 작업 없이 끝난 시도를 typed 실패로 기록하는 경로를 추가하고 실제 프로세스 테스트로 확인한다.

## 긴 작업 시작 응답 복구가 브라우저로 검증되지 않았다
- **현상**: 시작 요청이 Next 프록시의 30초를 넘겨 500을 받은 뒤 실제 작업 상태를 다시 읽어 보여 주는 경로(`chemicalStartProgressed`)는 단위 테스트로만 확인했다. 수락 QA의 시작 요청은 모두 30초 안에 끝났다.
- **영향**: 큰 수용체에서 실제로 이 경로를 탈 때의 화면은 관찰하지 않았다.
- **방향**: 표시된 지연 fixture로 30초를 넘기는 오프스크린 사례를 추가한다.

## M11 사례 대장의 증거 형식이 고르지 않다
- **현상**: 회귀 행 5개에 offscreen·WebGL 요약과 fixture 출처가 행 안에 없고(흐름 jsonl에만 있다), 모든 단계의 `paint-first.png`가 0바이트다(실제 paint 증거는 `baseline.paint.png`와 이후 프레임). attach-setup 행에는 파일별 출처 라벨이 없다.
- **영향**: 증거 자체는 유효하지만(독립 증거 검토 승인), 대장만 읽는 사람이 오해할 수 있다.
- **방향**: 다음 QA 전에 `m11-ledger.cjs`와 `main.cjs`의 첫 paint 저장을 고친다. 고정된 2026-09-28 증거는 바꾸지 않는다.

## 공유 서버 사용을 막는 장치가 없다
- **현상**: 백엔드는 인증 없이 `127.0.0.1:8000`에서 열린다. 여러 사람이 계정을 가진 서버에서 실행하면, 다른 계정도 모든 run의 구조·보고서를 읽고 계산을 실행할 수 있다.
- **영향**: 미공개 구조가 같은 서버의 다른 사용자에게 노출될 수 있다.
- **지금 해결하지 못하는 이유**: 현재 사용 방식은 인스턴스당 한 사람(서버도 혼자 사용)으로 정했다. 인증과 run 소유권은 설계되지 않았다.
- **방향**: 공유 서버나 외부 공개가 필요해지면 인증, 사용자별 runs 루트, 포트 격리를 설계한다.

## ProLIF 작업 프로세스가 macOS arm64 전용이다
- **현상**: `config/chemical/`의 잠금 파일과 `setup_prolif_worker.py`가 CPython 3.11 macOS arm64만 허용한다.
- **영향**: Linux 서버에 설치한 인스턴스에서는 M11 화학 기능을 쓸 수 없다.
- **지금 해결하지 못하는 이유**: 다른 플랫폼 wheel 조합을 조사하고 해시 잠금·검증을 새로 해야 한다.
- **방향**: Linux x86_64용 잠금 파일과 설치 경로를 따로 만들고, 같은 네이티브 테스트로 검증한다.
