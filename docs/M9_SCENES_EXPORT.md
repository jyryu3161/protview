# Saved views and local figure export (M9)

M9 adds named, immutable views of the molecule currently shown in Mol*. This page describes the controls and limits. The [phase index](../phases/protview-scenes/index.json) records the current review, acceptance checks and status.

1. Display the desired original, prepared, historical or completed OpenMM-minimized structure. Choose the model, representation, residue selection, camera and light/dark theme in the viewer. Enter a **보기 이름** and choose **현재 보기 저장** once the structure and viewer session are ready.
2. Under **저장된 보기**, choose a saved name and **저장된 보기 복원**. Names may repeat; the handle suffix distinguishes them. Restore loads that view's exact saved source and model, even if the pipeline has since advanced. It creates a fresh local viewer session, restores the exact residue identity (including model and insertion code), representation, theme and native camera. Reopening a run only lists saved views; it does not change the molecule until you choose Restore. **현재 구조로 돌아가기** returns to the underlying structure selection.
3. With the same saved view currently displayed, choose **현재 보기 PNG 내보내기**. This captures the molecular viewport through Mol* and stores one PNG with one JSON provenance sidecar. Use the **저장된 그림** selector and separate **PNG 다운로드** / **JSON 출처 다운로드** links. Both links use the same immutable figure handle; downloading JSON does not render again. Saved figures can be downloaded after reopening the run or rebuilding its object index from events.

Save and Export stay disabled while the structure or matching viewer session is not ready, or during another scene operation. If the current molecule, selection, camera, representation or theme differs from the chosen saved view, restore it before Export. A failed scene read can be retried with **저장된 보기 다시 읽기** and Restore; a failed download can be clicked again. A timed-out or disconnected viewer is not reported as a successful save or capture.

Each run allows up to 100 distinct saved scenes and 100 distinct figures. PNGs are limited to 8 MiB, 64–2048 pixels on each axis, four million pixels total and 64 MiB of distinct saved PNG bytes per run. Identical saved content reuses its handle and PNG bytes. Limit errors are explicit; the app does not silently discard older artifacts. Scene names are labels, never filenames; downloaded filenames derive from immutable handles.

These images are **client-rendered local views**, not new scientific measurements or proof that the displayed conformation has a particular energy or affinity. The sidecar records the saved scene handle, source/model, image SHA-256, dimensions, renderer version and this provenance limit. The backend validates the local source and PNG structure, but independent visual evidence comes from the actual renderer QA. Saving, restoring and exporting do not call a model, start a scientific job, use a provider, change budgets or enable online mode. The default workflow remains `local_only`. Scientific reports keep their separate exact handles and bytes.

The [M9 contract](M9_SCENES_EXPORT_CONTRACT.md) defines validation and race behavior; the [offscreen QA plan](M9_OFFSCREEN_QA_PLAN.md) defines actual control checks. The phase index records the current review and verification status.
