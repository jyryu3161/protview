# M25 JEV loop offscreen QA fixture server and setup (test only)

Made locally for ProtView M25 (JEV design loop) on 2026-10-07 in task T10 (the offscreen flow
`frontend/tests/offscreen/jev-loop-flow.cjs`). Nothing in this folder is a scientific result, a provider or model
response, a measured binding value, an affinity, a stability or an API credential. Production code never imports
these files.

| File | What it is |
|---|---|
| `server.py` | LABELLED FIXTURE SERVER. The unchanged product app (`mw.api.app`) on 127.0.0.1 with its module-global `SCIENCE_GATE` replaced by an `EgressGate` over an in-process `httpx.MockTransport` and an inert sentinel placeholder credential (the M24 fixture server's way, `../offscreen_jev_fixture/server.py`); `VIEWER_GATE` and the `EgressGate` default arguments get a transport that refuses and a resolver that finds no credential and never reads `.env`. Every science "reply" is written by this file from the script named in the control folder: `good` (the first `criteria` key, i.e. the first not-yet-computed alias in the sent order), `computed_alias` (an alias of the wire's `computed` list, refused at the gate as `response_invalid`), `http_500`, `slow` (held until the harness releases it: a late reply after consent off), `no_usage`, `model_mismatch`. The confidence (0.62), per-alias probabilities (`((i * 5) % 7) + 1` weights, normalized, four decimals, sent order) and usage numbers are labelled fixture values, never a model decision or a measurement. The control folder records per request only the body SHA-256 and byte count, alias / criteria / computed aliases, a boolean for the sentinel authorization, the script, the status and the scripted reply (`calls.jsonl`), and the credential resolver call counts (`credentials.json`); never the body, a header value or a credential. No socket to any provider is opened. |
| `qa_setup.py` | QA SETUP over the loopback API (no `mw` import), against the fixture server only. Makes the two runs the flow drives with the M24 runner's inputs: run L = public 1UBQ loaded for the viewer, the public prepared docking example receptor `../fixtures/chemical/prolif-vina-rec.pdb` (not experimental validation), the public-derived parent `../fixtures/docking/public-derived-parent-record0.sdf` and the labelled synthetic small blocks `../fixtures/ligand_ga/synthetic-ga-small-blocks.smi` imported, real M17 inspection + enumeration (site 22, fixed rules: 10 candidates; the run's first expensive-call approval is given here for those two jobs); run P = public 1UBQ and public 1MQ4 loaded and prepared, real M20 sets (allowed residue A only) at the 22 (1UBQ) and 3 (1MQ4) non-Ala residues with the most neighbors in the M24 oracle file `../fixtures/jev/expected.json`, and the labelled synthetic phenol `../fixtures/mutation_model/synthetic-phenol-ligand.sdf` imported. Writes `m25_jev_loop_setup@1` (run ids, handles, counts) into the QA root. |

Inputs are read only from the folders above (see their own provenance files). QA roots, control folders and evidence go
to a new Git-excluded folder under `runs/` (never `/tmp`); they are not committed (the committed M25 QA evidence is
made by the acceptance runner in `docs/qa/m25-jev-loop-<YYYYMMDD>/`).
