# scripts/ — 단계 실행기, 개발 훅 테스트, 설치 스크립트

## 담당 범위
- `execute.py`: `phases/<group>/index.json` 단계 실행기. 수락 명령(argv 배열)을 셸 없이 실행하고, SHA-256으로 묶인 검토 증거를 기록하며, `--verify`로 다시 확인한다.
- `test_execute.py`, `test_codex_hooks.py`: 실행기와 `.codex/hooks/`(PreToolUse 위험 명령 차단, Stop 훅의 ruff·pytest) 테스트.
- `setup_fpocket.py`: M12 fpocket 작업 환경을 `config/pockets/`의 35개 conda 패키지 해시 잠금으로 오프라인 설치하는 명시적 설정 명령(conda 필수, macOS ≥ 14.5 arm64). 테스트 `test_setup_fpocket.py`.
- M13 QA 도구(런타임에서 호출되지 않음): `m13_offscreen_acceptance.py`(분석 흐름 수락 QA 전체 실행기. 흐름·엔진 없음·M8–M10 회귀를 자기 서비스로 돌리고, M11·M12 수락 실행기 전체를 하위 루트에서 실행해 그 대장을 합친다. `mw`를 import하지 않음), `test_m13_offscreen_acceptance.py`(하위 대장 판정·`acceptance` 판정·빌드 출처 확인 단위 테스트, 서비스 없음).
- M14 QA 도구(런타임에서 호출되지 않음): `m14_offscreen_acceptance.py`(탭 수락 QA 실행기. `frontend/tests/offscreen/tabs-flow.cjs`의 `main`·`chemical` 모드를 자기 서비스로 돌리고 사례 대장을 만든다. `mw`를 import하지 않음), `test_m14_offscreen_acceptance.py`(사례 판정·`acceptance` 판정 단위 테스트, 서비스 없음). M8–M13 회귀는 이 실행기가 아니라 M13 실행기 전체로 돌린다.

- `import_reaction_references.py`: M26 반응 참조 스냅샷 가져오기(사용자가 실행하는 설정 명령, ProtView에서 유일하게 네트워크를 쓰는 코드, 결정 0034). M-CSA API 쪽 순회·UniProt 일괄 요청과 빠진 accession 분류·Rhea 표 한 요청을 허용 호스트 셋(`www.ebi.ac.uk`·`rest.uniprot.org`·`www.rhea-db.org`)에 HTTPS GET으로 보내 가공 JSONL 셋과 요청 기록을 만들고, 형식 검사를 모두 통과할 때만 `MW_REACTION_REFERENCE_DIR`(기본 `.deps/reaction_reference`) 아래 새 세트 폴더로 원자적으로 설치한 뒤 `active.json`을 rename으로 바꾼다. 인자 `--accession`·`--accessions-file`·`--no-kinases`·`--reference-dir`·`--yes`. M15 kinase 목록은 로컬 M15 활성 세트(`MW_REFERENCE_DIR` 또는 `.deps/reference`)에서 읽기만 한다. 재현 비교 `compare_manifests`. `mw`를 import하지 않고 `backend/mw/reaction_knowledge_constants.py`만 파일 경로로 불러 같은 행 형식·정규 JSON·매니페스트 규칙을 쓴다. 테스트 `test_import_reaction_references.py`(전송 함수를 주입한 가짜 전송, `127.0.0.1` 로컬 서버에 대한 전송 계층 시험, CLI에 호스트·스킴 우회가 없음).
- `import_precedent_snapshots.py`: M27 키나아제 전례 참조 스냅샷 가져오기(사용자가 실행하는 설정 명령, 결정 0035). **네트워크를 쓰지 않는다**: 로컬 `kbase_kinase` 체크아웃(`--from`, 저장소 루트여야 함)의 커밋된 `dist/moves.jsonl`·`moves_flagged.jsonl`·`references.jsonl`과 `ref/manifest.json`의 최신 날짜 `pubmed` 서지 스냅샷을 바이트 그대로 복사한다. 쓰는 하위 프로세스는 읽기 전용 `git -C <kbase> -c core.fsmonitor=false -c protocol.allow=never`(`rev-parse HEAD`, `log -1 --format=%H%n%cI -- dist`, `status --porcelain --untracked-files=normal -- dist ref/pubmed`, 각 60초, 상속한 `GIT_*` 변수 제거·`GIT_CEILING_DIRECTORIES`)뿐이다. 검증 순서는 dist 매니페스트 크기·`KBASE_PINS` 세 값 → 세 파일의 바이트·SHA-256·줄 수 → 모든 레코드의 형식과 `content_hash`(`move_id` 두 파일 합쳐 유일) → pubmed 스냅샷 파일·행 → git 정보(HEAD 필수, `dirty`는 기록만)이며, 하나라도 실패하면 아무것도 쓰지 않는다. 모두 통과하면 `--dest`(기본 `MW_PRECEDENT_REFERENCE_DIR` 또는 `.deps/precedent_reference`, 상대 경로는 저장소 루트 기준) 아래 `sets/.staging-<uuid>`에 쓰고 `sets/<set_hash>`로 rename한 뒤 `active.json`(`precedent_active@1`)을 `os.replace`로 바꾼다. 인자 `--from`·`--dest`·`--yes`, 라이브러리 함수 `run_import(kbase_dir, dest, *, yes=False, now=None, input_fn=None)`. `mw`를 import하지 않고 `backend/mw/precedent_constants.py`만 파일 경로로 불러 서버와 같은 레코드 규칙·정규 JSON·세트 해시·매니페스트 검사를 쓴다. 테스트 `test_import_precedent_snapshots.py`(합성 kbase 흉내 폴더, 핀·파일 해시·줄 수·레코드 해시·형식 위반 거절과 `active.json`·기존 세트 불변, pubmed 일부 PMID 누락 정상, `dirty` 기록, 같은 입력 두 번째 설치의 파일 SHA-256 동일, 서버 고정이 이 명령이 만든 세트를 받음, 네트워크 모듈 import 없음과 소켓을 막은 자식 프로세스, CLI에 호스트·URL 옵션 없음).

- `IMPLEMENTER_MODEL = "gpt-6-sol"`, `REVIEWER_MODEL = "gpt-6-astra"`를 새 모델 이름으로 바꾸지 않는다. 바꾸면 기존 검토 기록(`review.model`)과 불일치해 모든 과거 단계의 `--verify`가 실패한다. 새 흐름이 이 실행기를 써야 하는 상황이 오면, 과거 기록 호환성을 유지하는 별도 설계가 필요하다.

- `setup_qvina.py`·`setup_docking_worker.py`는 잠금의 이름·크기·SHA-256, 플랫폼, 실행 파일 해시(qvina)·설치된 배포 집합(작업 환경)이 모두 맞을 때만 설치를 완료로 두고, 실패하면 이 실행이 만든 것을 지운다. 기존 `.deps/prolif`·`.deps/fpocket`을 건드리지 않는다. 이 확인을 느슨하게 하면 안 된다.
- `import_reference_snapshots.py`는 kbase 매니페스트와 SHA-256·바이트·행 수가 모두 맞을 때만 새 세트를 활성화하고, 실패하면 `--dest`를 바꾸지 않는다. 이전 세트 폴더를 지우는 코드를 넣지 않는다.
- 수락 실행기(M11·M12·M13·M14·M15·M16·M17·M18·M19·M20·M21·M22·M23·M24·M25·M26·M27)의 남은 프로세스 확인은 작업 폴더가 수락 루트 안인 프로세스만 센다(같은 컴퓨터의 다른 pytest를 잡지 않도록). M11 실행기도 M13에서 같은 방식으로 좁혔다.
- M13 실행기는 하위 실행기 대장을 schema별로 판정한다(`sub_ledger_verdict`: M11은 `summary`·`nonLoopbackRequestsTotal`, M12는 `verdict`·`externalRequestsTotal`). 외부 요청 수를 모르는 행이 있으면 실패다. `--only`는 `partial_not_acceptance`이며 증거를 내보내지 않는다. 서비스는 `PYTHONPATH=<code root>/backend`로 띄우고 `import mw` 경로를 먼저 확인한다.

- Stop 훅(`.codex/hooks/stop.py`)의 pytest 열여덟 그룹(`PYTEST_GROUPS` 열일곱 + 나머지 그룹, ruff까지 `CHECKS` 19개, 목록은 `docs/operations.md`)을 합치면 게이트의 전체 백엔드·실행기 테스트와 같아야 한다. 나머지 그룹은 `backend/tests`에서 `PYTEST_GROUPS`에 적힌 파일을 `--ignore`로 뺀 것(목록은 자동으로 만듦)과 실행기 테스트 `SCRIPT_TESTS`다. 새 실행기 테스트 파일은 `SCRIPT_TESTS`에 넣는다(M26은 `test_import_reaction_references.py`·`test_m26_offscreen_acceptance.py` 둘을, M27은 `test_import_precedent_snapshots.py`·`test_m27_offscreen_acceptance.py` 둘을 넣었다).
